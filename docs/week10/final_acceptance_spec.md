## 3. 첫날 고정할 공유 계약

김우영이 `docs/week10/contracts.md`에 실제 Kotlin/JSON 필드와 예시를 제시하고 김선한이 데이터와 대조한다. 나머지 팀원은 그동안 아래 독립 작업을 진행한다. 문서만 합의하고 앱 연결을 미루지 않는다.

- **저장**: runId, seed, schemaVersion, phase, 현재 사건/선택/결과 ID, 선택 이력의 시기·해·결과 문장·imageId, lifeFacts, completedLives, 칭호 ID, 아바타 설정. 과거 인생은 새 게임 시작 때 삭제하지 않는다.
- **칭호**: 기존 `titles.sample.json`의 titleId/text/description/priority/conditions/isDefault 보존. 우선순위 내림차순, 동률 titleId 오름차순, 기본값 정확히 1개. 현재 조건은 minStats/requiredFlags/blockedFlags다. 확장 시 파서·검증기·테스트를 같이 바꾼다.
- **상태 전이**: removeFlags 지원과 사실 갱신 순서, 결과별 명시 건강 변화 우선 규칙, 기본 피해 적용 예외. lifeDelta를 임의로 0으로 일괄 치환하지 않는다.
- **이미지**: period/bodyType/faceConfig/portraitRef, faceSheet 셀 및 anchor, backgroundId, layer 순서. 누락은 로컬 대체 이미지. 일반 장면은 3인칭, 주요 사건의 1인칭 장면에는 얼굴을 억지로 합성하지 않는다.
- **생성**: 서버 비밀키 없이 호출할 인터페이스·요청/응답 예제, Fake의 고정 결과, 취소·타임아웃·실패 경로. 이미지 30초/문장 3초를 상한으로 정하고 오프라인 진행을 막지 않는다.
- **최종 완료 상태**: 종료 연출이 완료 기록을 두 번 만들지 않고 재시도해도 같은 runId로 갱신되도록 한다.

## 4. 밸런스 인수 방법

1. 실제 콘텐츠, 고정된 시작 조건으로 건강/운동/지력/사회성/경제력/행복/운 각 경로를 분리한다. 무작위 선택, 목표 스탯 지향 선택, 고의 건강 저하 선택을 섞지 않고 별도 표로 낸다.
2. 총 10,000회 이상. 경로별 무작위·지향 선택을 각각 최소 500회 확보하고 나머지는 건강 저하·저스탯·잠금 경계·사망 재현에 배정한다. 영아·유년 사망 0, 전 선택 잠김 0, 무한 진행 0은 필수다.
3. 9주차 같은 무작위 정책·시드 350회는 비교군으로 유지한다. 각 경로 최소 3종 결말·경로 전용 결말 1종 이상을 유지하고 행복·운의 전용 결말 도달률은 각각 20% 이상을 10주차 목표로 삼는다. 숫자를 맞추려고 조건을 모두 없애거나 제목만 바꾸지 않는다.
4. 스탯 지향 정책은 각 경로에 중간 사건→사실→전용 결말의 성공 재현 시드 3개 이상과 실패/다른 경로 분기 1개 이상을 제출한다. 모든 결말이 모든 정책에서 균등하게 나오게 만들 필요는 없다.
5. 무작위 기준 중년 이전 사망률 8% 이하를 과거 v4의 초기 목표로 유지하되, 고의 건강 저하 정책과 분리한다. 돌발 빈도는 실제 플레이당 횟수·시기별 분포를 공개하고 과거 평균 약 1회 목표와 사용자 체감을 함께 검토한다. 수치 변경은 근거와 합의 문서를 남긴다.
6. 결말 65개 전부가 10,000회에서 나오지 않으면 미도달을 숨기지 않는다. 개별 조건 재현 테스트로 도달 가능성을 증명하고, 모순으로 불가능한 결말은 수정한다.

## 5. 서버가 필요한 기능과 제출 범위

실제 사진 기반 AI 이미지 생성과 서버 AI 문장 생성은 미완료다. Fake 응답을 실제 AI 생성 성공이라고 보고하지 않는다. 이번 주 모든 사용자 흐름은 로컬/Fake로 작동해야 한다. 실제 서버 배포는 운영 주체·공급자·예산·동의/삭제 정책을 확정한 경우에만 추가한다. 확정되지 않으면 보고서에 실서비스 생성 연동 미완료를 표시하고 시연은 기본/커스텀 캐릭터와 대체 미래 이미지로 완주한다.

C 직접 입력 AI 선택지는 원래 선택 확장 기능이며 이번 주 필수 완료를 가로막지 않는다. 공급자 키·서명 키·원본 사용자 사진·local.properties는 Git에 넣지 않는다.

## 6. 최종 판정

F10-01~14를 실제로 검증한 코드와 증거가 있어야 완료다. 필수 실패 0, 크래시/진행 불가/저장 유실/인생 사실 모순 0을 출고 기준으로 한다. 미확정 외부 서비스는 별도 제한으로 공개한다. 8·9주차 숙제를 다시 복사하거나 문서만 제출하고 완료 처리하지 않는다.
