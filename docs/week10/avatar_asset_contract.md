# 성장 캐릭터 소재 계약 — 독립 레이어 v4

2026-10-29 정원률. 앱은 `app/src/main/assets/images/avatar_v4/`를 사용한다. 승인한 중간 밀도의 픽셀 스타일에서 볼의 둥근 정도만 줄였다. 적당히 짧은 팔다리와 부드러운 턱선, 얼굴·머리·목·어깨의 자연스러운 연결을 우선했다.

## 독립 조합

실제 PNG를 **몸 → 피부/얼굴 → 눈 → 머리** 순서로 겹친다. 완성 머리 PNG만 교체하던 실험 방식은 최종 앱에서 제외했다.

|독립 항목|소재|변경 시 유지|
|---|---|---|
|몸|6시기×slim/standard/muscular=18|피부·머리·눈 ID 유지|
|피부|skin_default / skin_tan / skin_deep|몸·옷·신발·머리·눈 유지, 얼굴·목·양손·드러난 다리에 적용|
|머리|hair_default / hair_bob_brown / hair_long_black / hair_curly_brown|같은 얼굴·눈·몸 유지|
|눈|eyes_default / eyes_big / eyes_narrow|같은 얼굴형·코·입·피부·머리 유지|

프로필은 피부·머리·눈을 선택한다. 몸은 기존 `bodyTypeFor(stats)`가 결정하며 판정/저장 모델은 바꾸지 않았다. 기존 AvatarConfig ID와 초상 6개·스탯 7개 이미지 ID를 보존했다.

눈 PNG에는 눈썹이 포함되고, 코와 작은 입은 얼굴 바탕에 있다. 머리는 얼굴·눈·피부가 없는 별도 컷아웃이다. 긴 머리는 목 아래까지 보존한다. 노년에는 같은 머리 모양을 백발 팔레트로 치환한다.

## 크기와 anchor

모든 레이어는 **192×312 RGBA**, 원점은 왼쪽 위다. 얼굴 중심 x=96, 발 anchor=(96,304), 마지막 불투명 행은 303이며 아래 8px은 투명하다. 최종 alpha는 0/255이고 검정/흰 바탕을 굽지 않았다.

|period|머리 위 기준 y|얼굴 바탕 bbox (left,top,right,bottom)|목 anchor|눈 위 y / 폭|
|---|---:|---|---|---|
|infant|138|(67,155,125,207)|(96,207)|173 / 38|
|child|90|(66,108,126,162)|(96,161)|126 / 39|
|teen|30|(63,46,130,108)|(96,108)|69 / 44|
|young_adult|14|(57,29,136,108)|(96,108)|62 / 51|
|middle|20|(61,39,132,106)|(96,105)|64 / 46|
|old_age|30|(61,53,132,116)|(96,116)|75 / 46|

bbox의 right/bottom은 포함하지 않는 끝 좌표다. 일부 얼굴은 목에 1px 겹쳐 틈을 막는다. 머리별 실제 폭·위치·bbox는 `avatar_v4_geometry.json`에 고정했다.

몸은 서로 다른 생성 원본 18개에서 목 아래를 분리해 원본 목 중심과 발을 anchor에 맞춘다. 같은 몸을 복제하거나 가로로 늘여 수량을 채우지 않았다. 얼굴 바탕과 외형 파츠는 이미지 도구로 생성·분리 편집했다. 포장 스크립트는 자르기·최근접 배치·팔레트 치환만 한다.

48×78/4배의 굵은 격자로 다시 줄이지 않고 원본의 중간 밀도와 색을 유지한다. 같은 Fit·아래 가운데 정렬·FilterQuality.None으로 렌더링한다. 192×312 RGBA 한 겹은 239,616 bytes, 네 겹은 958,464 bytes이며 기존 로더의 8MiB 캐시를 사용한다.

## 파일명과 팔레트

`images/avatar_v4/` 아래:

- `body/body_<period>_<bodyType>.png`: 18
- `face/skin_<period>_<skinId>_<bodyType>.png`: 54
- `face/eyes_<period>_<eyesId>.png`: 18
- `face/hair_<period>_<hairId>.png`: 24
- `examples/face_sheet_example.png`: 1

피부 파일에 체형이 붙는 이유는 몸마다 노출 피부 위치가 다르기 때문이다. 얼굴 바탕 자체는 같은 시기에서 동일하다. 구릿빛은 원본 RGB×(.83,.73,.65), 짙은 피부는 RGB×(.56,.45,.38)이다. 몸에서는 노출 피부 마스크에만 적용해 옷·신발 색을 유지한다. 색 파생을 새 고유 그림으로 가산하지 않는다.

## 사진 생성용 6셀 시트

규격은 **1152×312 RGBA, 192×312 셀 6개, 1행**이다. infant→child→teen→young_adult→middle→old_age 순서이며 i번째 셀 x=i×192다. 각 셀은 위 좌표를 사용하고 몸·손 없이 피부·눈·머리가 합쳐진 완성 머리를 포함한다.

제공 파일은 기본 생성 외형을 합성한 예제이며 실제 사용자 사진 생성 결과가 아니다. 향후 사진 시트를 표시할 때 완성 머리 셀이 기본 얼굴/눈/머리 세 겹을 대체하도록 해야 한다. 현재 #43의 Fake 응답과 구분하며, 실제 사진 서버와 사진 얼굴 시트 픽셀 합성은 미연결이다.

## 검증

청년 세 체형의 네 레이어를 실제 앱에서 먼저 확인하고 여섯 시기로 확장했다. 648조합의 파일·alpha·발 위치·양쪽 눈 표시·양손 피부 변경과 18개 몸의 생성 원본 대응을 검사했다. UI에서 선택 하나를 바꾸면 다른 선택이 유지되고 성장/체형의 네 레이어가 함께 교체되는지도 검사했다.

로딩 중에는 이전의 완성 조합을 유지하고 새 네 겹이 준비되면 함께 표시한다. 실제 파일 누락 시 기존 코드 대체 경로를 유지한다. 대표 18개, 시기별 36외형 비교표와 앱 화면을 직접 확인했다. 모든 648개를 수동 미적 검수했다고 주장하지 않는다.
