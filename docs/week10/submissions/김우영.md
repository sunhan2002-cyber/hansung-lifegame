## 구현 내용

- `removeFlags`를 모델·JSON 파서·레거시 로더·엔진에 연결했다.
- 플래그 제거 후 추가를 적용하며 충돌 시 추가가 최종 상태가 되도록 했다.
- `minStats`와 `maxStats`를 사건·선택지·결말·칭호 조건에서 읽도록 통일했다.
- 명시적 사건 결과에 `BIG_INCIDENT` 기본 피해가 몰래 추가되지 않도록 수정했다.
- 건강 변화의 단일 계산식(`statDelta.health + lifeDelta + annual delta`)을 엔진에 구현했다.
- 47개 칭호 데이터를 읽고 우선순위/안정적 ID 순서/기본 칭호로 하나를 판정하도록 했다.
- 현재 인생 저장 포맷을 v3로 확장해 전체 선택 기록, 읽는 중인 결과, 아바타, 칭호를 저장한다.
- 완료 인생을 별도 영구 저장하고 `runId` 기준 중복을 막았다.
- v1/v2 저장 호환과 손상·미지원 버전의 안전한 실패 처리를 추가했다.
- 앱 재실행 후 결과 화면을 다시 추첨하지 않고 복원하며, 지난 인생 목록도 복원한다.
- 실제 선택 이력에서 이미지가 있는 장면만 시간순·중복 제거하는 주마등 선택 함수를 추가했다.
- 얼굴 시트·미래 모습·회고 생성용 `GenerationClient`와 성공/실패/시간 초과/취소 Fake를 구현했다.
- 운동능력 우선 체형 판정 순수 함수를 구현했다.

## 시연 순서

1. 앱에서 새 인생을 시작하고 사건 선택지를 고른다.
2. 결과 화면이 열린 상태에서 앱을 종료한 뒤 이어하기를 누른다.
3. 같은 결과 문구·능력치·인생 사실 변화가 중복 적용 없이 복원되는지 확인한다.
4. 인생을 끝내고 홈으로 돌아가 지난 인생에 결말과 칭호가 나타나는지 확인한다.
5. 앱을 재시작한 뒤 지난 인생이 유지되는지 확인한다.
6. 세 인생을 끝내 각 기록이 별도로 남고 같은 `runId`가 중복되지 않는지 확인한다.

## 미완료·협업 확인 사항

- 실제 원격 이미지/텍스트 생성 공급자 연결은 앱 키와 공급자 결정 후 `GenerationClient` 구현체로 교체해야 한다. 현재 Fake와 로컬 대체 계약까지 완료했다.
- 프론트엔드는 `CompletedLifeRecord`의 칭호·아바타·선택 기록을 최종 상세 화면에 연결해야 한다.
- 사진 원본은 저장소나 영구 저장에 넣지 않으며, 동의 철회 UI는 프론트엔드와 함께 최종 확인한다.
