## 0. 읽는 법

- 상태 표시
  - `[확정]` 팀 회의에서 정했고 김재겸이 세부를 정리했다. 팀장 최종 승인은 아직이다.
  - `[시작값]` 숫자나 공식의 출발점이다. 시뮬레이션과 플레이 테스트로 바꿀 수 있다.

  - **필수**: 반드시 지킨다.

## 3. 확정된 게임 규칙

### 3.1 진행 구조
- **R-01 [확정]** 진행 단위는 시기다. 시기는 영아 `INFANT`, 유년 `CHILD`, 청소년 `TEEN`, 청년 `YOUNG_ADULT`, 중년 `MIDDLE`이다.
  - 화면에는 "청소년기 · 4번째 해"처럼 보여 준다.
  - 정확한 나이는 **표시하지 않는다.**
- **R-02 [시작값]** 시기별 해 수는 목표 6·9·9·9·9(=42), 개발용 4·5·5·5·5(=24)다.
  - **필수:** 데이터(`periods.json`)로 바꿀 수 있어야 한다.
- **R-03 [미정]** 노년기 `ELDER`. 마지막 시기이고 길이는 사망 확률로 정해진다(최대 8해).
  - 구현은 설정 플래그 `elderEnabled`(기본 false)로 감싼다.
- **R-04 [확정]** 한 해에 결정 카드는 **최대 1장**이다.
  - 예약된 갈림길이 있는 해에는 돌발을 뽑지 않는다.

### 3.2 초점
- **R-10 [확정]** 시기가 시작되면 장 표지 화면에서 초점 하나를 고른다.
  - 영아기는 초점이 없다(부모님이 키우는 시기).
- **R-11 [확정]** 고른 초점은 **그 시기 동안 바꿀 수 없다.** 초점을 바꾸는 UI를 만들면 안 된다.
- **R-12 [확정]** 장 표지에 초점마다 오르는 능력치와 내려가는 능력치를 미리 보여 준다.
  - 모든 초점은 손해를 하나 이상 가진다.
- **R-13 [확정]** 초점 효과는 해마다 자동으로 적용된다. 예외로 효과가 멈추는 경우:
  - 군 복무 중
  - 그해에 "초점 효과 없음"이 붙은 선택을 한 경우 (예: 병원)
- **R-14 [시작값]** 효과 크기
  - `↑↑` = `max(1, round(4 × (1 − v/130)))`
  - `↑` = `max(1, round(2 × (1 − v/130)))`
  - `↓` = −1, `↓↓` = −2
  - `v`는 현재 능력치다. 줄어드는 공식은 증가에만 쓴다.
- **R-15 [시작값]** 한 시기 내내 같은 초점을 유지하면 시기가 끝날 때 플래그 `focus_{period}_{focusId}`를 준다.
  - 결말 조건을 살리는 데 쓴다 (예: 청소년기 학업 → `study_focus`도 함께 부여).

### 3.3 시간 흐름
- **R-20 [확정]** 결정할 일이 없는 해는 저절로 넘어간다.
  - 배속은 1× / 2× / 4×이고, 일시정지 버튼과 "다음 결정까지" 버튼(결정이 나오는 해까지 빨리 넘김)이 있다.
- **R-21 [시작값]** 한 해 길이: 1× = 3.0초, 2× = 1.5초, 4× = 0.75초. 지지직 전환 시간도 같이 줄어든다.
- **R-22 [확정, 필수]** 결정이나 돌발이 오면 자동 진행이 **멈춘다.**
  - 자동 결정 기능은 만들지 않는다.
- **R-23 [확정, 필수]** 전환 연출
  - 해 넘김 = 지지직 노이즈
  - **모든 돌발** = 왜곡 → 팝업
  - 시기 전환 = 장 표지
  - 왜곡은 배속과 상관없이 원래 길이(약 0.9초)를 유지한다.
  - 시스템 애니메이션이 꺼져 있으면 생략한다.
- **R-24 [확정]** 전환 종류는 엔진이 넘겨주는 `TransitionCue`(NOISE / DISTORT / CHAPTER)로 정한다.
  - 이 값을 저장해서, 이어하기를 했을 때 같은 연출이 반복되지 않게 한다.

### 3.4 사건 뽑기 (1단계 확률)
- **R-30 [확정]** 사건 종류(`kind`)
  - `MILESTONE`: 갈림길. 시기와 몇 번째 해로 예약된다.
  - `INCIDENT`: 일반 돌발
  - `BIG_INCIDENT`: 큰 돌발
- **R-31 [시작값]** 한 해 판정 순서
  1. 예약된 갈림길
  2. 큰 돌발: 42해 기준 3%, 24해 기준 6%, 한 판 최대 2번
  3. 일반 돌발: 40%. 3해 연속 아무 일도 없으면 다음 해는 반드시 뜸
- **R-32 [확정]** 돌발이 뜨면, 조건을 만족하는 사건 중 **가중치에 비례해서** 뽑는다.
  - 가중치 = `base × Π(조정 계수)` (형식은 §5.3 `weight`)
  - 예: "몸살" `base 10`, 건강 50 미만이면 1 낮을 때마다 +0.4, 유흥 초점이면 ×1.5
- **R-33 [확정]** `once: true`인 사건은 한 판에 한 번만 나온다. `cooldownYears`로 다시 나올 수 있는 간격을 정한다.

### 3.5 선택 결과 (2단계 확률)
- **R-40 [확정]** 선택지마다 **결과 목록**(`outcomes`)이 있고, 고르면 그중 하나가 확률로 정해진다.
  - 고정 결과는 결과가 하나인 경우로 처리한다.
- **R-41 [확정, 필수]** 능력치가 낮다고 선택지를 잠그면 안 된다. 능력치는 확률에만 영향을 준다.
  - 선택지를 숨길 수 있는 건 **플래그 조건뿐이다** (`visibleIf`, 이야기상 불가능한 경우. 예: 연인이 없을 때 "프러포즈").
- **R-42 [시작값]** 결과 확률 공식

  `chance = clamp(min, max, base + Σ coef_s × (stat_s − 50) + Σ perPoint_s × max(0, threshold_s − stat_s) + Σ flagBonus)`

  - 기본값은 `min = 15`, `max = 85`이고, 결과마다 따로 정할 수 있다 (예: 병원 회복 95).
  - `rest: true`인 결과는 나머지 확률을 가져간다.
  - 확률 합이 100을 넘으면 `rest`가 아닌 결과끼리 비율대로 줄인다.
- **R-43 [확정, 필수]** 화면에는 숫자 %를 보여 주지 **않는다.** 대표 결과(`primary: true`)의 확률만 말로 바꿔서 보여 준다.
  - 35 미만 "낮음", 35~59 "반반쯤", 60~79 "높음", 80 이상 "매우 높음"
  - 뒤에 핵심 능력치 이름을 붙인다. 예: "회복 가능성 반반쯤 · 건강"
- **R-44 [확정, 필수]** `hidden: true`인 결과(예: 사망)는 힌트, 미리보기, 디버그가 아닌 어떤 UI에도 드러내면 안 된다.
- **R-45 [확정, 필수]** 모든 무작위 판정은 `runSeed`와 해 번호에서 나온 결정적 시드로 굴린다.
  - 같은 저장 데이터에서 같은 선택을 하면 항상 같은 결과가 나와야 한다 (앱을 다시 켜서 재굴림하는 것을 막음).

### 3.6 죽음
- **R-50 [확정]** 해마다 건강 사망 판정 [시작값]

  | 시기 | 해마다 사망 확률 |
  |---|---|
  | 영아·유년 | **0 (필수)** |
  | 청소년·청년 | 건강 < 20일 때만 `(20 − 건강) × 0.3%` |
  | 중년 | 건강 < 35일 때 `(35 − 건강) × 0.3% + 0.5%` |
  | 노년(R-03) | `clamp(2, 50, 5 + 4n + 0.5 × (50 − 건강))%`, n은 노년 몇 번째 해 |

- **R-51 [확정]** 청소년기부터 돌발 결과에 `hidden` 사망을 넣을 수 있다. 영아·유년기 사건에는 **금지**다.
- **R-52 [확정, 필수]** 위험 신호를 보여 준다. 건강이 위험선에 들어가면:
  - 건강 막대가 빨간색이 된다.
  - 경고 기록 한 줄을 남긴다 (예: "요즘 계단이 무섭다").
  - "건강 경고" 돌발을 한 번 보장한다 (선택지: 병원 / 운동 시작 / 무시).
  - 위험선: 청소년·청년 20, 중년 35
- **R-53 [확정]** 사망하면 왜곡 전환 → 주마등 → 결말로 간다. 사인 문장은 결과 데이터의 `death.cause`를 쓴다.
- **R-54 [시작값]** 조기 사망률 목표: 중년기 전에 죽는 판이 **8% 이하** (§9 시뮬레이션 기준).

### 3.7 경제력, 직장, 자산
- **R-60 [확정]** 별도의 돈 숫자는 없다. `경제력`(0~100)은 **형편 수준**이다.
  - **무언가를 산다고 줄어들지 않는다.**
  - 병원비도 없다.
- **R-61 [확정]** 직장 단계: `NONE → STAFF(사원) → ASSISTANT_MANAGER(대리) → MANAGER(과장) → GENERAL_MANAGER(부장)`
  - 취업, 승진 심사, 해고, 구조조정은 확률 사건이다 (R-40).
- **R-62 [시작값]** 경제력 변화
  - 일회성: 취업 +10, 승진 +7, 해고·구조조정 −15
  - 해마다: 무직 −2, "일" 초점은 R-14의 ↑
- **R-63 [확정]** 자산은 **문턱을 넘으면 살 수 있다** [시작값]
  - 문턱: 차 50, 전세 60, 자가 75
  - 사면 플래그(`asset_car`, `asset_jeonse`, `asset_home`)가 남고 경제력은 줄지 않는다.
  - 자산 효과: 자가는 해마다 행복 +1, 결혼 사건 가중치 ×1.5
- **R-64 [확정]** 유년~청소년기의 경제력은 집안 형편이다 (시작 기질에서 정해짐).
  - 청년기 시작부터 내 경제력으로 바뀐다. 계산식은 [미정]이고, 기본은 그대로 이어받는다.
- **R-65 [확정]** 병원 같은 "시간이 드는 선택"은 비용 대신 `cost.skipFocusThisYear: true`로 표현한다.

### 3.8 성별과 군 복무
- **R-70 [확정]** 프로필을 만들 때 성별을 고른다. 선택지는 [미정]이고, 기본안은 남·여다.
  - 이벤트 조건에 `gender`를 추가한다.
- **R-71 [확정]** 남성은 청년기 1~3번째 해 중 하나에 갈림길 "입영 통지서"가 예약된다 (바로 입대 / 미룬다).
  - 미루면 1~2해 뒤 다시 예약된다.
  - 건강 < 35이면 확률로 사회복무가 된다.
- **R-72 [시작값]** 복무는 2해다. 그동안 초점이 멈추고 해마다 운동능력 +3, 사회성 +1, 지력 −1, 행복 −1이다.
  - 군대 돌발 5~6개는 유머 톤으로 쓴다. 전쟁·폭력 묘사는 **금지**다.
  - 전역하면 `military_done` 플래그와 칭호 후보가 생긴다.

### 3.9 결말
- **R-80 [확정]** 지금 결말 31개는 칭호 목록으로 바꾼다.
  - 조건을 만족하는 칭호 중 점수와 우선순위로 하나를 고르고, 기본 칭호를 보장한다.
  - 검증되지 않은 칭호는 `enabled: false`로 끈다.
- **R-81 [확정]** 결말 화면 순서: 주마등 → 예상 미래 모습 → 인생 기록 서류 + 칭호
- **R-82 [확정]** 인생 기록 서류에는 실제로 모델링한 것만 쓴다.
  - 쓸 수 있는 것: 시기별 초점, 결정·돌발 수, 기억에 남는 순간(최대 5개), 마지막 능력치, 직장 단계, 자산, 사인, 칭호
  - 연봉, 정확한 나이 같은 모델에 없는 수치는 **금지**다.

### 3.10 문장
- **R-90 [확정]** 해마다 기록 한 줄은 **템플릿**으로 만든다.
  - 고르는 기준: 시기 × 초점 × 최근 플래그
  - `{name}` / `{nameCall}` 치환을 적용한다.
  - 같은 판에서 같은 문장이 반복되지 않게 한다.
- **R-91 [확정, 선택 기능]** AI 문장은 시기 끝 회고(한 시기 한 문단)와 결말 요약에만 쓴다. 한 판에 최대 6번이다.
  - 3초 안에 응답이 없으면 템플릿으로 대신한다.
  - 입력으로는 그 판의 사실(초점별 해 수, 고른 선택지 제목, 능력치 변화, 플래그)만 넘긴다.
  - 프롬프트에 "주어진 사실 밖의 사람·직업·사건을 만들지 말 것, 2~3문장"을 넣는다.
  - 모델은 [미정]이다. 후보는 Claude Opus 5.5(`claude-opus-5-5`)와 비용을 줄이는 Claude Haiku 5.5(`claude-haiku-5-5`).
- **R-92 [확정, 필수]** API 키를 APK에 넣으면 **안 된다.** 외부 AI 호출은 반드시 중계 서버를 거친다.

### 3.11 사진, 도트 캐릭터, 미래 모습
- **R-100 [확정]** 장면 그림은 **전부 도트**다.
  - 평소 진행은 3인칭 도트(내 캐릭터가 나옴), 결정·돌발은 1인칭 도트(내 얼굴이 안 나옴)다.
  - 필름 프레임(C안 빈티지)은 유지한다.
- **R-101 [확정]** 프로필을 만들 때 아기 사진을 넣는 것은 **선택**이다.
  - 넣으면 동의 화면을 거친다.
  - 기기에서 얼굴만 잘라 256px로 줄인 다음 중계 서버로 보낸다.
  - 서버는 이미지 생성 서비스로 **시기별 얼굴 시트 6칸**(영아~노년)을 한 번 만들어 돌려준다.
  - 서버에 사진을 **저장하면 안 된다.**
  - 앱에 사진과 시트를 지우는 기능이 있어야 한다.
- **R-102 [확정]** 게임 중 실시간 생성은 **금지**다. 쓰는 방법:
  - 얼굴: 시트에서 그 시기에 해당하는 칸을 쓴다.
  - 몸: 부품으로 바꾼다. 체형 규칙 [시작값]은 운동능력 ≥ 70이면 근육, 건강 < 35 또는 운동능력 < 30이면 마름, 나머지는 보통이다.
- **R-103 [확정]** 결말에서 **예상 미래 모습**을 한 번 생성한다.
  - 입력: 얼굴 시트, 체형, 직장 단계, 자산 플래그, 행복 구간
  - 생성에 실패하면 노년 스프라이트(부품 조립)로 대신한다.
- **R-104 [확정]** 사진이 없거나 생성에 실패하면 부품 조립 얼굴을 쓴다. 피부톤, 머리, 눈을 사용자가 직접 고른다.
- **R-105 [미정]** 이미지 생성 서비스를 무엇으로 할지는 7주차 시험 결과로 정한다.
  - 시험: 후보 2~3개 × 아기 사진 3장으로 생성한 결과를 보고, 팀 5명이 "같은 사람처럼 보이는지" 다수결로 판정한다.

### 3.12 홈 화면
- **R-110 [확정]** 앱을 켜면 홈(프로필) 화면이 나온다. 들어가는 것:
  - 진행 중인 인생 카드: 전신 도트, 이름, "청년기 · 3번째 해", 능력치 미니 차트, 지금 초점, 최근 기록 2줄
  - **[이어하기] [새 인생 살기]** 버튼
  - 지난 인생 목록과 칭호 도감
- **R-111 [확정]** 저장 슬롯은 진행 중 1개와 완료 기록 목록이다.
  - 진행 중인 인생이 있을 때 새 인생을 시작하면 덮어쓰기 확인을 받는다.

## 4. 한 해 처리 순서 (엔진)

```
onPeriodStart(period):
  cue = CHAPTER
  if period.hasFocus: await chooseFocus(period) → state.focus = 선택 (시기 동안 고정)
  reserve milestones for this period (시기, 몇 번째 해)

onYear(state):                       # 자동 진행 타이머 또는 "다음 결정까지"가 부른다
  1. applyYearEffects:
       시기 효과(중년 건강 −2), 초점 효과(R-13 예외 확인), 직장/경제력 해마다 변화, 자산 효과
  2. healthDeathCheck(seed(run, turn, "hazard")) → 죽으면 endRun(cause, cue = DISTORT)
  3. decision = reservedMilestone(year)
              ?: rollBigIncident(seed) ?: rollIncident(seed, pity)   # R-31, R-32
  4. if decision != null:
       pause autoplay; cue = DISTORT (돌발) / NONE (갈림길)
       show decision (1인칭 도트) → player picks choice
       outcome = rollOutcome(seed(run, turn, eventId, choiceId))      # R-42, R-45
       apply outcome (statDelta, flags, job, assets, skipFocusThisYear 기록)
       if outcome.death: endRun(outcome.death.cause, cue = DISTORT)
  5. log += templateLine(period, focus, recent flags) 또는 outcome.resultText
  6. save()                          # 해마다 그리고 선택마다 저장
  7. if last year of period:
       periodRecap (템플릿, 선택적으로 AI) → onPeriodStart(next)
     else:
       cue = NOISE → 다음 해
endRun: 주마등(그 판의 장면을 다시 씀) → 예상 미래 모습 → 인생 기록 + 칭호
```

- **필수:** 엔진은 UI 없이 테스트할 수 있는 순수 Kotlin이어야 한다.
  - 시간(타이머)은 UI 계층에 둔다. 엔진은 `advanceYear()`를 한 번 부를 때 한 해를 처리한다.
- 권장 API 예시: `startRun(profile, seed)`, `chooseFocus(focusId)`, `advanceYear(): TurnStep`, `choose(choiceId): OutcomeStep`, `snapshot()/restore()`.
  - `TurnStep`에 들어가는 것: `cue`, `logLine`, `pendingDecision?`, `ended?`

## 7. 외부 서비스 (중계 서버)

- **R-120 [미정]** 서버 형태는 정해지지 않았다 (후보: Cloudflare Workers, Firebase Functions). 담당자, 비용 부담, 과제에서 외부 API를 써도 되는지도 미정이다.
- 엔드포인트 예시: `POST /face-sheet`(사진 → 시트), `POST /future-look`, `POST /recap`(선택)
- **필수:**
  - 기기별 요청 수 제한
  - 사진과 결과 미보관
  - 타임아웃: 이미지 30초, 텍스트 3초
  - 실패하면 앱이 대체 경로로 계속 진행
- 앱에는 `FakeGenerationClient`를 넣어서 서버 없이도 전체 흐름을 완주할 수 있게 한다 (**8주차 완주 조건**).

## 8. 도트 그림 규격

| 종류 | 규격 | 수량 목표 |
|---|---|---|
| 장면 원본 (1인칭, 3인칭) | 300×225 px (4:3), PNG, 40색 이하, 디더링 없음 | 3인칭: 시기 × 초점 20장 + 영아 3장. 1인칭: 8주차 핵심 40장, 나머지는 비슷한 사건끼리 같이 씀 |
| 3인칭 얼굴 위치 | 장면마다 `faceAnchor: {x, y, size}` (원본 px). 얼굴 시트의 칸을 이 위치에 덮어 그림 | 3인칭 장면마다 1개 |
| 얼굴 시트 | 32×32 px × 6칸(영아·유년·청소년·청년·중년·노년), 투명 배경 | 플레이어당 1장 (런타임 생성 또는 부품 조립) |
| 몸 부품 | 시기 6 × 체형 3, 얼굴 자리 기준점 포함 | 18장 |
| 파일 | `assets/images/scene/…`, `assets/images/pov/…`, `assets/images/body/…`. `image_ids.json`의 `fileName`과 맞춘다 | |

- **필수:** 앱에서 도트 이미지를 그릴 때 **nearest 필터**를 쓴다. Compose에서는 `FilterQuality.None`이다. 흐리게 보간하면 안 된다.
- 개발용 그림은 이미지 생성 도구로 만든 뒤 같은 후처리를 한다: 300×225로 축소(박스) → 40색 양자화(디더링 없음) → 저장.
  - 이 후처리를 해야 그림체가 맞는다. 시안의 8-3 도트가 이 방식으로 만든 것이다.

## 10. 하지 말 것

- main에 직접 푸시하지 않는다. 팀장 승인 없이 이 개편을 머지하지 않는다.
- 숫자 % 확률이나 숨은 결과를 화면에 보여 주지 않는다.
- 초점을 시기 중간에 바꾸는 기능, 자동 결정 기능을 만들지 않는다.
- API 키를 앱에 넣지 않는다. 동의 없이 사진을 보내지 않고, 서버에 사진을 저장하지 않는다.
- 영아·유년 사망, 실제 통계, 전쟁·학대 같은 무거운 소재를 넣지 않는다.
- 지지직(해 넘김)과 왜곡(모든 돌발) 규칙을 바꾸지 않는다.
- 결말 기록에 모델에 없는 사실(연봉, 정확한 나이, 등장하지 않은 사람)을 지어내지 않는다.
