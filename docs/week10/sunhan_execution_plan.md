## 선행 의존과 작업 원칙

- 아직 없는 `contracts.md`는 김우영의 계약 미제출로 기록한다. 현재 소스에서 확인되는 사실을 별도 QA 계약 검토로 남기며, 합의된 계약이라고 주장하지 않는다.
- 칭호 판정·완료 인생 저장·아바타 합성·Fake 생성·최신 UI는 각각 담당자의 구현이 필요하다. QA 도구로 독립적인 기대값을 계산하더라도 앱 기능이 구현됐다고 보고하지 않는다.
- 796→1,000 선택지 확장은 신기훈 작업이다. 이번 검사는 현재 전체를 감사하고, 콘텐츠가 늘어나면 같은 도구로 자동 재검사하도록 만든다.
- 10,000회에서 목표 미달/오류가 나오면 데이터를 공개한다. 엔진·시나리오 목표를 임의로 낮추거나 기존 테스트를 끄지 않는다.
- 이번 브랜치는 김선한 QA 산출물이다. 다른 담당자의 기능을 대신 전면 구현하거나 검증 실패 상태를 main에 자동 병합하지 않는다.
