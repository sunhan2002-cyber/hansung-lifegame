# 7주차 통합 완료 대면회의 안건·회의록

- 회의일: 2026-10-15
- 프로젝트: 인생게임 Android 앱
- 현재 단계: 7주차 결과물 통합 및 main 반영 완료
- 회의 목적: 통합본의 실제 플레이 흐름을 확인하고, 2주 뒤 개발 완료를 위한 범위·담당·검증 기준을 확정한다.
- 최종 개발 완료 목표일: 2026-10-29

## 1. 회의 전 확인할 현재 상태

- 7주차 결과물은 백엔드, 시나리오, DB·QA, 프론트엔드, UI/UX 결과를 통합한 상태다.
- 통합 검증 기준인 `python scripts/validate_content.py`, `./gradlew.bat test`, `./gradlew.bat assembleDebug`를 확인한다.
- 현재 앱의 목표 흐름은 다음과 같다.

  `홈/프로필 → 새 인생 시작 → 캐릭터 설정 → 장 표지·시기별 초점 → 자동 진행 → 결정/돌발 → 결과 → 저장·이어하기 → 주마등·결말`

- `디자인 미리보기`는 UI 확인용 기능이다. 최종 제출 화면에 남길지, 디버그 전용으로 둘지 오늘 결정한다.
- 7주차 검증 문서 기준으로 작은 화면·큰 글자 환경에서 UI 테스트 1건이 남아 있다. 일반 test/build 통과와 최종 사용자 화면 검수는 분리해서 판단한다.
- 실제 이미지 제작은 8~9주차 핵심 완료 범위에 포함한다. 다만 204개 사건마다 서로 다른 이미지를 만들 필요는 없고, 비슷한 사건은 같은 1인칭 도트 장면을 공유할 수 있다.
- v4 화면은 기존 사건 화면 하나를 계속 재사용하는 구조가 아니다. 3인칭 평소 진행 화면과 1인칭 사건·돌발 화면을 구분해 구현하고, 두 화면 사이를 자동 진행·결정 상태에 따라 전환해야 한다.
- 현재 코드의 `LifeGameApp.kt`는 `Routes.GAME`에서 `GameScreen` 하나를 호출하는 구간이 남아 있으므로, 이 요구는 아직 완료된 것으로 보면 안 된다. 회의에서 화면 분리 작업을 8주차 필수 작업으로 확정한다.

## 2. 오늘 회의 안건

### 안건 A. 7주차 통합본 시연

Android Studio의 `main` 최신 상태에서 다음 순서로 한 번 시연한다.

1. 앱을 새로 시작한다.
2. 이름·캐릭터를 설정한다.
3. 장 표지에서 시기별 초점을 선택한다.
4. 자동 진행을 시작하고 진행 단위가 바뀌는지 확인한다.
5. 일반 결정과 돌발 사건을 각각 한 번 선택한다.
6. 선택 결과가 능력치·플래그·다음 사건에 반영되는지 확인한다.
7. 결과와 결말 화면까지 이동 가능한지 확인한다.
8. 앱을 종료한 뒤 이어하기 대상 상태가 유지되는지 확인한다. 아직 미완성이면 8주차 필수 작업으로 기록한다.

시연 중 확인할 것:

- 화면이 흰색/검은색 빈 화면으로 멈추지 않는가
- `{name}`, `{nameCall}` 같은 치환되지 않은 문구가 보이지 않는가
- 숫자 확률이 사용자 화면에 노출되지 않고 가능성 문구로 표시되는가
- hidden outcome/death 정보가 선택 화면에 직접 노출되지 않는가
- 이미지가 없을 때도 placeholder로 게임 흐름이 끊기지 않는가
- 도트 이미지가 흐려지거나 화면 밖으로 잘리지 않는가

### 안건 B. 2주 뒤 “개발 완료”의 범위 확정

이번 회의에서 말하는 개발 완료는 모든 사건과 이미지를 영구히 확정한다는 뜻이 아니라, 핵심 게임을 처음부터 결말까지 반복 실행할 수 있고 구조 변경을 멈추는 상태로 정의한다.

2주 뒤 필수 완료 기준:

- 24턴 기준으로 홈부터 결말까지 한 판 완주
- 같은 seed와 같은 선택에서 같은 결과 재현
- 저장 후 앱 재시작 시 같은 시기·pending 결정으로 이어하기
- 일반 결정, 큰 돌발, 마일스톤, 결과, 결말의 데이터 흐름 연결
- 숨은 사망 결과가 UI에 노출되지 않음
- 영아·유년 시기 사망 0건
- v4 `periods/focuses/events/outcomes` 로더와 Compose 화면 연결
- 3인칭 평소 진행 화면과 1인칭 사건·돌발 화면을 각각 구현하고 실제 흐름에서 전환
- 핵심 시기·초점 평소 장면과 대표 돌발 장면의 도트 이미지 제작·연결
- 이미지가 없는 장기 꼬리 사건은 공통 이미지 또는 임시 placeholder를 사용할 수 있지만, 핵심 시연 경로에는 미완성 박스를 남기지 않음
- `validate_content.py`, 단위 테스트, debug 빌드, 에뮬레이터 한 판 완주 확인
- 고정 seed 데모 동선 1개와 시연용 APK 확정

2주 뒤까지 범위를 줄여도 되는 항목:

- 204개 사건 전체에 서로 다른 이미지를 1장씩 제작하는 작업. 유사 사건 간 이미지 공유로 대체한다.
- 1,000개 이상의 선택지 전체 확장. 핵심 시연 경로와 대표 분기부터 완성한다.
- 서버/API 연결
- 핵심 흐름과 무관한 부가 화면의 대규모 디자인 변경

위 항목은 이미지 제작 자체를 미룬다는 뜻이 아니다. 핵심 경로에 필요한 3인칭·1인칭 이미지 세트는 2주 안에 제작하고 연결한다.

### 안건 C. 8주차 작업 분배

| 담당 | 8주차 목표 | 완료 증거 |
|---|---|---|
| 김우영·백엔드 | 저장·복원, pending 결정 유지, v4 로더 연결, 확률·큰 돌발·hidden death 통합 | 관련 Kotlin 변경, 테스트, 재시작 후 동일 상태 캡처 |
| 김재겸·프론트엔드 | 홈→초점→자동 진행→결정→결과→결말 화면을 실제 상태와 연결하고 이어하기 UI 구현 | main 기준 실행 캡처, 임시/디버그 버튼 정리안 |
| 신기훈·시나리오 | 군대·직장·건강 경고·마일스톤 사건과 결과 분기 보강, 모든 문구 치환 확인 | JSON 변경, 사건·imageId 검토표, 대표 플레이 경로 |
| 정원률·UI/UX | 핵심 화면에 피그마 도트 스타일 적용, 이미지 비율·작은 화면·큰 글자 검수 | 실제 화면 캡처, UI 체크 결과, 최종 이미지 적용 목록 |
| 김선한·DB/QA·총괄 | 통합 데이터 검증, 다중 seed·저장 QA, 문서/Notion 상태 갱신, merge 판정 | 검증 보고서, 실행 로그, 통과 PR 목록 |

8주차 종료 시 통합 기준:

- 역할별 브랜치에서 작업한다.
- PR에 수정 파일, 실행 명령, 테스트 결과, 화면 캡처를 남긴다.
- 팀장 검증 전에는 main에 병합하지 않는다.
- 필수 기준을 충족한 PR만 통합하고, 실패 항목은 PR에 수정 요청으로 남긴다.

### 안건 E. 검증·병합 규칙

각 PR 제출 시 아래 정보를 반드시 포함한다.

```text
- PR 목적과 변경 파일
- 연결한 요구사항 또는 화면 흐름
- 실행한 명령과 결과
- 에뮬레이터/실기기 환경
- 통과한 시나리오와 남은 제한
```

팀장 검증 순서:

1. main 최신화와 PR 변경 파일 확인
2. `python scripts/validate_content.py`
3. `./gradlew.bat test`
4. `./gradlew.bat assembleDebug`
5. 가능하면 `./gradlew.bat connectedDebugAndroidTest`
6. 새 게임과 이어하기를 직접 실행
7. v4 금지사항과 문구 치환 확인
8. 통과 PR만 merge
9. merge 후 main에서 같은 검증 재실행

## 4. 회의 직후 공통 실행 명령

Android Studio에서 main을 최신화한 뒤 실행하고, 문제가 재현되면 아래 결과를 회의록에 붙인다.

```powershell
git checkout main
git pull origin main
python scripts/validate_content.py
./gradlew.bat test
./gradlew.bat assembleDebug
```

에뮬레이터가 연결된 경우에만 다음을 추가한다.

```powershell
./gradlew.bat connectedDebugAndroidTest
```
