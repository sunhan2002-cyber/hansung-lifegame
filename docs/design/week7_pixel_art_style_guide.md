## 2. 확정한 스타일 방향

**차분한 종이색 UI 안에 인생의 한 장면을 기록한 도트 필름 한 컷을 놓는다.**

- [필수 요구] 선명한 픽셀 경계, 제한된 색상 느낌, 디더링 없는 픽셀아트.
- [필수 요구] 빈티지 종이 배경과 어울리는 차분한 톤, 조용한 인생 기록 필름 분위기.
- [권장 기준] 빈티지 분위기는 채도·명암·재질 표현으로 만든다. 사진 노이즈나 색 점을 뿌려 디더링처럼 보이게 만들지 않는다.
- [권장 기준] 화면마다 새로운 필터·네온 강조색을 추가하기보다 전체 이미지 세트의 톤과 픽셀 표현을 맞춘다.
- [권장 기준] 밝고 어두운 면은 몇 단계의 단색 덩어리로 구분한다. 연속적인 색 변화와 흐린 경계를 사용하지 않는다.

## 3. 필수 이미지 규격

| 항목 | 확정 기준 |
| --- | --- |
| 최종 앱 자산 크기 | **300×225 px**. 현재 생성 원본은 1448×1086이며 축소 보류 |
| 화면 비율 | **4:3** |
| 표현 | 도트풍 픽셀아트 |
| 색상 | **40색 이하 느낌** |
| 디더링 | 없음 |
| 평소 자동 진행 | 3인칭. 인물이 장면 안에 보이도록 한다 |
| 결정·돌발 | 1인칭 POV. 상황을 경험하는 시점으로 표현한다 |
| 필름 적용 | 원본 전체가 보이며 의미 있는 부분이 잘리지 않아야 한다 |
| 이미지 안의 글자 | 없음. 표지판·책·문서·포장 등에 읽을 수 있는 글자와 숫자도 넣지 않는다 |

**금지:** 그라데이션, 이모지, 3D 렌더링, 워터마크, 텍스트 포함 이미지, 과한 네온.

`40색 이하 느낌`은 원문의 표현이다. 실제 고유 색상을 40개 이하로 제한하는 것은 일관성을 위한 **권장 제작 목표**로 삼는다.
색 개수만으로 도트 스타일이 통과한 것으로 판정하지 않는다. 원본 규격과 시각적 느낌을 함께 확인한다.
이미지 팔레트나 도트 블록 크기의 새 정량값을 추가하지 않는다. 예시 8장의 육안 검수는 2026-10-13 사용자 완료 보고를 반영했다. 실제 고유 색상 수가 40개 이하인지 계측한 것은 아니다.

## 4. 이미지와 UI의 경계

- [필수 요구] 생성·제작하는 장면에는 텍스트·워터마크를 넣지 않는다.
- [권장 기준] 장면 파일에는 필름 프레임·천공·능력치·버튼·시기 이름 같은 UI도 넣지 않는다. 프레임은 앱이 별도로 그린다.
- [권장 기준] 이미지 경계에 중요한 손·얼굴·물체를 걸치지 않는다. 기기별 반올림이나 작은 화면에서도 상황이 읽히게 한다.
- [권장 기준] 작은 장식보다 인물/손, 행동, 상황을 설명하는 핵심 물체의 형태와 대비를 우선한다.
- [권장 기준] 1인칭 시점은 손이나 시선 방향·주변 물체로 표현하고, 3인칭 인물 사진 같은 구도가 섞이지 않는지 확인한다.

UI에 표시하는 사건 제목·본문·연차·능력치 및 이미지 대체 안내 문구는 장면 파일 안의 텍스트가 아니다.

## 6. 확정 필름 기준과 현재 적용 범위

- [디자인 기준] 그림 영역은 4:3. 기기 폭에서 바깥 여백과 좌우 프레임을 뺀 폭으로 높이를 계산한다. 현재 이미지 검수 화면은 이 계산을 적용한다.
- 위·아래 검은 띠: 각각 14dp. 좌우 검은 테두리: 각각 10dp.
- 천공: 폭 8dp, 높이 6dp, 간격 16dp.
- 필름 장식은 그림 영역 바깥에 둔다. 프레임을 위해 장면 자체를 잘라내지 않는다.
- 픽셀 보간·디더링을 끄고 원본 전체를 맞춰 표시한다. 현재 `FilmStrip.kt`의 bitmap 표시에서 적용했다.
- 파일이 없거나 읽지 못하면 전달된 그림 영역 크기에 맞춘 대체 그림을 사용한다. 검수 화면은 4:3으로 전달하며, 대체 그림은 실제 도트 샘플이 아니다.
- 기존 게임의 필름 전환 왜곡·노이즈는 UI 애니메이션이다. 이미지 검수 화면은 정지 상태로 전환·왜곡·노이즈를 넣지 않는다. UI 연출을 정지 장면의 디더링 허용 근거로 사용하지 않는다.

FilmStrip 자체는 호출 화면이 전달한 높이를 사용하므로 모든 화면의 4:3을 자동으로 보장하지 않는다. 기존 GameScreen은 별도 높이 계산을 유지한다. 김재겸 PR은 가운데 잘라 채우기·화면 높이 제한을 사용하므로, 실제 v4 화면에도 전체 장면·4:3 기준을 적용하는 것은 후속 협의·검수 항목이다.

관련 코드: [ImageSamplePreviewScreen.kt](../../app/src/main/java/com/example/lifegame/ui/screens/ImageSamplePreviewScreen.kt), [Week7DesignTokens.kt](../../app/src/main/java/com/example/lifegame/ui/theme/Week7DesignTokens.kt), [FilmStrip.kt](../../app/src/main/java/com/example/lifegame/ui/components/FilmStrip.kt).

## 7. 권장 제작·파일 처리 기준

아래는 원문에 별도 형식이 정해지지 않은 부분의 권장 기준이다. 예시 PNG 8장은 제작·보관했으며, 300×225 축소와 팔레트 후처리는 수행하지 않았다.

1. 최종 장면은 손실 없는 **PNG**를 우선 사용한다. 전체 화면 장면은 불투명 배경을 권장한다.
2. 제작 도구의 출력 크기가 다르면, 최종 전달 전에 300×225 px로 맞춘다. 비율이 다른 결과를 강제로 늘리거나 중요한 부분을 잘라 맞추지 않는다.
3. 크기 조정은 픽셀 경계를 유지하는 최근접 방식으로 한다. 스무딩·블러·디더링을 적용하지 않는다.
4. 색을 정리할 때도 디더링을 끈다. 그라데이션·글자·워터마크가 남아 있으면 다시 정리한다.
5. imageId와 fileName은 사건별 요청서 및 저장소의 매핑을 기준으로 연결한다. 이 가이드에서 새 ID를 임의로 확정하지 않는다.

### 현재 300×225 처리를 보류한 이유

이번 대화의 생성 도구는 출력 크기를 직접 고정할 수 없어 1448×1086·4:3 원본을 반환했다. 별도 API로 생성하지 않고 이 원본으로 예시를 확인했으며, 사용자가 축소를 일단 생략하기로 하여 육안 검수와 인계 자료 준비를 먼저 마쳤다. 최종 300×225 기준은 유지하고, 재개 시 기존 4:3 원본을 별도로 축소한 후 가독성·규격을 검증한다. [대화에 근거한 보류 사유](week7_handoff.md)를 참고한다.


## 8. 검수 기준과 현재 상태

**파일 검수:** 실제 해상도 300×225, 4:3, 정상적으로 읽히는 파일, 요청서의 imageId/fileName과 매핑 일치.

**시각 검수:** 픽셀 경계 선명, 제한된 색상 느낌, 디더링·금지 요소 없음, 시점 일치, 차분한 필름 톤, 작은 화면에서 핵심 상황 식별 가능.

**최종 앱 적용 후 검수 기준:** 원본 전체 표시, 프레임 밖/아래에서 중요 요소 잘림 없음, 이미지 누락 시 비율 유지, 일반 화면과 큰 글씨에서 본문·선택지·진행 버튼 접근 가능.

2026-10-13 현재 상태:

| 구분 | 상태·근거 |
| --- | --- |
| 개별 예시 8장 육안 검수 | **완료** — 사용자가 임시 예시 보기에서 직접 확인 후 완료했다고 보고 |
| 현재 원본 파일 | PNG 8장, 각각 1448×1086, 4:3 확인 |
| 300×225 처리 | **보류** — 사용자 요청. 현재 원본을 최종 크기 통과 자산으로 표시하지 않음 |
| 고유 색상 수 40개 이하 계측 | 미수행. 원문의 40색 이하 느낌과 별도인 권장 제작 목표 |
| 최종 imageId/fileName·규격 검증 | 김선한 담당, 인계·최종 검증 대기 |
| 실제 게임 연결 후 표시 검증 | 프론트 연결 이후 수행. 이번 육안 검수는 임시 예시 화면에 한정 |

육안 검수 완료는 사용자 보고를 기록한 것이다. 별도 자동 스타일 검사나 300×225 최종 자산 승인을 의미하지 않는다.
