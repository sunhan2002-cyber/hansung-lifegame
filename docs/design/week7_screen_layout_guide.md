## 1. 읽는 기준과 현재 적용 상태

과제 근거는 [Week7 팀원별 과제](https://github.com/sunhan2002-cyber/hansung-lifegame/blob/de214be5a2e5e1e1d5f3a1e187e70909f7af065f/docs/week7/week7_assignments_v4.md)다. Figma 시안 8의 흐름과 빈티지 필름 분위기를 참고했다. 디자인 수치는 사용자가 실행하며 검토해 확정한 값이며 Figma 원본 측정값이 아니다.

이 문서에서 **과제 필수**는 원문 요구, **디자인 확정**은 사용자 확정 값, **PR 구현**은 김재겸 PR의 확인된 동작, **권장 검수**는 적용 후 확인할 기준을 뜻한다. 확정 디자인이 PR 화면 전체에 이미 적용됐다고 해석하지 않는다.

프론트 비교 기준은 [PR #28](https://github.com/sunhan2002-cyber/hansung-lifegame/pull/28)의 커밋 `9c4818db0947d4b10e502939a7e7ce7439890a07`이다. 이후 PR이 바뀌면 해당 변경을 다시 확인한다.

| 화면 | 이 브랜치의 산출물 | 실제 기능 구현 기준 |
| --- | --- | --- |
| 홈/프로필 | 아래 3절의 모양·정보·검수 기준 | 김재겸 PR의 HomeScreen·CharacterSelectScreen |
| 장 표지·초점 선택 | 아래 4절의 모양·정보·검수 기준. 독립 미리보기 제거 | 김재겸 PR의 ChapterFocusScreen |
| 자동 진행 | 아래 5절의 모양·정보·검수 기준. 독립 타이머·상태 제거 | 김재겸 PR의 AutoProgressScreen |
| 결정·돌발 | 아래 6절의 모양·정보·검수 기준. 독립 상태·판정·컴포넌트 제거 | 김재겸 PR의 DecisionScreen |

**현재 로컬 앱에는 김재겸 PR의 v4 흐름을 가져오지 않았다.** 기존 HEAD의 게임을 유지하고, debug의 `디자인 미리보기`에서 이미지 검수 화면만 제공한다. 아래의 PR 구현 설명은 별도 프론트 코드에 대한 인계 기준이다.

참조 장면·초점 내용은 신기훈의 시나리오 커밋 `f4800f0ec3af1f09b51ec2b263e1ef60dcf60ca2`에서 가져왔다. 당시 중점 데이터 사본과 독립 진행 미리보기는 제거했다. 실제 시기 길이와 판정 규칙은 엔진·시나리오 상태를 따른다.

## 2. 공통 디자인 기준

아래는 **디자인 확정** 값이다. 현재 코드 참조 여부는 [수치 관리 안내](week7_ui_tuning.md), 이미지 제작 기준은 [도트 스타일 가이드](week7_pixel_art_style_guide.md)를 확인한다.

| 항목 | 디자인 기준 |

| 바깥 여백 / 큰 영역 간격 | 12dp / 16dp |
| 카드 내부 / 카드 사이 / 모서리 | 14dp / 10dp / 8dp |
| 주요 버튼·선택 카드 | 최소 높이 56dp, 긴 문구는 높이 증가 |

긴 본문·선택지·결과를 고정 높이나 말줄임으로 자르지 않는다. 안전 영역과 줄바꿈·스크롤을 확보한다. 시기·연차·초점 표시 기능은 PR 구현을 기준으로 하며 문구는 `N번째 해`, `이번 시기 초점`, `N해 고정`을 따른다. 시기 진행 표시는 v4의 5개 시기 정의를 사용한다.

### 공통 능력치

PR의 `PeriodHeader`가 같은 `StatsButton`을 사용하며 자동 진행·결정 화면이 같은 `StatsSheet`·`StatGrid`를 사용한다. 정원률의 신규 공유 구현은 제거했다. [PR의 공통 UI](https://github.com/sunhan2002-cyber/hansung-lifegame/blob/9c4818db0947d4b10e502939a7e7ce7439890a07/app/src/main/java/com/example/lifegame/ui/components/PeriodChrome.kt).

- 버튼: 미니 막대 7개와 능력치 글자, 최소 48dp, 모서리 8dp, 글자 12sp.
- 패널: 종이색 하단 시트, 좌우 24dp·하단 32dp, 제목/그리드 간격 16dp.
- 순서: 건강, 운동능력, 지력, 사회성, 경제력, 행복, 운.
- 그리드: 폭 360dp 미만 또는 글자 배율 1.5 이상이면 1열, 그 외 2열. 행 간격 12dp·열 간격 16dp.
- 스탯바: 높이 6dp, 이름·값 아래 표시. 내부 스크롤로 전체 항목에 접근.

작은 화면·큰 글씨 접근성은 적용 후 검수한다. 별도 능력치 기능을 다시 구현하라는 지시가 아니다.

## 3. 홈/프로필

### 목적·정보·배치

**과제 필수:** 홈에 현재 인생 카드·이어하기·새 인생 살기, 프로필에 이름·캐릭터·성별 설정을 제공한다. 값의 유효성·저장 조회·새 인생 생성은 프론트·엔진 담당이다.

**PR 구현:** 홈은 제목 → 현재 인생 카드 또는 빈 상태 → 이어하기/새 인생 살기 → 지난 인생 목록 순서다. 진행 중 새 인생을 시작하면 덮어쓰기 확인이 나온다. 프로필은 이름·성별·타고난 기질을 고른 뒤 시작한다. 현재 이어하기는 앱을 켜 둔 동안의 상태이며, 앱 재시작 후 저장 복구까지 완료된 것으로 표시하지 않는다.

**권장 검수:** 카드에는 실제로 제공되는 이름·시기·연차·초점만 표시한다. 홈 대표 장면을 추가한다면 4:3 필름을 권장하지만 필수 홈 이미지로 지정하지 않는다. 프로필 캐릭터 자산은 장면 이미지 300×225 규격과 별도다.

### 글자·간격·버튼

디자인 기준은 앱 로고 32sp/40sp, 제목 24sp/32sp, 안내·입력 16sp/26sp, 카드 보조 정보 14sp/20sp다. 공통 여백·카드·주요 버튼 수치를 적용할지는 프론트와 맞춘다. 버튼은 관련 카드·입력 영역 뒤에 배치하고 긴 문구가 잘리지 않게 한다.

### 컴포넌트 인계

아래 명칭은 PR의 화면 또는 내부 구성이다. 신규 파일을 따로 생성하라는 뜻이 아니다.

| PR 구성 | 화면에 필요한 정보·모양 |
| --- | --- |
| HomeScreen / LifeCard / EmptyLifeCard | 현재 인생 정보 또는 빈 상태, 주요·보조 동작, 지난 인생 목록 |
| InkButton / LineButton | 이어하기·새 인생 살기, 활성/비활성·확인 상태 |
| CharacterSelectScreen / SelectCard | 이름·성별·기질, 선택 표시·설명·오류 안내·시작 동작 |

**권장 검수:** 320×400dp·글자 배율 2.0에서 카드와 마지막 버튼 접근. 키보드가 열려도 입력·오류·시작 버튼 접근. 선택 상태는 색 외의 표시로도 구분한다.

## 4. 장 표지·초점 선택

### 목적·정보·배치

새 시기의 길이와 초점 효과를 이해하고 하나를 선택한다. **PR 구현:** 장 번호 → 시기 이름 → 기간·소개 → 이전/현재 성장 모습 자리 → 초점 안내·선택 카드 순서로 본문을 표시하며 시작 버튼은 하단에 둔다. 선택 전에는 시작이 비활성화된다. 선택 후 `학업으로 5해 시작하기`처럼 초점·시기 길이를 표시한다. 초점 고정은 실제 진행 상태에서 처리한다.

### 이미지·글자·간격

성장 영역은 PR에서 도트 실루엣 자리 표시를 사용한다. 실제 성장 자산은 프론트·생성 기능이 공급한다. 이 자산을 장면 이미지 300×225로 단정하지 않는다.

디자인 기준은 제목 24sp/32sp, 기간·소개 16sp/26sp, 카드 이름 16sp/22sp·굵게, 효과·설명 14sp/20sp다. 영역 간격 16dp, 카드 내부 14dp·항목 간격 10dp·모서리 8dp. 이 값은 PR의 현행 수치와 차이가 있으며 후속 디자인 적용 기준이다.

### 컴포넌트·작은 화면

| PR 구성 | 입력·역할 |
| --- | --- |
| ChapterFocusScreen | 실제 화면 상태·선택 완료 콜백, 시기 소개·카드·시작 버튼 조합 |
| GrowthStage / FigureWithLabel | 이전·현재 시기 모습 자리와 설명 |
| SelectCard / EffectText | 초점 이름·효과·설명·선택 표시 |
| InkButton | 선택한 초점으로 시작, 선택 전 비활성 |

5개 카드와 설명을 한 화면에 고정하지 않는다. 설명을 말줄임하지 않고 본문을 스크롤한다. 하단 버튼을 고정해도 본문 마지막 설명을 가리지 않아야 한다. 320×400dp·글자 배율 2.0에서 마지막 선택지·설명·시작 버튼 접근을 확인한다.

## 5. 자동 진행

### 목적·정보·배치

선택한 초점을 유지하며 해가 지나가는 상황과 재생·정지를 보여 준다. **PR 구현:**

1. 시기 이름 + 작은 회색 `N번째 해` + 능력치 버튼, 시기 진행 표시.
2. 그 아래 `이번 시기 초점`·선택 이름·`N해 고정`·능력치 효과.
3. 3인칭 필름 장면, 다음 해까지 진행 표시 또는 멈춤 안내.
4. 최근 기록 3개. 지난 기록은 흐리게, 현재는 강조.
5. 하단의 재생/일시정지·1×/2×/4×·`다음 결정까지 ›`.

연차 옆에 전체 해 수를 반복하지 않는다. 결정이 오면 실제 결정 화면으로 이동한다. 이전 독립 미리보기의 `시작 전`, `결정 화면 보기`, 3번째 해 결정 대기·복귀·5해 완료 안내는 현재 로컬 기능이나 PR 공통 기준으로 사용하지 않는다. 타이머·해 수·사건 배치는 프론트·엔진 담당이다.

### 이미지·글자·간격

디자인 기준은 3인칭 장면 전체를 4:3으로 표시하는 것이다. PR은 화면 높이에 따라 필름 높이를 제한하고 가운데를 잘라 채우므로, 해당 기준의 적용은 협의가 필요하다.

제목 24sp/32sp, 연차 13sp/18sp, 초점 이름 포함 안내 16sp/22sp, 고정 기간·효과·보조 안내 14sp/20sp, 기록 본문 16sp/26sp를 디자인 기준으로 유지한다. 바깥 여백 12dp·영역 간격 16dp, 초점과 고정 기간 사이 8dp를 기준으로 한다. 실제 PR 크기·간격에 이미 반영됐다고 주장하지 않는다.

### 컴포넌트·작은 화면

| PR 구성 | 입력·역할 |
| --- | --- |
| PeriodHeader / PeriodProgress | 시기·연차·진행도·능력치 열기 |
| FocusLockRow / EffectText | 선택 초점·고정 기간·효과 |
| FilmStrip | 실제 sceneImageId에 연결된 3인칭 장면 또는 대체 그림 |
| YearTimer / YearLog | 재생 상태·최근 기록 |
| PlaybackBar / SpeedToggle | 정지·재생·배속·다음 결정까지 |
| StatsSheet / StatGrid | 공통 능력치 상세 |

PR은 헤더·하단 조작을 두고 가운데 내용을 스크롤한다. **권장 검수:** 좁은 폭·큰 글씨에서 초점·고정 기간·배속·다음 결정 버튼이 겹치거나 잘리지 않아야 한다. 필요하면 줄바꿈·전체 스크롤 등을 프론트에서 조정한다. 정원률 브랜치에는 독립 자동 진행 구현을 추가하지 않는다.

## 6. 결정·돌발

### 목적·정보·배치

공개 사건과 행동을 읽고, 선택 후 실제 결과를 확인한다. **PR 구현:** 시기·연차·능력치·진행도 → 초점 고정 안내 → 1인칭 필름 → 사건 종류·제목·본문 → 선택지 또는 결과 → 진행 버튼 순서다.

모든 돌발은 왜곡 전환 후 팝업이 나오며 `사건 보기`로 본문·선택지에 진입한다. 갈림길은 팝업 없이 진입한다. 선택지에는 가능성 문구·핵심 능력치를 표시하고 숫자 확률·숨은 결과를 보여 주지 않는다. 능력치 때문에 선택지를 잠그지 않는다.

결과 뒤 버튼은 PR 문구인 **`계속하기`**, 인생 종료 결과는 **`인생 정리하기`**를 따른다. 과거 독립 구현의 `계속 진행`을 현재 PR 버튼명으로 안내하지 않는다.

### 이미지·글자·간격

디자인 기준은 1인칭 장면 전체 4:3, 제목 24sp/32sp, 본문·선택·결과 16sp/26sp, 보조 안내 13sp/20sp다. 사건 내부 간격 12dp, 선택 영역 위아래 12dp, 카드 사이 10dp, A/B 표식·문장 사이 12dp, 결과 내부 16dp·항목 사이 10dp, 모서리 8dp를 기준으로 한다. 돌발 팝업은 바깥 여백 24dp·내부 20dp다. 실제 PR의 수치와 차이가 있으며 프론트 적용 대상이다.

### 컴포넌트·작은 화면

| PR 구성 | 입력·역할 |
| --- | --- |
| DecisionScreen / PeriodHeader / FocusLockRow | 실제 결정 상태·시기·연차·초점·능력치 조합 |
| FilmStrip | 실제 POV 파일 또는 대체 그림 |
| DecisionText | 공개 사건 종류·제목·본문 |
| DecisionSheet / DecisionChoiceCard | 선택지 문장·가능성 안내·선택 동작 |
| OutcomeBlock / EffectText | 실제 결과 하나·선택한 행동·능력치 변화 |
| InkButton | 계속하기 또는 인생 정리하기 |
| IncidentPopup | 돌발 제목·짧은 안내·사건 보기 |

긴 문구를 고정 높이·말줄임으로 자르지 않는다. 결과와 진행 버튼까지 스크롤로 접근할 수 있어야 한다. **권장 검수:** 선택 후 결과 첫 줄을 쉽게 찾을 수 있도록 하고, 320×400dp·글자 배율 2.0에서 상단이 본문 공간을 과도하게 차지하면 함께 스크롤하는 방식을 검토한다. 팝업은 내부 스크롤로 사건 보기까지 접근한다. 이는 디자인 검수 기준이며 현재 PR이 모든 환경 검사를 통과했다는 주장이 아니다.

## 7. 현재 검수·후속 업무

현재 로컬 실행 경로는 **첫 화면 → 디자인 미리보기 → 예시 이미지 검수**다. `ImageSamplePreviewScreen`이 4:3 크기를 계산하고 `FilmStrip`에 전달한다. 그림은 정지 상태이며 이미지 선택·전환·초기화·복귀만 제공한다. 실제 게임 상태·판정·저장과 분리한다.

개별 8장의 육안 검수는 2026-10-13 사용자 완료 보고를 유지한다. 직접 진입으로 변경한 조작과 큰 글씨 표시는 사용자 후속 확인 대상이다. 기존 장 표지·자동 진행·결정 미리보기의 화면 테스트 결과는 제거 전 버전의 이력이며 현재 기능 통과 근거로 사용하지 않는다.

정리 후 앱·검수 APK 빌드와 Release Kotlin 컴파일, 단위 테스트 Debug 51개 + Release 51개가 통과했다. 이번 MD 설명 수정에서는 앱 코드·이미지·프롬프트를 바꾸지 않고 문서 링크·수치·참조 설명을 확인한다. [검증 기록](week7_handoff.md).

후속 업무: 정원률은 실제 화면의 모양을 검수하고 수정 기준을 제공한다. 김재겸은 실제 화면에 디자인 차이를 적용하고 연결한다. 김우영은 규칙·상태·판정·저장을 공급한다. 신기훈은 이미지 요청서, 김선한은 imageId/fileName·최종 규격을 검증한다. 300×225 처리·최종 게임 자산 검증은 보류 상태로 유지한다.
