## 2. 정원률 브랜치에 유지하는 것

- 필수 가이드 3개, 확정 디자인 수치·색상·글자 스타일, 네 화면의 모양과 작은 화면 검수 기준.
- `Week7DesignTokens.kt`, `Color.kt`, `Type.kt`의 디자인 정의와 기존 시각 컴포넌트의 여백·모서리·이미지 영역 변경.
- `FilmStrip.kt`의 전체 이미지 표시, 보간·디더링 해제, 확정 필름 틀 수치.
- 독립 TXT 8개, PNG 원본 8장, 생성·검수 기록과 debug 검수용 이미지 사본.
- `ImageSamplePreviewScreen.kt`, `Week7ImageSamples.kt`, 이미지 검수만 담당하는 `DesignPreviewScreen.kt`.
- debug 미리보기 진입 버튼·경로, 이를 위한 `buildConfig = true`, 이미지 검수 테스트 2개.

실행: 첫 화면 **디자인 미리보기**를 누르면 이미지 8장 검수 화면으로 바로 들어간다. **이전 이미지 / 다음 이미지 / 장면 고르기 / 다시 보기 / 돌아가기**를 사용한다. 예전 `화면 고르기` 및 장 표지→자동 진행→결정 미리보기는 제거했다.

확정 수치는 디자인 인계 기준이다. 실제 v4 화면 전체에 적용됐다는 뜻은 아니다. 비교 커밋 `9c4818d`에는 Tokens와 디자인 산출물이 없으며 프론트가 해당 화면에 필요한 값을 적용한다. 그 커밋 이후 PR 변경은 별도 확인한다.

김재겸 PR 문구는 `N번째 해`, `이번 시기 초점`, `N해 고정`, 결과 뒤 `계속하기`/`인생 정리하기`를 기준으로 안내한다. 제거한 기능은 현재 로컬에서 실행되는 것으로 설명하지 않는다.

## 3. 협업 범위

| 담당 | 후속 역할 |
| --- | --- |
| 정원률 | 화면 모양·색상·간격·글자·필름·장면 스타일 기준 제공, 실제 화면의 육안 검수와 수정 요청 |
| 김재겸 | PR의 실제 화면·이동·상태 표시·능력치 창을 구현하고 디자인 기준 적용. 통합 시 debug 이미지 검수 진입 경로 유지 여부 결정 |
| 김우영 | 시기·연차·중점 효과·사건 판정·확률·저장 등 실제 게임 규칙과 데이터 공급 |
| 신기훈 | 장면·시점·사건별 이미지 요청서와 시나리오 내용 |
| 김선한 | imageId/fileName·최종 이미지 규격과 콘텐츠·QA 검증 |

김재겸에게 전달할 디자인 차이는 **색상, 여백, 글자 크기·행간, 카드·필름 수치, 이미지 전체 표시, 작은 화면·큰 글씨 기준**이다. 동일 기능을 별도로 다시 구현하지 않는다. 이 문서는 인계 준비이며 실제 팀원 메시지 발송은 아니다.

## 4. 검증과 보류

- 이미지·프롬프트 파일은 이번 정리에서 변경하지 않는다. 8장 육안 검수 완료 보고는 유지한다.
- 원본 1448×1086 PNG·4:3, 300×225 처리 보류와 최종 규격 검증 대기는 유지한다.
- 코드 정리 후 앱 빌드·Release Kotlin 컴파일·검수 테스트 APK 빌드 통과. 기존 단위 테스트 Debug 51개 + Release 51개 통과. 세부 결과는 인계 문서에 기록했다.
- 에뮬레이터는 실행하지 않는다. 변경된 직접 진입·전환·복귀와 큰 글씨 화면은 사용자가 직접 확인한다.
- 기존 장 표지·자동 진행·결정 화면 검사 기록은 과거 버전의 이력이다. 제거한 구현의 검사 결과를 현재 코드의 통과 근거로 사용하지 않는다.
- 브랜치·HEAD·스테이징 상태는 유지한다. commit·push·PR·merge는 하지 않는다.

2026-10-13 설명 확인: 남은 Kotlin 변경은 .kt 15개(기존 수정 9개·신규 6개)와 .kts 1개다. 앱 진입·시작 화면·캐릭터 화면 변경은 검수 진입과 시각 스타일을 위한 부분이며, 실제 기능 구현은 프론트 기준으로 넘겼다. 이 기록은 MD 설명 수정 시점 기준이다.
