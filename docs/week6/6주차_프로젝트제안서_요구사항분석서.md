## 2. 프로젝트 제안서

### 2.1 제안 배경

사용자가 짧은 시간 안에 선택의 결과를 확인하면서도 반복 플레이할 동기가 있는 모바일 게임을 개발한다. 기존 선택형 텍스트 게임은 선택 이후의 결과가 단순하거나, 사용자가 왜 그 결과가 나왔는지 이해하기 어려운 경우가 많다. 우리 프로젝트는 인생을 여러 시기로 나누고, 시기별 초점과 누적 능력치, 돌발 사건, 결말을 연결하여 사용자가 자신의 선택이 어떤 흐름을 만들었는지 볼 수 있게 한다.

### 2.2 프로젝트 목적

텍스트 기반 인생게임은 사용자가 하나의 캐릭터를 생성하고, 영아기부터 중년기까지 시기별 선택을 누적하며, 그 결과로 변화하는 능력치와 사건, 결말을 확인하는 Android 앱이다. 현재 앱은 시작 화면, 캐릭터 설정, 사건 선택, 능력치 변화, 결말 화면까지의 기본 흐름이 구현되어 있다. 이후 v4 개편에서는 시기 시작 시 초점을 고르고 자동 진행 중 결정·돌발 사건이 발생하면 사용자가 선택하는 구조로 확장한다.

### 2.3 핵심 사용자 경험

- 사용자는 새 인생을 시작하고 캐릭터와 이름을 설정한다.
- 현재 구현 앱은 사건 텍스트, 이미지 ID, 선택지, 능력치를 보여 주고 선택 결과를 반영한다.
- v4 개편에서는 시기별 초점을 선택하고, 자동 진행 중 결정·돌발 사건에서 멈추는 흐름으로 바꾼다.
- 선택지는 능력치로 단순 잠금하지 않고, 결과 확률과 결과 가능성에 영향을 주는 방식으로 설계한다.
- 위험하거나 극적인 돌발 사건은 숨은 사망 결과를 가질 수 있지만, 결과 가능성 미리보기에는 사망 결과를 직접 노출하지 않는다.
- 모든 주요 장면 이미지는 도트풍으로 통일한다. 슬롯형 결과 연출이나 게임 중 실시간 이미지 생성 방식은 사용하지 않는다.

## 3. 요구사항 분석 기준과 ID 규칙 근거

강의자료 `06_요구사항 분석.pptx`에서는 요구사항 분류에 따라 ID 부여규칙과 요구사항 수를 작성하고, 요구사항 내용 작성표에 분류와 일련번호를 조합해 표현한다고 설명한다. 따라서 본 문서의 `FR-xx`, `DR-xx`, `UI-xx`, `TR-xx`, `NFR-xx`는 실제 코드 파일명이 아니라 요구사항 분석서에서 요구사항을 추적하기 위한 식별자이다.

다만 요구사항 ID가 곧 현재 구현 완료를 뜻하지는 않는다. 본 문서는 각 요구사항에 현재 근거를 함께 적는다.

| 상태 | 의미 |
|---|---|
| 구현됨 | 현재 Android 코드 또는 JSON에서 확인 가능한 기능 |
| 일부 구현 | 기본 구조는 있으나 v4 목표까지는 추가 작업 필요 |
| 설계 확정 | v4 개편안/팀 공유 문서에 명시되어 있으나 아직 앱에는 완전 반영 전 |
| 계획 | 후순위 또는 확장 기능으로 문서화만 된 항목 |

## 5. 요구사항 내용 작성표 — 기능 요구사항

| FR-07 | 다음 사건 진행 | 구현됨 | GameSession.proceed, GameEngine.advanceAfterResult | 선택 결과 이후 다음 사건으로 이동하거나 결말로 이동한다. | 다음 사건 버튼 클릭 시 새 사건 또는 결말이 표시된다. |

| FR-12 | 자동 진행 | 설계 확정 | 개편안_v4 상세 명세 | 초점 선택 후 해 단위 자동 진행 중 결정/돌발에서 멈춘다. | v4 구현 후 자동 진행과 일시정지가 동작한다. |
| FR-13 | 결과 확률 | 설계 확정 | 개편안_v4 상세 명세 | 선택지는 여러 outcome을 가지고 능력치와 플래그가 결과 확률에 영향을 준다. | v4 데이터와 엔진에서 outcome 판정 테스트가 통과한다. |

| NFR-06 | 사용성 | 구현 목표 | 능력치 변화와 결과 가능성은 사용자가 이해할 수 있는 문장으로 표시한다. | 숫자만 나열하지 않고 설명 문구를 제공한다. |
| NFR-07 | 접근성 | 구현 목표 | 작은 화면에서 버튼과 본문이 잘리지 않게 한다. | Pixel 6a 기준 주요 화면을 확인한다. |
| NFR-08 | 협업 품질 | 구현됨 | main 직접 push를 지양하고 PR 검증 후 병합한다. | PR별 검증 결과가 GitHub/Notion에 남는다. |

## 7. 데이터 흐름도(DFD)

DFD는 현재 코드 구조와 v4 목표 구조를 함께 설명하는 요구사항 분석용 개념 모델이다. 실제 클래스 다이어그램이 아니라 데이터가 어디에서 들어오고, 어떤 처리 과정을 거쳐 저장·출력되는지 보여 주는 도식이다.

### 7.1 Context DFD

외부 엔티티는 사용자와 팀장/콘텐츠 관리자로 본다. 사용자는 이름, 캐릭터, 선택을 입력하고 앱은 사건, 결과, 결말을 출력한다. 팀장/콘텐츠 관리자는 검증된 사건·이미지·결말 데이터를 반영한다.

### 7.2 Level 1 DFD

1. 시작/캐릭터 설정: 사용자 입력을 받아 새 인생 상태를 만든다.
2. 콘텐츠 로딩: 사건, 이미지 ID, 결말 데이터를 불러온다.
3. 게임 진행/사건 판정: 현재 상태에 맞는 사건을 고른다.
4. 선택 결과 계산: 선택 결과를 능력치, 플래그, 기록에 반영한다.
5. 저장/결말 관리: 진행 상태를 저장하고 결말을 계산한다.

## 8. 작성 기준 확인

- ID 규칙은 실제 코드 ID가 아니라 강의자료의 요구사항 식별번호 작성 방식에 따른 문서용 ID이다.
- 현재 코드에 없는 v4 기능은 `설계 확정`으로 표시했다.
- 현재 일부만 구현된 기능은 `일부 구현`으로 표시했다.
- 슬롯형 결과 연출은 사용하지 않는 범위로 명시했다.
- DFD는 실제 구현 클래스 구조가 아니라 요구사항 분석 단계의 데이터 흐름 개념도이다.
