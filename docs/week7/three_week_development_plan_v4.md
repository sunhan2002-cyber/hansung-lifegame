# 인생게임 v4 개편 — 3주 개발 완료 계획

- 기준 문서: `개편안_v4_AI용_명세.md`, `개편안_v4_팀장확인용.md`
- 목표: 남은 약 6주 중 앞 3주 안에 개발 핵심 완성
- 개발 완료 목표 주차: 7주차~9주차
- 10주차 이후: 안정화, 발표, 이미지 보강, 실기기 검수

## 1. 개발 완료 기준

3주 안에 끝났다고 볼 수 있는 기준은 아래다.

```text
앱 시작
→ 홈/프로필
→ 새 인생 시작
→ 성별/이름/캐릭터 설정
→ 장 표지에서 초점 선택
→ 자동 진행
→ 결정/돌발 발생
→ 선택지 결과 확률 처리
→ 기록 저장
→ 이어하기
→ 주마등
→ 인생 기록/칭호 결말
```

반드시 지켜야 할 것:

- main 직접 push 금지
- 서버 없이도 앱 완주 가능
- 실제 이미지가 부족하면 placeholder 도트 이미지로 대체
- 모든 장면은 도트풍 기준
- 숫자 확률 UI 노출 금지
- hidden death UI 노출 금지
- 영아·유년 사망 금지
- `{name}`, `{nameCall}` 미치환 문구 금지

## 2. 7주차 목표 — v4 구조 진입

### 주차 목표

기존 6주차 앱을 v4 구조로 바꾸기 위한 뼈대를 만든다. 이번 주의 핵심은 “자동 진행 가능한 게임 구조”와 “피그마 예시 기반 도트 화면 방향”이다.

### 완료해야 하는 기능

| 영역 | 완료 기준 |
|---|---|
| 엔진 | 시기, 해, 초점, 자동 진행, 결정/돌발 pending 상태 모델 생성 |
| 프론트 | 홈, 장 표지, 자동 진행, 결정/돌발 화면 초안 연결 |
| 시나리오 | 시기별 초점 20개, 대표 확률 사건 5개 작성 |
| DB·QA | v4 데이터 스키마 문서, 검증 스크립트 1차 보강 |
| UI/UX | 도트 이미지 규격, 화면 레이아웃 기준, 이미지 생성 프롬프트 작성 |
| 이미지 | 피그마 예시 느낌의 도트 후보 8장 또는 프롬프트 8개 이상 |

### 7주차 merge 조건

- `./gradlew.bat test` 통과
- `./gradlew.bat assembleDebug` 통과
- 홈 → 장 표지 → 자동 진행 → 결정 화면 이동 확인
- 대표 사건 5개 JSON 파싱 가능
- 이미지 ID와 placeholder 연결 가능
- PR별 팀장 검증 완료

### 7주차에서 하지 않아도 되는 것

- 모든 204개 사건 변환
- 완성형 이미지 전체 제작
- 실제 서버 연결
- 미래 모습 생성
- AI 회고 문장 연결

## 3. 8주차 목표 — 처음부터 끝까지 플레이 가능

### 주차 목표

v4 구조로 시작부터 결말까지 한 판을 완주할 수 있게 만든다. 이미지와 문장은 부족해도 앱 흐름이 끊기면 안 된다.

### 완료해야 하는 기능

| 영역 | 완료 기준 |
|---|---|
| 엔진 | 결과 확률, 큰 돌발, 일반 돌발, 마일스톤, 사망, 직장/경제력/자산, 군복무 1차 구현 |
| 프론트 | 이어하기, 배속, 주마등, 결말 화면 연결 |
| 시나리오 | 군대/직장/건강 경고/마일스톤 사건 작성 |
| DB·QA | 로더 오류 표시, maxStats, 시뮬레이션 1차, 저장 QA |
| UI/UX | 홈/장표지/자동진행/돌발/주마등 화면 1차 정리 |
| 이미지 | 3인칭 평소 장면 핵심 10장, 1인칭 돌발 장면 핵심 10장 또는 최종 프롬프트 |

### 8주차 merge 조건

- 개발용 24턴 기준 한 판 완주 가능
- 저장 후 앱 재시작해도 같은 해/같은 pending 결정 유지
- 같은 seed + 같은 선택 = 같은 결과
- 숨은 결과가 UI에 안 보임
- 영아·유년 사망 0건
- 실기기 또는 에뮬레이터에서 한 판 완주 캡처

### 8주차 통과 테스트

- `./gradlew.bat test`
- `./gradlew.bat assembleDebug`
- 가능하면 `./gradlew.bat connectedDebugAndroidTest`
- `python scripts/validate_content.py`

## 4. 9주차 목표 — 개발 핵심 완료

### 주차 목표

수치 조정, 이미지 연결, 결말 기록, 성능 검수를 끝내고 개발 핵심을 닫는다. 10주차부터는 큰 구조 변경을 하지 않는다.

### 완료해야 하는 기능

| 영역 | 완료 기준 |
|---|---|
| 엔진 | 확률/사망률/경제력/칭호 수치 조정, 시뮬레이션 결과 반영 |
| 프론트 | 예상 미래 모습 화면, 인생 기록 서류, 오류 없는 데모 동선 |
| 시나리오 | 결과가 갈리는 선택 30개까지 확장, 사인 문장, 칭호 문구 |
| DB·QA | 여러 seed 완주, 조기 사망률 목표 확인, 데이터 검증 안정화 |
| UI/UX | 도트 이미지 실제 적용, 작은 화면 검수, 접근성 문구 정리 |
| 이미지 | 피그마 예시 느낌의 핵심 이미지 세트 앱 연결 |

### 9주차 merge 조건

- 개발용 24턴 완주 + 목표 42턴 구조 전환 가능
- 최소 1개 고정 seed 데모 동선 확정
- 결말 기록에 모델에 없는 사실이 나오지 않음
- 주마등 화면에서 실제 본 장면을 재사용
- 이미지가 없어도 placeholder로 완주 가능
- 이미지가 있으면 도트가 흐려지지 않음

## 5. 10~12주차 운영 계획

앞 3주에 개발 핵심을 끝낸 뒤 남은 기간은 안정화와 발표 준비에 쓴다.

| 주차 | 목표 |
|---|---|
| 10주차 | 구조 변경 금지, 버그 수정, 발표용 고정 seed, 데모 동선 확정 |
| 11주차 | 이미지 보강, 문장 교정, 실기기 성능 검수, 교수/심사자 질문 대비 |
| 12주차 | 최종 발표자료, 시연 영상, 제출 패키지, README/Notion/GitHub 정리 |

## 6. 이미지 제작 일정

이미지는 한 번에 몇백 장을 만들지 않는다. 먼저 피그마 예시와 같은 스타일을 맞춘 뒤, 핵심 장면부터 만든다.

### 7주차

- 도트 스타일 가이드 확정
- 이미지 생성 프롬프트 확정
- 3인칭 5장, 1인칭 3장 후보 생성
- imageId 명명 규칙 확정

### 8주차

- 핵심 흐름 이미지 20장 수준 확보
- 홈/장표지/자동진행/돌발/주마등에 연결
- 없는 이미지는 placeholder 유지

### 9주차

- 자주 나오는 사건 위주로 이미지 추가
- 주마등 썸네일용 이미지 확인
- 작은 화면에서 잘림/흐림 검수

## 7. 위험 요소와 대응

| 위험 | 대응 |
|---|---|
| 이미지 생성량이 너무 많음 | 1인칭 사건은 비슷한 사건끼리 공유, 3인칭은 시기×초점 핵심만 먼저 제작 |
| 서버/API 비용 문제 | 9주차 전까지 `FakeGenerationClient`와 부품 조립 얼굴로 대체 가능하게 구현 |
| 엔진 구조 변경이 큼 | 7주차에는 기존 API를 바로 지우지 않고 새 API 병행 |
| 팀원 PR 충돌 | 역할별 수정 파일을 나누고, main 최신 pull 후 PR 생성 |
| 확률/사망률 밸런스 실패 | 8주차부터 시뮬레이션 결과로 조정 |
| UI가 너무 늦음 | 피그마 예시의 4개 화면만 먼저 구현하고 홈/미래 모습은 8주차에 완성 |

## 8. 팀장 주간 검증 루틴

매주 제출 후 아래 순서로 검증한다.

1. GitHub PR 목록 확인
2. 역할별 산출물 확인
3. `python scripts/validate_content.py`
4. `./gradlew.bat test`
5. `./gradlew.bat assembleDebug`
6. 앱 실행 캡처 확인
7. v4 금지사항 위반 여부 확인
8. 통과 PR만 merge
9. main pull 후 통합 검증
10. Notion 카드 상태 갱신
