## 2. 데이터 흐름

```text
선택 결과 → 엔진이 플래그를 붙임 (PeriodRunState.flags, 붙은 순서 유지)
          → life_facts.sample.json (flag → fact · label, 시나리오 담당)
          → buildLifeFacts(): 붙은 순서대로 덮어써서 "지금 상태"를 만듦
          → LifeFactsUi (교육 · 전공 · 직업 · 직급 · 일 · 관계 · 자녀 · 주거 · 경제력 구간 · 빚 · 건강 상태 · 업적)
          → 플레이 중 요약 줄 / 결과 화면 "새로 생긴 사실" / 결말 화면
```

- 백엔드가 `PeriodRunState`에 사실 필드(`educationLevel`, `careerTrack`, `maritalStatus`, `childrenCount`, `housingType`, `wealthBand`, `achievementFlags`, `deathPeriod`, `deathCause`)를 넣으면, `buildLifeFacts`의 입력만 그 필드로 바꾸면 된다. 화면 쪽 코드는 그대로 쓴다.
- 경제력 구간은 지금 경제력 수치로 정한다: 25 미만 빠듯함 / 50 미만 보통 / 75 미만 여유 / 그 이상 넉넉함. 백엔드의 `wealthBand`가 생기면 그 값을 쓴다.
- 대표 경로: 겪은 경로 사건(`path_<int|fit|soc|wea|hap|luk|hea>_*`) 하나당 10점에 그 스탯 값을 더해 가장 높은 쪽을 고른다. 경로 사건이 없으면 가장 높은 능력치를 따른다.

## 3. 잠금 이유 규칙

| 조건 | 화면 문구 |
|---|---|
| 최소 능력치 미달 | `지력 60 필요 (지금 52)` |
| 최대 능력치 초과 | `행복 30 이하일 때만 (지금 45)` |
| 필요한 사실 플래그 없음 | `대학 진학 필요` (이름은 `life_facts.sample.json`의 label) |
| 필요한 사건 완료 플래그 없음 (`v4:event:<id>`) | `「고등학교 원서」 이후 가능` |
| 이름표가 없는 플래그 | `「그 플래그를 주는 사건 제목」에서 이어지는 선택 필요` |
| 그것도 없을 때 | `앞선 선택이 필요해요` |
| 막는 플래그가 있음 | `이미 '결혼' 상태라 고를 수 없음` / `「…」 이후에는 고를 수 없음` |

- 잠긴 선택지는 위 이유에 필요 값과 지금 값이 이미 들어 있으므로, 원래 있던 "조건:" 줄은 겹쳐 쓰지 않는다.
- 실제 선택 가능 여부는 엔진(`resolvePeriodDecision`)이 다시 검사한다.

## 5. UI 상태별 수동 테스트 절차

1. 홈 → 새 인생 살기 → 남 · 골똘한 아기 → 시작
2. **영아기 결정 화면**
   - 상단 요약 줄: "초점 없음 · 대표 ○○ N" / "경제력 보통"
   - 줄을 누르면 "지금까지의 나" 시트가 열린다. 항목마다 기본 문구가 보인다.
3. **잠긴 선택지가 있는 결정**(유년기 「학원 고르기」 등)
   - 잠긴 카드에 자물쇠와 "행복 52 필요 (지금 51)" 같은 이유가 보인다. 눌러도 반응하지 않는다.
4. **선택 직후**
   - 능력치 변화(+/−)가 보인다.
   - 사실이 생기면 "새로 생긴 사실"에 "교육 대학 진학", "경제력 여유 → 보통" 같은 줄이 보인다.
   - 조건이 새로 맞은 사건이 있으면 "새로 열린 길: 「…」"가 보인다.
5. **자동 진행 화면**
   - 요약 줄이 "이번 시기 초점 ○○ · 대표 ○○ N"으로 바뀐다.
   - 사실이 쌓일수록 둘째 줄이 늘어난다.
6. **끝까지 진행 → 인생 요약**
   - 결말 제목 · 설명, 한 줄 인생 요약, 마지막(시기 · 원인)
   - 교육 · 직업, 가족 · 관계 · 주거 · 경제력, 업적, 많이 키운 능력치, 주요 선택
7. **(선택) 큰 글씨 확인**: 기기 설정 → 글자 크기 최대 → 3~6번을 반복한다. 글자가 잘리지 않고 줄이 바뀌기만 해야 한다.
