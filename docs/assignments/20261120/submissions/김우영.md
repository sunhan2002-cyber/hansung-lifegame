## 구현 내용

### 주사위와 도전 코드

- `LG2`에서는 6개 능력치 모두 두 눈의 합을 실제 증가량으로 사용한다.
- `StartingStatResult` 하나에 능력치명, 두 눈, 합, 증가량, 최종값을 담아 UI가 다시 계산하지 않게 했다.
- `LG1`은 `(합-7)×2`를 그대로 재현하고 `LG2`와 코드 접두어로 구분한다.
- 기존 저장의 실제 스탯과 건강은 재계산하지 않는다. 새 저장은 원본 눈, 규칙 버전, 남은 재굴림을 함께 저장한다.
- 앱 시작 화면과 10,000회 고정 시드 시뮬레이션이 같은 `StartingDice` 계약을 사용한다.

### 진행 중 인생 리셋

- 진행 저장 삭제를 동기 커밋한 뒤에만 런타임 세션·생성 작업을 정리한다.
- 삭제 실패 시 기존 인생을 메모리와 저장소에 보존하고 오류를 반환한다.
- 연타는 `CurrentLifeResetCoordinator`가 한 번만 처리한다.
- 완료 인생·칭호·설정 저장 영역은 삭제하지 않는다.

### 결혼 상태 계약

- 신기훈 PR #83의 계약 JSON에 정의된 13명 상대를 `partner_id_<id>`로 고정한다.
- 교제를 시작한 실제 사건·선택과 `met_*`, `dating__*`, `partner_<route>`가 일치할 때만 상대 ID를 만든다.
- 결별로 `dating`/`partner_*`가 사라지면 현재 상대 ID도 제거한다.
- 승인된 본식 4개는 교제·약혼·양가 인사·결혼 준비·단일 상대·미혼 조건이 모두 맞아야 후보가 된다.
- 본식에서 `spouse_id_<id>`를 한 번만 확정한다. 이미 결혼한 저장은 그대로 복원한다.

### 저장 호환

- v1~v4에 새 필드가 없으면 LG1 규칙으로 해석하되 저장된 스탯·건강·진행 상태는 그대로 유지한다.
