## P0. 3D 주사위 눈을 실제 스탯에 적용

첨부 화면의 경제력은 `1 + 4 = 5`인데 `50 − 4 = 46`으로 표시됐다. `StartingDice.kt`에서 합계 5에 기존 보정식 `(합계 − 7) × 2`를 적용한 값이다. PR #82의 결과 줄 단순화는 그 보정값을 그대로 사용하고 계산 근거도 가린다. 이번 과제는 두 눈의 합을 그대로 증가량에 쓰는 규칙으로 변경한다.

| 두 눈 | 실 증가량 | 기본 50에서 시작값 |
| --- | ---: | ---: |
| 1, 1 | +2 | 52 |
| 1, 3 | +4 | 54 |
| 1, 4 | +5 | 55 |
| 6, 6 | +12 | 62 |

- 주사위를 굴리는 6개 능력치에 적용한다. 건강 초기값은 현재 규칙을 따른다. 각 줄에서 능력치 이름, 두 눈의 합, 증가량, 최종값을 짧게 읽을 수 있어야 한다. 예시는 **경제력 · 1 + 4 = 5 · 50 + 5 = 55**다. 색 구분과 화면 읽기 문구도 실제 적용값을 사용한다.
- PR #82의 3D는 첫 능력치의 두 눈만 렌더링한다. 3D로 표시되는 능력치명을 명시하고 6개 행 각각의 눈을 확인할 수 있게 한다. 모든 행의 3D 재생이나 행별 확인 방식은 작은 화면과 접근성을 검증해 선택한다.
- 같은 굴림으로 3D 착지, 정적 대체, 결과 행, 실제 첫 사건 진입 전 스탯과 저장값이 일치해야 한다. 재굴림 횟수를 보존하고 회전·복원·연타로 재굴림이나 증가가 추가 적용되지 않게 한다.
- 기존 인생 저장의 실제 능력치를 다시 계산하지 않는다. 기존 `LG1` 도전 코드는 이전 규칙으로 재현하고, 새 규칙 코드는 버전을 구분한다. 앱과 시뮬레이터가 같은 규칙·시작 상태를 사용하도록 한다. 36개 눈 조합과 6개 능력치를 검증하고, 초기값 변화가 성향·조건 선택지·건강·엔딩 분포에 주는 영향은 고정 시드 10,000회로 확인한다.

## P1. 만남에서 실제 결혼식까지 이어지는 서사

PR #82에는 `love_*` 사건 20개와 연결 PNG 20장이 이미 있다. 일반 경로의 `결혼식 10분 전`은 대기실 사건이고, 음악 경로에는 `연주로 채운 축가`가 있다. 플레이어가 직접 선택하는 결혼식 본식과 상대별 연애 이야기를 추가한다.

- 최소 3개의 구별되는 연애 경로를 구성한다. 첫사랑·음악·독서 인연처럼 이미 만난 인물을 재사용할 수 있다. 실제 만남 → 상대 선택 또는 거절 → 상대별 첫 데이트와 추가 에피소드·갈등/화해 → 결혼 논의·양가 인사 → 결혼 준비 → **플레이어 본인의 실제 본식** 순서가 인게임에서 이어져야 한다.
- 본식은 독립 사건으로 구현한다. 입장·서약·축하 같은 본식 행동과 본문·전용 그림·실제 선택 결과가 있어야 한다. 공통 본식에 상대별 문구나 연출을 달아도 된다. 같은 상대가 사건과 인생 기록에 이어지고, 성공을 의미하는 실제 본식 선택 결과에서 혼인 상태를 한 번만 확정한다.
- 거절·이별·결혼 보류·비혼 경로를 열어 둔다. 새 인생에서 만나지 않은 상대, 교제나 약혼 조건이 없는 상대와 갑자기 결혼하는 흐름을 차단한다. 기존 이미 결혼한 저장은 호환한다. 친구 결혼식과 결혼식 직전 대기실은 본식 완료 수량에 포함하지 않는다. `adult_032`처럼 ‘결혼한다’는 문구와 약혼으로만 저장되는 결과도 단계에 맞게 정리한다.
- 시나리오 담당이 사건 ID·선행 조건·핵심 사물 명세를 먼저 공유한다. 이미지 담당은 본식·준비·각 루트의 주요 연애 장면 전용 그림을 제작하고 선택 전에 혼인 결과를 확정해 보이는 연출을 피한다. 360×740dp 크롭에서도 상대, 서약, 핵심 소품이 읽혀야 한다.

## P0. 진행 중 ‘인생 리셋’

- 플레이 중 일시정지 또는 메뉴에 **인생 리셋**을 넣고 게임 진행 화면 안에서 접근할 수 있게 한다. 선택하면 **“현재 진행 중인 인생은 사라집니다. 새 인생을 시작할까요?”** 확인 창을 연다. 버튼 문구는 **취소**, **새 인생 시작**으로 분명히 구분한다.
- 취소·뒤로가기는 기존 진행과 화면 상태를 보존한다. 확인하면 현재 진행 중인 인생과 대기 중 자동 진행을 정리하고 새 인생의 프로필·주사위 화면으로 바로 이동한다. 완료한 지난 인생·칭호·설정은 유지한다. 진행 데이터 정리에 실패하면 기존 인생을 보존하고 실패를 알려야 한다.
- 자동 진행 중, 선택 대기, 결과 표시 중, 복원 후에 각각 확인과 취소를 검증한다. 확인 연타·앱 종료·재실행 뒤 폐기된 인생이 다시 열리거나 완료 기록·보상이 중복 추가되지 않아야 한다.

## P1. 진행 화면에 보이는 중복 문구 제거

- 첨부 화면의 캐릭터 밑 **‘영아기 · 다음 사건을 기다리는 중’**, 기록에 반복되는 **‘영아기 · 1번째 해’**, 진행 막대 옆의 **‘다음 해까지’**, 기록의 **‘그해 이야기’** 같은 해 단위·상태 문구를 제거하거나 문맥에 필요한 이름으로 정리한다.
- 하단 생애 시기 바, 필요한 현재 시기 표시, 사건·선택 본문, 새 사실, 배속·일시정지·다음 결정 컨트롤을 살린다. **내 선택**과 **자동 이야기**는 필요할 때 짧게 구분한다. 내부 진행 인덱스와 저장 구조는 표시 문구 변경과 독립적으로 유지한다. 인생 기록의 실제 사망·결말 시기는 정확히 보여 준다.
- 6개 시기, 선택 결과·자동 이야기 섞임, 일반 글꼴 및 200% 글꼴에서 화면을 확인하고 전후 캡처를 제출한다.

## PR #82 통합 판단과 성능

1. AI 승인 커밋 `cb4c9ff`의 이미지·의미 인수 기록은 실제 표시 PNG와 원본 SHA를 대조한다. 사람 승인으로 표시하지 않는다. 기록 오류가 있는 행만 수정하고, 승인 근거가 남지 않은 항목을 승인으로 세지 않는다.
2. 돌잡이 `infant_007`은 팀장 커밋의 새 원화 때문에 기존 승인과 달라졌다. 선택 전에는 피아노·판사봉·지폐가 중립적으로 보이는 돌상 그림을 검수하고, 판사봉을 잡은 그림은 해당 결과가 확정된 경로에만 쓴다. 선택 화면·장면 보기·이어하기에서 확인 후 현재 PNG SHA로 인수한다.
3. 세로 파생본은 `797e939` 기준 95건으로 문서상 11/19의 96건과 시점이 다르다. 패키지 크기·표시 프레임·로딩을 비교해 파생 PNG부터 줄인다. 동일한 장면의 가독성·도트 경계·핵심 사물 보존과 원본/파생 SHA 검증이 모두 통과해야 한다.
4. 같은 에뮬레이터에서 모션 기본/끔으로 로비·주사위·대표 세 사건을 비교한다. 지원 실기기에서 첫 실행, 장면 로딩, P95·지연률, 메모리, 15분 연속 플레이 발열·배터리를 기록한다. APK 절감은 처음에 세로 이미지 묶음의 30% 절감을 작업 목표로 삼고, 변경 전후 화질·성능을 제시해 목표 조정이 필요한 경우 근거를 남긴다.
5. PR 병합 후보에서 저장 호환, 릴리스 보안 검사, 원격 CI, 새 기능 계측 테스트와 전체 기기 회귀를 다시 실행한다. 업데이트 전후의 구버전 데이터와 이어하기, 로비의 신규·진행 중·완주 후 세 상태, 설정의 모션 끄기, 3D 정적 대체, 장면과 기록증을 확인한다. 팀 서명·실기기 측정은 각각 결과를 명시한다. 자동 테스트 통과와 최종 인수 판단은 별도다.
