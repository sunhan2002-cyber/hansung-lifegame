## 구현 내용

- 사진 동의·권한·처리 실패 상태를 `PhotoFlowStatus`로 분리했다.
- 돌잡이 컷신 상태를 `CutsceneStatus`로 저장하며 보상 상태와 분리했다.
- 사건 이미지 선노출 상태를 사건 ID와 함께 저장하고, 같은 사건의 표시 완료가 복원 후 다시 대기로 돌아가지 않게 했다.
- 선택 결과 애니메이션을 `resultDisplayId` 기반 순수 표시 이벤트로 만들었다. 애니메이션 확인은 엔진 선택·능력치 반영을 다시 호출하지 않는다.
- 자동 연도 이야기와 선택 결과를 `RunNarrativeKind`로 구분해 실제 표시 문장 그대로 저장한다.
- 선택 결과 기록에는 원본 사건 ID와 선택지 ID를 필수로 두어 출처 없는 결과 문장을 기록할 수 없게 했다.
- `recordId` 기반 `appendOnce`로 화면 복원·반복 호출에도 같은 기록이 중복되지 않게 했다.
- 저장 형식을 v4로 올리고 v1~v3 저장은 새 표시 상태와 기록이 기본값인 상태로 계속 읽는다.
- 주사위 초기 스탯, 건강·생존·사망 판정, 실제 보상 계산은 변경하지 않았다.

## 2026-11-09 보완

- `CharacterSelectScreen`의 동의 요청, 사진 선택 권한/피커 진입, 처리 중, 준비 완료, 취소·읽기/생성 실패를 `PhotoFlowStatus`에 실제 연결했다.
- 프로필에서 결정된 사진 흐름 상태를 새 인생의 `PresentationState`로 넘겨 저장하며, 사진 실패 사유는 `FALLBACK`일 때만 남긴다.
- `PeriodPlayUiState`에 표시 전용 `PresentationState`를 전달한다. 사건 그림이 실제 구성되면 `markEventImageShown`, 결과 카드 애니메이션이 끝나면 `markResultAnimationConsumed`만 호출한다.
- 결과 카드 표시 애니메이션은 260ms 표시 효과이며 엔진 선택, 보상, 기록, 건강·사망 판정을 호출하지 않는다. 모션 줄이기 설정에서는 즉시 완료한다.
- 빠른 연타·재구성으로 같은 선택 콜백이 반복되어도 `runId:eventId:choiceId` 입력은 `ChoiceApplicationGuard`에서 한 번만 엔진으로 전달한다. 엔진 호출 실패 때만 재시도를 허용한다.
- v1, v2, v3 저장 복원 테스트를 각각 유지·추가했다. 구버전에는 새 표시 상태와 서사 기록 기본값을 넣고 기존 건강·플래그·생존 상태는 보존한다.

## 남은 작업

- 사진 흐름, 이미지 선노출 완료, 결과 애니메이션 완료는 실제 화면과 연결했다. 돌잡이 컷신은 현재 `main`에 독립 화면이 없어 상태 API와 저장 계약만 유지하며, 프론트 컷신 화면 병합 시 `setCutsceneStatus`를 연결해야 한다.
- Pixel_7 AVD는 로컬 Windows의 WHPX 하드웨어 가속 비활성으로 부팅되지 않아 실제 기기 크롭·화면 검증은 팀 가속 환경에서 필요하다.
- 김우영 이미지 잔여 그룹은 소량 배치로 계속 제작하고 의미·중앙 크롭·라우팅 승인을 각각 받아야 한다.
- 제출과 팀 최종 승인은 구분한다.

## 2026-11-10 통합 후속 검증

- PR #65 통합 브랜치가 PR #63의 최신 커밋을 포함하는 것은 확인했지만, 프론트 PR #61 충돌 해결 과정에서 `DecisionScreen`의 사건 이미지 표시 완료·결과 애니메이션 소비 콜백이 빠진 것을 확인했다.
- 통합 브랜치 기준 후속 작업에서 `markEventImageShown`과 `markResultAnimationConsumed`를 새 사건 선노출·변화 애니메이션 화면에 다시 연결했다.
- 결과 애니메이션 소비는 `ResultAnimationStatus.PENDING`인 동일 `resultDisplayId`에만 실행하며, 엔진 선택·보상·기록·건강·사망 판정을 호출하지 않는다.
- 모션 줄이기 또는 변화 수치가 없는 결과는 즉시 소비하고, 일반 변화 애니메이션은 표시 시간 이후 소비한다.
- 통합 기준 `gradlew.bat test assembleDebug`는 성공했고 Debug·Release 합계 406개 테스트가 실패·오류·건너뜀 없이 통과했다. `python scripts/validate_content.py`도 PASS였다.
- 돌잡이 컷신은 통합 브랜치에도 독립 화면이 없어 `setCutsceneStatus` API와 저장 계약까지만 검증했다. 실제 컷신 화면의 시작·완료·건너뛰기 호출 연결은 프론트 협업 항목이며 완료로 보고하지 않는다.
