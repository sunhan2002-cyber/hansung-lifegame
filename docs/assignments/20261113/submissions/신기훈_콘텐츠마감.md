## 4. 확장 콘텐츠 검증 (실제 기록과 연결)

- **고친 점**:
  - **NPC 관계 플래그**: 결별 때 지워지는 연인 플래그(`partner_*`)를 쓰고 있어, 재회 사건에서 사람을 찾지 못했다. 이제 그 사람과 관계가 생길 때만 붙고 지워지지 않는 사람별 플래그(`met_festival`·`met_bus`·`met_music_band`·`met_book_club` 등)를 쓴다.
  - **NPC 항목 분리**: 한 항목에 연인 플래그 5개를 모두 요구해(`containsAll`) 영원히 나오지 않는 항목이 있었다. 같은 페르소나라도 만난 곳이 다르면 사람별로 나눴다. 지금 연인 사건은 `dating__<만난 사건>`으로 구분한다.
  - **NPC 출발 기록**: `origin.choiceIds`를 관계가 생기는 선택으로 좁혔다.
  - **회상 표시 위치**: `showIn`에서 자동 사건 ID를 빼 선택 사건과 결말만 남겼다(화면 조회 함수가 선택 사건 화면에서만 부른다).
  - **결별 카드**: `tp_family_breakup`은 `love_conflict_01`에서 실제로 헤어진 경우(`ex_partner`)에만 나온다. 전에는 화해했다가 나중에 다른 이유로 헤어진 인생에도 나왔다.
- **감사 스크립트에 추가한 규칙**:
  - 회상 원본 사건·선택이 실제로 존재한다.
  - 표시 위치는 선택 사건 또는 `ENDING`이다.
  - 카드 사건과 플래그가 실제로 만들어진다.
  - 칭호 47개가 빠짐없이 덮인다.
  - NPC 출발 사건·선택이 존재하고, 관계 플래그는 만들어지되 어떤 결과도 지우지 않는다.
  - 등장 사건이 존재한다.
- **10,000개 인생 기록 대입**: 김재겸 `ScenarioExtensions.kt`의 판정 규칙을 그대로 옮겨 실제 선택 기록(trace)에 적용했다.

- **main의 영아·유년 사망(김우영·팀장)**: main 엔진이 "건강 0 = 즉시 사망"을 반영하며 영아·유년 건강 하한(`healthFloor`)을 없앴다.
