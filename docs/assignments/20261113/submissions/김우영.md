## 구현 내용

1. 노년기 사건이 있는 해에는 선택 결과 해석에서, 사건이 없는 해에는 자동 진행에서 연간 건강 감소가 정확히 한 번만 적용되도록 수정했다.
2. 영아기·유년기를 포함한 모든 시기에서 건강이 0이 되면 즉시 사망하고 실제 `deathPeriod`와 `deathCause`를 기록한다.
3. 결과 화면용 `SavedOutcome`에 선택 당시 `period`와 `yearInPeriod`를 저장해 달력 이동·앱 재실행 뒤에도 같은 시기와 해를 표시한다.
4. 고용 상태 규칙에 연결된 플래그는 취업·실업·은퇴 중 마지막으로 추가된 한 상태만 남도록 정규화한다.
5. 자동 소사건용 `AutomaticEvent`, `AutomaticEventRecord`, 트리거 및 저장 상태를 추가했다.
   - 선택·돌발·마일스톤 또는 결말 대기 중에는 실행하지 않는다.
   - `eventId + triggerToken`을 저장해 같은 진행 단계에서 보상과 기록이 중복 적용되지 않는다.
   - 능력치 변화가 없는 사건은 기록만 남길 수 있다.
   - 시나리오 JSON 목록은 아직 팀 산출물에 없으므로 엔진·세션 주입 계약까지만 연결했다.
6. 시작 주사위의 두 눈 원본, 합계, 보정치, 최종 능력치를 하나의 `StatRoll`에서 계산하고 원본값을 현재 인생 저장 데이터에 보존한다.
7. 기존 v1~v4 저장에는 새 필드가 없어도 빈 자동 사건 이력·null 주사위·null 결과 시기 스냅샷으로 안전하게 복원된다.

## 시연 순서

1. 새 인생에서 주사위를 굴려 각 행의 `두 눈=합 → 최종 능력치` 문구를 확인한다.
2. 게임을 시작하고 자동 진행·결정 사건·결과 화면을 진행한다.
3. 결과 화면에서 앱을 종료한 뒤 이어하기로 선택 당시 시기·해와 사실 변화를 확인한다.
4. 건강이 0이 되는 테스트 경로에서 즉시 결말과 사망 시기·원인이 기록되는지 확인한다.
