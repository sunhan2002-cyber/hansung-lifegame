## 구현 내용

1. 노년기 사건이 있는 해에는 선택 결과 해석에서, 사건이 없는 해에는 자동 진행에서 연간 건강 감소가 정확히 한 번만 적용되도록 수정했다.
2. 영아기·유년기를 포함한 모든 시기에서 건강이 0이 되면 즉시 사망하고 실제 `deathPeriod`와 `deathCause`를 기록한다.
3. 결과 화면용 `SavedOutcome`에 선택 당시 `period`와 `yearInPeriod`를 저장해 달력 이동·앱 재실행 뒤에도 같은 시기와 해를 표시한다.
4. 고용 상태 규칙에 연결된 플래그는 취업·실업·은퇴 중 마지막으로 추가된 한 상태만 남도록 정규화한다.
5. 자동 소사건용 `AutomaticEvent`, `AutomaticEventRecord`, 트리거 및 저장 상태를 추가했다.
   - 선택·돌발·마일스톤 또는 결말 대기 중에는 실행하지 않는다.
   - `eventId + triggerToken`을 저장해 같은 진행 단계에서 보상과 기록이 중복 적용되지 않는다.
   - 능력치 변화가 없는 사건은 기록만 남길 수 있다.
   - 시나리오 JSON 목록은 아직 팀 산출물에 없으므로 엔진·세션 주입 계약까지만 연결했다.
6. 시작 주사위의 두 눈 원본, 합계, 보정치, 최종 능력치를 하나의 `StatRoll`에서 계산하고 원본값을 현재 인생 저장 데이터에 보존한다.
7. 기존 v1~v4 저장에는 새 필드가 없어도 빈 자동 사건 이력·null 주사위·null 결과 시기 스냅샷으로 안전하게 복원된다.

### 실제 구현

1. `auto_events.sample.json` 49건을 `AutomaticEvent`로 파싱하고 `V4Content`와 `ContentRepository`를 통해 새 게임·이어하기의 `PeriodGameSession`에 주입했다.
2. 자동 사건은 별도 연도 카운터를 추가하지 않고 현재 시기의 실제 진행 기록에서 `progressStep`을 계산한다.
3. `PERIOD_START`, `PERIOD_MID`, `PERIOD_END`, `AFTER_EVENT`, `ELAPSED_TIME` 규칙과 스탯·플래그·인생 사실 조건을 검사한다.
4. 선택·마일스톤·돌발 사건이 생긴 단계에서는 자동 사건을 실행하지 않는다. 시기별 최대 건수, `eventId + triggerToken`, `dedupeKey`, repeatable 정책을 적용한다.
5. `RECORD_ONLY` 사건은 JSON에 수치가 있더라도 능력치 변화를 적용하지 않고 기록만 남긴다. 후보 선택은 eventId 첫 항목 고정이 아니라 seed·시기·진행 단계 기반 결정적 추첨이다.
6. `RunExtensionApi`와 `RunExtensionState`를 추가했다.
   - 실제 `RunChoiceRecord`가 있는 경우에만 회상 근거를 반환한다.
   - 실제 기록이 있는 사건만 결말 계기 카드 후보로 최대 3건 반환하며 2건 미만이면 만들지 않는다.
   - 실제 첫 만남 선택과 관계 플래그가 모두 있어야 NPC 재등장을 허용한다.
   - 칭호 다음 판 목표·힌트, 시작 성별·주사위·seed 도전 코드 상태를 한 인생 단위로 저장한다.
   - 지난 두 인생 비교 기능은 구현하지 않았다.
7. 자동 사건 `dedupeKey`, 회상 근거 사건 ID, 계기 사건 ID, 칭호 목표 상태, 도전 코드 입력 상태, 관계 플래그를 저장·복원한다. 기존 v1~v4 저장에는 빈 기본값을 사용하며 다른 완료 인생의 상태와 합치지 않는다.
