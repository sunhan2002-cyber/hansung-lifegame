## 4. 자동 소사건 규칙

- 매년 카운터를 쓰지 않는다. `ELAPSED_TIME`은 같은 시기에서 선택·돌발 없이 지나간 자동 진행 횟수(`afterAutoSteps`)이고, `PROGRESS_STAGE`는 시기 진입·중반·마지막 해·특정 사건 완료 직후다.
- 스탯은 감기·용돈·운동회·월급처럼 바뀔 만한 사건에만 준다(`statEffect: STAT`, ±1~2). 나머지는 `RECORD_ONLY`.
- 자동 사건이 추가하는 플래그는 `auto_ya_love_start`(예전에 망설였던 인연과 연애 시작)의 `dating`·`partner_second_chance`뿐이다. 칭호·결말 조건 플래그는 건드리지 않는다.
- 월급·직장 관계는 재직 중만, 구직은 재직·자영업이 아닐 때만, 배우자·결혼기념일은 결혼했을 때만, 자녀·손주는 `lifeFacts.minChildrenCount 1`일 때만 나온다.
- 돌잡이 사진(선택에 따라 3종 중 1), 전학생 생일 초대·청첩장, 중학교 전학생, 축제 사진, 노년의 첫사랑 회상은 실제 선택 플래그가 있을 때만 나온다.

## 6. 저장 호환

- 사건 ID는 지우거나 바꾸지 않았다. 대기 중 선택 사건도 그대로 복원된다.
- 자녀 사건 9개는 `v4:event:adult_039` 대신 `lifeFacts.minChildrenCount 1`을 쓴다. 기존 규칙 `v4:event:adult_039 → childrenAtLeast 1`을 남겨 두어, 구버전 저장에서 첫 아이를 본 인생도 계속 자녀 사건을 본다.
- 구버전 저장의 `dating`(후보 플래그 없음)은 공통 갈등·결혼 논의로 이어진다. 구버전의 `married`는 결혼 규칙 그대로다.
- 선택지 라벨은 저장되지 않는다(`V4ProgressStore`·`Week10ProgressCodec` 확인). 선택 기록 `eventId:choiceId`는 바뀌지 않았다.
