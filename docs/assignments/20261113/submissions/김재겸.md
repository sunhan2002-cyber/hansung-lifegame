## 2. 구현

### 2-1. 사건 화면 순서: 그림 선노출 → 제목 · 본문 타이핑 → 선택지 (과제 2)
- `DecisionScreen.kt`
  - 돌발 사건은 팝업 "사건 보기" 다음에 바로 선명한 그림을 보여 준다.
  - 그림이 끝나면 제목 · 본문 타이핑, 본문이 끝나면 선택지가 나온다.
  - 전환점 사건도 같은 순서를 쓴다(팝업만 없음). 체크리스트의 "사건이 시작되면 해당 사건 이미지가 먼저 선노출된다"에 맞춰 두 종류의 흐름을 하나로 맞췄다. 전환점은 예외로 두려면 알려 주기 바란다.
- 그림 아래 안내는 "누르면 본문으로", 낭독 설명은 "○○ 장면. 누르면 본문으로 넘어갑니다"로 바꿨다(정원률 11-14 검수 요청).
- 그림을 읽지 못하면(파일 없음 · 깨짐) 선노출을 건너뛰고 본문으로 간다. 읽는 중이면 최대 1.5초 기다린다.
  - 이 경우 "선노출 완료"로 저장하지 않는다.
  - `FilmStrip.SceneImage`가 `LOADING / READY / FAILED`를 알린다.

### 2-2. 다음 단계로 넘기는 터치가 선택으로 통과하지 않음 (과제 3)
- 선노출이 **터치 · 시간 초과 · 뒤로가기**로 끝나면 300ms 동안 터치를 삼킨다(#73).
- 본문이 끝나 선택지가 **처음 나타나는 순간**에도 같은 보호를 건다. 저절로 끝난 경우를 포함하며, 순서가 바뀌어 새로 생긴 경계다.

### 2-3. 결과 화면의 선택 당시 시기 · 연도 · 그림 · 사실 변화 (과제 4)

- 이어하기 뒤 "새로 생긴 사실"(특성화고 등)이 사라지던 문제를 고쳤다.
  - `SavedOutcome`에 **선택 전 플래그**(`beforeFlags`, 선택 항목)를 더해 선택 전 사실을 다시 계산한다(`restoredFactChanges`).

- 결과 화면 그림은 #74의 `eventImageId` 스냅샷을 그대로 쓴다.

## 3. 승인된 확장 기능 UI
