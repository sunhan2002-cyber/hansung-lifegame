## 2. 구현

### 2-1. 사건 화면 순서: 그림 선노출 → 제목 · 본문 타이핑 → 선택지 (과제 2)
- `DecisionScreen.kt`
  - 돌발 사건은 팝업 "사건 보기" 다음에 바로 선명한 그림을 보여 준다.
  - 그림이 끝나면 제목 · 본문 타이핑, 본문이 끝나면 선택지가 나온다.
  - 전환점 사건도 같은 순서를 쓴다(팝업만 없음). 체크리스트의 "사건이 시작되면 해당 사건 이미지가 먼저 선노출된다"에 맞춰 두 종류의 흐름을 하나로 맞췄다. 전환점은 예외로 두려면 알려 주기 바란다.
- 그림 아래 안내는 "누르면 본문으로", 낭독 설명은 "○○ 장면. 누르면 본문으로 넘어갑니다"로 바꿨다(정원률 11-14 검수 요청).
- 그림을 읽지 못하면(파일 없음 · 깨짐) 선노출을 건너뛰고 본문으로 간다. 읽는 중이면 최대 1.5초 기다린다.
  - 이 경우 "선노출 완료"로 저장하지 않는다.
  - `FilmStrip.SceneImage`가 `LOADING / READY / FAILED`를 알린다.

### 2-2. 다음 단계로 넘기는 터치가 선택으로 통과하지 않음 (과제 3)
- 선노출이 **터치 · 시간 초과 · 뒤로가기**로 끝나면 300ms 동안 터치를 삼킨다(#73).
- 본문이 끝나 선택지가 **처음 나타나는 순간**에도 같은 보호를 건다. 저절로 끝난 경우를 포함하며, 순서가 바뀌어 새로 생긴 경계다.

### 2-3. 결과 화면의 선택 당시 시기 · 연도 · 그림 · 사실 변화 (과제 4)

- 이어하기 뒤 "새로 생긴 사실"(특성화고 등)이 사라지던 문제를 고쳤다.
  - `SavedOutcome`에 **선택 전 플래그**(`beforeFlags`, 선택 항목)를 더해 선택 전 사실을 다시 계산한다(`restoredFactChanges`).

- 결과 화면 그림은 #74의 `eventImageId` 스냅샷을 그대로 쓴다.

### 2-4. 돌잡이 컷신 (과제 5)

  - 한 번 탭하면 완료, "건너뛰기"나 뒤로가기면 건너뜀.

  - 완료 · 건너뜀 뒤에는 이어하기에서 다시 재생하지 않는다.

- 컷신은 연출 상태만 바꾼다. 능력치 · 플래그 · 보상은 건드리지 않는다.

### 7-2. 자동 사건 화면 연결

김우영 `AutomaticEvent`(엔진 · 저장)와 신기훈 `auto_events.sample.json`(49개)이 main에 있었지만, 실제 플레이에서는 한 번도 나오지 않았다. 원인은 두 가지다.
- 앱이 콘텐츠를 읽지 않았다.
- 이 게임은 해마다 돌발이 보장돼 "결정 없이 지나간 해"가 거의 없다. 엔진은 그런 해에만 자동 사건을 붙이므로 기회가 없었다.

연결 방식:

| 항목 | 내용 |
|---|---|
| 읽기 | `data/AutomaticEventParser.kt`: 시기 · 트리거 · 조건(플래그 · 능력치 · 생애 사실) · 능력치/기록만 · 중복 키를 읽는다. `RECORD_ONLY`는 콘텐츠에 값이 있어도 능력치를 바꾸지 않는다 |
| 고르기 | `domain/engine/AutomaticEventRules.kt` `AutomaticEventPicker` |
| 나오는 때 | **한 해의 결정이 끝나고 다음 해로 넘어가기 전 한 단계.** 해 · 시기는 넘기지 않으므로 그해 결정은 다음 단계에서 그대로 나온다 |
| 우선순위 | 결정 대기 · 돌발 · 장 표지(초점 선택) · 결말 중에는 고르지 않는다. 결과 화면에도 붙지 않는다 |
| 한도 | 한 단계 1건, 한 시기 2건(영아기 · 노년기 3건). 같은 eventId · 같은 중복 키는 한 인생에 1번 |
| 추첨 | 바로 앞 선택에 이어지는 `AFTER_EVENT`(예: 돌잡이 사진)를 먼저 고른다. 나머지는 runSeed · 시기 · 진행 단계로 결정적으로 뽑되, 남은 자리를 시기의 남은 단계에 고르게 나눈다. 매번 채우면 시기 앞쪽에서 한도가 차 "마지막 해" 사건이 나올 수 없었다 |
| 사망 | 자동 사건으로는 죽지 않는다. 건강을 0 이하로 만드는 후보는 고르지 않는다. 엔진 `applyAutomaticEvent`의 낮은 건강 확률 사망 굴림은 뺐다(콘텐츠 규칙 "사망 판정은 하지 않는다"). 건강 0 즉시 사망 규칙은 그대로다 |
| 화면 | 자동 진행 화면 맨 위의 **자동 사건 카드**. 아래 표 참고 |
| 기록 | 자동 진행 기록 줄에 "자동" 표시, 인생기록증에 "저절로 지나간 일"로 선택 기록과 따로 표시한다 |
| 저장 · 복원 | 엔진의 진행 단계 키(`runId:auto:시기:해`)로 다시 적용하지 않는다. 카드를 보던 중 앱이 꺼지면 이어하기에서 같은 카드를 다시 보여 준다 |

자동 사건 카드:
- 맨 위에 "자동" 표시와 주제를 둔다.
- 그 아래에는 능력치가 바뀌었으면 변화(예: `건강 −2`)를, 아니면 "능력치 변화 없이 기록에만 남겼어요"를 보여 준다.
- 근거 선택이 실제로 있으면 "그때 그 선택" 회상을 붙인다.
- 관계가 이어진 사람이면 "다시 만난 사람"을 붙인다.
- 한 해 3초로는 29~65자 문장을 읽기 어려워, 카드는 글자 수에 맞춰 1배속 4~8초 머문다. 배속을 올리면 그만큼 줄고, 멈춤으로 붙잡을 수 있다.

수치(JVM, 같은 엔진 · 콘텐츠로 200개 인생):
- 자동 사건 **총 2,730건**, 인생당 평균 13.65건(최소 3 · 최대 14).
- 기록만 남긴 사건 1,070건, 콘텐츠 49개 중 48개가 나왔다.
- 단계별: 경과 1,137 · 중반 1,018 · 시작 253 · 직후 244 · 마지막 해 78.
- 노년기 전에 끝난 인생: 자동 사건 있음 10 · 없음 7(200개 중). 자동 사건 자체로 죽은 경우는 0이다. 차이는 능력치 변화로 이후 길이 달라진 데서 온다.
- 60개 인생에서 매 자동 사건의 조건 · 능력치 · 한도 · 우선순위를 단언했다. 지나간 해마다 결정은 정확히 1번이다.

### 7-4. 돌잡이 컷신과 새 게임 흐름

- **흐름**: 첫 화면 "새 인생 살기" → 프로필(도전 코드로 출발선) → "이 인생 시작하기" → **돌잡이 컷신** → 첫 사건(돌잡이) 본문 → 선택지.
  - 실제 화면 경로 그대로 기기 테스트로 확인했다.
  - 첫 사건은 항상 돌잡이다(영아기 1년차 마일스톤). 1년차에는 조건에 맞는 자동 사건이 없어 사이에 끼지 않는다.
- **완료**: 2초 뒤 저절로 끝나고 저장(COMPLETED). 같은 그림을 선노출로 한 번 더 보여 주지 않고 본문부터 시작한다.
- **건너뛰기 · 뒤로가기**: 둘 다 SKIPPED가 된다. 뒤로가기는 홈으로 나가지 않고 첫 사건에 머문다.
- **저장 · 복원**
  - 재생 중 종료 → 이어하기: 컷신을 다시 보여 준다.
  - 끝난 뒤 종료 → 이어하기: 다시 보여 주지 않는다.
  - 컷신은 능력치를 바꾸지 않는다.
- **선택 유도 검토**: [김재겸_돌잡이_유도검토.md](김재겸_돌잡이_유도검토.md). 결론은 "유도 있음"이다.
  - 그림이 판사봉을 잡은 순간이라 A · C를 고르면 이야기가 어긋난다.
  - 보상상 B가 가장 유리하지는 않다.
  - 컷신 그림의 화면 낭독 문구가 그림과 달라(손이 "그중 하나로 뻗는다") 그림대로 고쳤다.
  - 그림 순서는 팀장 결정으로 남긴다. 추천은 선택 전에는 손 없는 이전 승인 그림, 판사봉 결과에서 잡는 그림이다.
