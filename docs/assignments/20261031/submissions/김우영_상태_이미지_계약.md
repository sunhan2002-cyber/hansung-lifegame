# 김우영 상태·이미지 복원 계약

## 건강 표시와 게임 상태

- 건강 게이지의 4색 구간은 화면 표시 규칙이다.
- `0..10`을 빨강으로 표시해도 `health`, `isDead`, `isEnding` 또는 저장된 진행 상태를 변경하지 않는다.
- 생존·사망 판정은 기존 엔진 결과만 사용한다. 표시 계층에서 건강을 깎거나 사망을 만들지 않는다.
- 이전 저장을 포함해 건강 수치는 정수값 그대로 왕복해야 한다. 자동 테스트는 건강 10의 저장·복원 후에도 `health == 10`, `isDead == false`, `isEnding == false`임을 확인한다.

## 사건 본문 타이핑 입력

- `displayedChars < totalChars`인 동안의 탭 결과는 `COMPLETE_TEXT` 하나뿐이다.
- 이 탭은 본문을 전부 표시하고 소비한다. 같은 탭을 선택 적용, 다음 사건 이동, 결과 적용, 보상 지급으로 전달하지 않는다.
- 본문이 이미 완성된 다음의 별도 탭만 `FORWARD`로 반환할 수 있다.
- 순수 계약은 `NarrativeInputState.consumeTap()`에 있고 프론트는 이 반환값을 입력 처리에 사용한다. 엔진 진행 함수를 직접 호출하는 로직은 이 계약에 넣지 않는다.

## 사건 이미지 식별자

1. JSON 로딩 시 사건 화면 ID는 `povImageId`를 우선한다.
2. `povImageId`가 비어 있을 때만 `imageId`를 사용한다.
3. 파서는 위 우선순위를 적용한 값을 `DecisionEvent.povImageId`와 `PendingDecision.povImageId`로 넘긴다.
4. 선택 당시 실제 화면에 사용한 ID는 `RunChoiceRecord.eventImageId`와 `SavedOutcome.eventImageId`에 스냅샷으로 저장한다.
5. 결과 확인 중 앱을 다시 열면 `SavedOutcome.eventImageId`를 현재 콘텐츠보다 우선한다. 따라서 콘텐츠 매핑이 바뀌어도 이미 적용한 결과가 다른 사건 그림으로 복원되지 않는다.
6. 완료 인생의 주마등은 `momentImageId`가 있으면 이를 우선하고, 없으면 선택 당시 `eventImageId`, 이전 저장이라 둘 다 없으면 현재 콘텐츠 사건 ID를 사용한다.
7. `eventImageId`가 없던 이전 저장은 `null`로 읽어 계속 호환한다.

UI의 파일 경로 선택과 후보 라우팅은 기존 `ImageRouting`을 그대로 사용한다. 이 계약은 별도 UI 라우터를 만들지 않는다.

## 검증 항목

- `NarrativeInputGateTest`: 타이핑 중 탭 소비, 완료 후 별도 탭 전달, 빈 본문 처리.
- `Week10ProgressCodecTest`: 선택 기록·대기 결과·완료 기록의 이미지 ID 왕복, 이전 저장 호환, 건강 10 불변.
- `PeriodPlayUiTest`: 콘텐츠 갱신 뒤에도 저장된 결과 이미지 복원.
- `LifeRecordUiTest`: 완료 기록에서 저장된 사건 이미지 ID 우선.
