## 1. 본인 분류 70행

공용 `사건이미지_분류대장.csv`의 `classificationOwner=정원률` 70행을 별도 파일로 제출했다.
공용 대장과 같은 26열이며 사건 ID·제목·본문·시기·기존 경로 등 원본 11열을 유지했다.
장소·주요 행동·필수 사물·인물/연령·시간·시점·후보 그룹·기존 그림 판정·근거를 행별로 작성했다.

- 지정 파일 없는 사건 **67개**: `MISSING`, 각각 신규 후보.
- 지정 파일 있는 사건 **3개**: 원본 이미지를 직접 열어 아래처럼 판정.
- 후보 그룹 **70개**: `grp_wr_<eventId>`. 본인 행에서 무리하게 합칠 근거가 없어 분리 제안했다. 최종 N이 아니다.
- 상태 `CLASSIFIED_PENDING_REVIEW`. `approvedPerspective`는 이 CSV에서 **제안 시점**이며 공용 열 이름을 유지한 것이다.
- `approvedGroupId`, `semanticReviewer`, `visualReviewer`, `productionOwner`는 아직 공란이다. 제작 상태는 `NOT_ASSIGNED`다.
- 본문 미지정 사항은 연출 제안으로 구분했고 선택 전 결과를 확정하지 않도록 행별 금지 사항을 적었다.

| 본인 기존 파일 | 판정 | 이유 |
| --- | --- | --- |
| `path_hap_09` | 수정 필요 | 예술고의 늦은 실기실 본문과 달리 밝은 낮 작업실이다. 야간 조명·청소년 단서 필요. |
| `path_int_10` | 교체 필요 | 본문은 도서관 사서와 주제를 정하는 단계인데 그림은 대학 강단의 강의 중 장면이다. |
| `path_wea_09` | 재사용 후보 | 변호사 사무실·서류·고객 시점이 부합한다. 재산목록 표현과 실제 세로 크롭은 교차 검토 필요. |

따라서 본인 범위의 **신규 후보 67 + 수정 후보 1 + 교체 후보 1 + 그대로 재사용 후보 1**이다.
이를 확정 제작 69장이라고 보고하지 않는다. 전체 묶음 승인·기존 파일 판정·제작 배정이 남아 있다.

## 2. 기존 PNG 17건 전수 원본 검토

공용 대장에서 파일이 있다고 한 17건의 실제 PNG를 모두 열어 제목·본문·구도·시점·시간·선택 전 상태를 대조했다.
검토표에는 파일 경로·실제 해상도·SHA-256·관찰 내용·요청 수정·검수 범위를 남겼다.

- 원본 재사용 후보 **5건**.
- 수정 필요 **7건**.
- 교체 필요 **5건**.

수정/교체 12건은 그대로 쓸 수 없으므로 R에 포함하면 안 된다. 단순 파일 존재 검사는 의미 적합성 검사가 아니다.
이 중 `path_hap_09`, `path_int_10`은 이번 제출에서 수정·적용했고, 나머지 10건의 수정 요청은 담당 배정과 교차 검토가 필요하다.
모든 행의 `mobileCropStatus`는 `PENDING_DEVICE_REVIEW`다. 원본을 봤다는 이유로 실제 앱의 17개 사건을 모두 실행·승인했다고 하지 않았다.

신기훈 PR #49의 의미 검토와 대조했다. `path_fit_09`, `path_hea_10`, `teen_042`는 기존 재사용 제안에 문제가 있다는 방향이 일치한다.
수정/교체 용어를 통일하는 최종 합본은 아직 남아 있다.

## 3. 가이드와 건강 UI

공통 가이드에 본문 적합성, 1인칭, 연령, 글자/주인공 얼굴 제외, 4:3 실제 PNG, 기존 해상도 보존,
세로 가운데 크롭 계산, 개인 manifest, 샘플 3장 승인 순서를 정리했다.
4:3 원본이 360×740 영역을 채우면 가로 약 36.49%만 보이는 점을 명시하고 중앙 안전 구도를 제안했다.

건강 UI는 main이 아직 3색이므로 PR #47 커밋 `cc8fb104`를 **임시 분리 복사본**에서 검사했다.
API 36 에뮬레이터에서 기존 건강 경계 검사와 추가 시각 캡처 검사 **2개를 새로 실행해 통과**했다.
밝은 그림·어두운 그림의 실제 HealthGauge와 실제 DecisionScreen 4구간 캡처를 직접 확인했다.
이는 PR #47 코드의 검수이며 이번 브랜치에 타인의 프론트 코드를 병합하지 않았다.
