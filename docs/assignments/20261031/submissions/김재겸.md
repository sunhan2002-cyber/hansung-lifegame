## 1. 건강 게이지 4색

- 파일: `ui/components/PlayChrome.kt`(`HealthLevel` · `healthLevelOf`)
- 구간: 60~100 초록(좋음), 30~59 노랑(주의), 11~29 주황(위험), 0~10 빨강(위급). 경계는 60=초록, 30=노랑, 10=빨강이다.
- 음수와 100 초과는 0~100으로 묶어 같은 규칙을 쓴다. 0 이하는 채움 없음.
- 게이지 전체를 지금 값의 색 하나로 칠한다(구획 분할 · 그라데이션 없음).
- 숫자 숨김 · 두께 14dp · 상단 배치는 그대로 유지했다.
- 접근성 설명은 "건강 좋음/주의/위험/위급"으로 바꿨고, 진행 값은 그대로 둔다.
- 노랑은 밝은 종이색 트랙에서도 구분되도록 채도 높은 황금색(`#E2B000`)으로 정했다. 실제 화면 캡처로 회색·종이색 트랙 위 구분을 확인했다. 정원률의 최종 색 합의는 남아 있다.
- 화면 표시 전용이다. 건강 감소 · 회복 · 사망 판정과 저장 값은 바꾸지 않았다(엔진 · 저장 파일 미수정).

## 2. 타이핑 중 터치하면 본문 즉시 표시

- 파일: `ui/screens/DecisionScreen.kt`
- **재감소 방지:** 타이핑 루프를 `while (typedChars < 길이)`로 바꿨다. 매 바퀴 현재 값을 다시 읽으므로, 터치로 전문을 채우면 바로 끝나고 작은 값으로 덮어쓰지 않는다.
- **터치 소비:** 본문이 나오는 동안에는 화면 최상위(`completeTextOnTap`)가 Initial 단계에서 손을 뗀 이벤트를 먼저 소비하고 본문만 완성한다.
  - 같은 터치가 선택지 · 장면 보기 · 상세 창 · 진행으로 가지 않는다.
  - 누른 이벤트는 소비하지 않아 스크롤은 그대로 된다.
- **연타 방지:** 완성 직후 300ms 동안의 연타도 삼켜, 본문을 보려던 손가락이 선택을 확정하지 않게 했다.
- 돌발 팝업은 먼저 닫히고(팝업 터치로는 본문 완성 · 선택이 일어나지 않음) 그 뒤 본문이 나온다.
- 동작 줄이기 설정이면 처음부터 전문이 보인다(삼키는 단계 없음).
- 장면 보기에서 돌아오거나 화면 상태가 복원돼도 다시 타이핑하지 않는다. 다음 사건은 처음부터 다시 나온다.
- 이모지처럼 두 칸짜리 글자는 한 번에 넘겨 반쪽 글자가 보이지 않는다.
- 스크린리더는 본문의 "본문 전체 보기" 동작으로 같은 완성을 할 수 있다.

### 앱 연결 상태

- 현재 사건 그림 경로 17건은 모두 장면 보기 화면이 PNG의 가운데 크롭과 일치했다.
  - 일치율 1.000. 1080×2400과 360×740dp 두 크기 모두 같다.
  - 공용 그림으로 바뀐 사건은 0건이다.
- 수정본 2장은 기존 이미지 ID · 경로를 그대로 쓰므로, #50이 합쳐지면 앱 코드 변경 없이 새 그림이 나온다.
  - 임시 빌드의 APK 안 파일과 수정본의 SHA-256이 같았다.
  - 그 빌드의 화면이 수정본과 픽셀 단위로 같은 것도 위 검사로 확인했다.
- 승인 그룹(`이미지그룹_승인manifest.json`)은 아직 없다. 그래서 **새로 연결한 ID는 0건**이다.
  - 승인 그룹이 `image_routing.json`에 들어오고 사건의 `povImageId/imageId`가 그 ID를 가리키면 같은 검사가 그 사건을 자동으로 포함한다.
  - 경로가 깨졌거나 공용 그림으로 빠지면 실패한다.
  - 김선한의 `--acceptance`는 JSON · 해시 쪽을, 이 검사는 실제 화면 쪽을 맡는다.
- 제안(미구현): 가운데 크롭만으로는 34% 밖의 사물을 살릴 수 없다.
  - 재구도 대신 그림별로 가로 초점(예: `cropFocusX`)을 `image_routing.json`에 두는 방법이 있다.
  - 그러면 `adult_070`(오른쪽으로 이동) 같은 그림은 다시 그리지 않고도 핵심을 보일 수 있다.
  - 경로 형식이 바뀌는 일이라 김선한 · 정원률이 동의할 때만 넣는다.
