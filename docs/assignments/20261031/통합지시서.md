# 후속 수정 과제 — 건강바·타이핑 즉시 표시·사건 이미지 전수 대응

작성일: 2026-10-31. 기존 5명 역할을 유지한다. 이번 문서의 1~3번 요구는 과거 과제의 해당 부분보다 우선한다.
이번 과제는 과제 출제이며 앱 기능 구현 완료 보고가 아니다. ‘6시기×5해’ 등 과거 문서의 진행 단위 설명을 새 설계의 근거로 복사하지 않는다.

## 2. 수정사항 1 — 건강 게이지 4색

새로운 체력 스탯을 만들지 않고 기존 **건강** 게이지에 적용한다. 게이지 전체 채움 색은 현재 값에 따라 한 가지 색으로 바뀐다. 게이지를 4개 구획으로 고정 분할하거나 그라데이션으로 만들지 않는다.

사용자 범위 표기의 중복 경계를 아래와 같이 명시한다: **60은 초록, 30은 노랑, 10은 빨강**. 별도 사용자 변경 지시가 있으면 경계표와 검사도 함께 수정한다.

| 정수 건강 값 | 색상 | 권장 의미 문구 |
|---|---|---|
| 60~100 | 초록 | 좋음 |
| 30~59 | 노랑 | 주의 |
| 11~29 | 주황 | 위험 |
| 0~10 | 빨강 | 위급 |

- 김재겸: `PlayChrome.kt`의 `HealthLevel`, `healthLevelOf`, 게이지 색상·접근성 설명 변경. 밝은 배경과 어두운 배경에서 모두 판독 가능하게 한다. 노랑은 실제 실행 화면에서 흰 바탕과 구분되는 채도를 정원률과 맞춘다.
- 김우영: 색 표시 변경이 건강 감소·회복·사망 판정이나 저장 값을 바꾸지 않는지 검증한다. 화면 전용 단계값을 새 생존 규칙으로 사용하지 않는다.
- 김선한: 100, 61, 60, 59, 31, 30, 29, 11, 10, 9, 1, 0 경계와 음수·100 초과 표시 방어를 확인한다. 숫자 표기 제거·두꺼운 게이지·현재 배치 유지 여부도 확인한다.
- 완료: 네 구간의 실제 색·접근성 설명·경계 검사가 일치한다. 기존 80/60 기준 테스트 기대값도 새 요구에 맞춰 갱신한다.

## 3. 수정사항 2 — 타이핑 중 터치하면 본문 즉시 표시

| 상태 | 사용자 동작 | 반드시 나와야 할 결과 |
|---|---|---|
| 본문 일부 출력 중 | 사건 화면의 본문 또는 배경을 한 번 터치 | 현재 사건 본문 전체를 즉시 출력 |
| 본문 일부 출력 중 | 장면 보기·선택지 영역을 한 번 터치 | 해당 터치는 본문 완성만 수행. 장면 진입·선택 확정·진행은 하지 않음 |
| 본문 완성 후 | 장면 보기 버튼 누르기 | UI 숨김·블러 제거·배경 전체화면 표시 |
| 장면 감상 중 | 화면 한 번 터치 | 같은 사건과 선택지 UI로 복귀 |
| 본문 완성 후 | 선택지 누르기 | 결과는 한 번만 반영 |
| 다음 사건 진입 | 자동 출력 시작 | 앞 사건의 완성 상태가 다음 사건에 누출되지 않음 |

- 김재겸 구현: `DecisionScreen.kt`의 `introDone`, `typedChars`, 타이핑 코루틴과 입력 처리를 함께 다룬다. 문자 수만 최대값으로 바꾼 뒤 기존 루프가 작은 값으로 다시 덮어쓰는 오류를 막는다. 완성 터치를 소비해 동일 터치가 뒤의 선택지나 장면 버튼까지 실행되지 않게 한다.
- 김우영 지원: 표시 상태와 게임 진행 상태를 분리한다. 터치가 `onChoose`, `onContinue`, 다음 사건 이동, 보상 적용을 부르지 않아야 한다.
- 신기훈: 긴 한글 문장·줄바꿈·대사·이모지 등 실제 콘텐츠 사례를 제공한다. 내용 자체를 줄여 요구를 회피하지 않는다.
- 기존 돌발 팝업은 먼저 닫고 본문 출력 단계로 들어가는 흐름을 유지한다. 팝업 닫기 터치로 사건 선택까지 확정하지 않는다.
- 접근성/동작 줄이기에서 원래 즉시 표시되는 경우도 정상 작동한다. 장면 보기 복귀 후 본문이 다시 타이핑되지 않아야 한다.
- 검증: 타이핑 시계를 멈춘 Android 테스트에서 일부 표시→한 번 터치→전문 표시를 확인하고, 선택/진행 콜백 호출 0회를 확인한다. 빠른 연속 터치·다음 사건·복원·동작 줄이기·팝업→본문도 점검한다.

## 4. 수정사항 3 — 모든 사건을 의미에 맞는 이미지로 연결

### 4-1. 먼저 분류하고 수량을 확정한다

**이 단계가 끝나기 전에 ‘각자 몇 장’이라는 제작량을 확정하거나 이미지를 대량 제작하지 않는다.** 335는 현재 파일 누락 사건 수이고, 재사용 검토 전의 확정 신규 장수가 아니다.

1. 김선한이 `사건이미지_분류대장.csv`를 공유한다. 5명이 배정된 행의 제목·본문·시기·시점·기존 파일을 직접 확인한다. 파일 존재만 보고 적합 판정을 하지 않는다.
2. 각 사건에 장소, 주요 행동, 필수 사물, 등장 인물/연령, 시간대, 시점, `proposedGroupId`, 기존 이미지 적합/부적합, 신규/교체/재사용 근거를 기록한다. 본문에 없는 성공·사망·결혼 등 결과를 선택 전 그림으로 미리 확정하지 않는다.
3. 신기훈이 사건 의미와 재사용 묶음을 대조한다. ‘건강 사건’ 같은 스탯 태그만 같은 것은 재사용 근거가 아니다. 학교 급식의 브로콜리와 감기 아침의 물컵·체온계는 다른 장면이다.
4. 정원률이 구도·시점·화풍·소재 재사용 가능성을 확인한다. 같은 방이라도 핵심 행동/사물이 다르면 별도 그룹으로 나눈다. 공용 시기 배경은 사건 일치 이미지로 승인하지 않는다.
5. 두 검토를 통과한 `approvedGroupId`를 김선한이 확정하고 `제작수량_확정표.md`와 `이미지그룹_제작대장.csv`를 만든다. 이 두 파일은 현재 없는 **분류 단계의 제출물**이다.

수량은 아래 식으로 공개한다.

- `E`: 검토 대상 사건 수. 조사 기준 352이며 신규 사건이 합쳐지면 다시 센다.
- `N`: 의미 검토를 마친 고유 이미지 그룹 수.
- `R`: 그 그룹 중 실제 기존 PNG를 검수해 그대로 쓸 수 있는 그룹 수.
- **`M = N - R`: 신규 또는 교체 제작이 필요한 이미지 수.** 신규와 교체는 별도 열로 구분한다.
- 각 사건은 정확히 하나의 승인 기본 그룹에 대응한다. 기존 그룹 재사용에도 이유를 남긴다. 상황별 추가 그림이 필요하면 별도 그룹으로 등록해 N에 포함한다.
- 시나리오와 이미지가 충돌해 결정을 못 한 행은 `미해결`로 남긴다. 미해결이 0이 되기 전에는 제작 수량을 ‘최종 확정’으로 보고하지 않는다.

### 4-2. 지금 바로 할 수 있는 5명 분류 숙제

| 담당 | 분류 대상 사건 | 지정 파일 없는 사건 | 파일 있는 사건 재검수 |
|---|---:|---:|---:|
| 김선한 | 71 | 67 | 4 |
| 김우영 | 71 | 67 | 4 |
| 김재겸 | 70 | 67 | 3 |
| 신기훈 | 70 | 67 | 3 |
| 정원률 | 70 | 67 | 3 |
| 합계 | 352 | 335 | 17 |

개인별 대상은 CSV의 `classificationOwner`로 확인한다. 이 배정은 분류 업무이며 **각자 이미지 67장을 제작하라는 확정 지시가 아니다.** 다른 사람이 같은 사건을 중복 분류하지 않도록 행 ID를 고정한다.

### 4-3. M 확정 후 5명 모두 제작한다

- 한 그룹은 한 명만 제작한다. 같은 승인 그룹을 여러 사람이 각각 제작하지 않는다.
- `q = M // 5`, `r = M % 5`로 각자 q장 이상 배정하고 남는 r장은 김선한→김우영→김재겸→신기훈→정원률 순서로 한 장씩 배정한다. 복잡한 인물 장면 등은 예상 난이도도 기록하고 합의한 교환을 제작대장에 반영한다.
- 임의 예시: M=100으로 확정되면 각 20장이다. 이는 현재 확정 수량이 아니다.
- 정원률이 공통 가이드와 대표 샘플 3장을 먼저 제시하고 신기훈이 의미를, 김재겸이 실제 화면의 크롭을 검수한다. 그 뒤 같은 규격으로 5명이 자기 배정분을 제작한다. 샘플 3장도 승인 그룹에 속하면 총량에 한 번만 센다.
- 전원 제출물: 실제 PNG, 그룹 ID, 사용 사건 ID 목록, 생성/수정 방법·프롬프트, 파일 경로·크기·해시, 자체 검수 결과. 이미지 ID·프롬프트·시안만 제출하면 미완료다.
- 공통 그림: 기존 도트풍과 맞추고 필수 사물·행동·시점이 드러나게 한다. UI 글자·선택지·게이지를 그림에 구워 넣지 않는다. 사용자 제공 얼굴 사진을 사건 제작 소재나 저장소 파일로 사용하지 않는다.
- 기존 검증기의 4:3 규격과 실제 파일 경로를 먼저 맞춘다. 새 세로 규격이 필요하면 정원률·김재겸·김선한이 로더·검증기·기존 그림 호환을 함께 변경하는 별도 합의를 먼저 남긴다.
- 전체화면 가운데 크롭을 적용해도 주요 행동과 사물이 화면에서 보이도록 안전 영역을 확인한다. 원본 접촉시트만 보고 승인하지 않는다.

### 4-4. 코드 연결과 완료 기준

- 이미지 그룹 목록을 공통 원본으로 삼고, 중앙 JSON을 5명이 각자 덮어쓰지 않는다. 개인별 그룹 manifest/PNG를 PR로 제출하고 김선한이 합치며, 김재겸이 앱 연결을 확인한다.
- 김재겸은 `povImageId/imageId`, `image_ids.sample.json`, `image_routing.json`, 실제 경로를 연결한다. 다른 장면을 임의 대체해 성공처럼 표시하지 않는다.
- 김선한은 **전수 의미 대응률 100%**, 승인 그룹 실제 파일 존재·디코딩 성공 100%, 누락/의미 미확인 0을 검사한다. 352가 바뀌면 최신 사건 수를 분모로 쓴다.
- 기본 완료 판정에서 스탯 공용 장면·시기 배경으로 대체된 사건은 완료로 세지 않는다. 삭제/손상 시 안전한 대체 처리는 유지하지만 정상 데이터의 사건 커버리지를 대신하지 못한다.
- 전수 접촉시트에 사건 ID·제목·본문 요약·선택된 그룹·실제 이미지를 같이 보여주고 신기훈/정원률이 교차 검수한다. 특히 기존 파일 17건도 예외 없이 포함한다.
- 대표 사례를 실제 에뮬레이터에서 확인한다: 브로콜리 급식, 감기 아침, 시험, 해고 통보, 각 경로, 각 시기, 장면 보기, 결과 후 복원. 자동 누락 검사와 사람의 의미 검수를 구분해 기록한다.
- 체크를 끄거나 missing 파일을 허용하는 기존 검사만 통과했다고 전체 이미지 완료로 선언하지 않는다.

순서: 전원 분류 시작과 동시에 1·2번 구현/검증 → 분류 합본·N/R/M 확정 → 그룹별 제작량 배정 → 샘플 승인 → 전원 제작·개인 PR → 연결·의미 검수 → 최종 앱 검사.
1·2번은 이미지 분류 완료를 기다릴 필요가 없다. 대량 이미지 제작은 N/R/M과 공통 가이드 확정 뒤 시작한다.

## 6. 제출·통합

- 최신 main에서 개인 브랜치를 만든다. 과거 과제 전체를 다시 수행하거나 이미 완료된 기능을 재구현하지 않는다.
- `개인과제_이름.md`를 읽고 본인 분류 행을 먼저 제출한다. 결과는 `submissions/이름.md`에 단계별로 기록한다.
- 분류 완료, 수량 확정, 제작 완료, 앱 연결 완료, QA 완료를 서로 다른 상태로 보고한다.
- PR에는 변경 파일, 배정 그룹 ID, 실제 PNG 수, 실행한 검사와 실제 기기 화면, 남은 항목을 적는다. 미실행 검사·Fake·대표 사례만 확인한 것을 전수 완료로 보고하지 않는다.
- 다른 팀원의 필수 기능을 기다리는 부분은 의존 항목으로 남기고 독립 업무를 진행한다. main 직접 푸시·강제 푸시로 통합하지 않는다.
- 최종 인수는 **건강 4색 + 터치 즉시 전문 표시 + 모든 사건의 승인 이미지 대응** 세 항목을 각각 통과해야 한다.
