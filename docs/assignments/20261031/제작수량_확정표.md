`이미지그룹_제작대장.csv`는 352개 **후보**를 누락 없이 회수한 대장이다. 승인 그룹과 제작 담당 칸은 의도적으로 비워 두었다. 대장이 생겼다는 사실을 수량 확정 또는 제작 시작으로 해석하지 않는다.

## 확정 전에 해소할 항목

1. 신기훈이 새로 도착한 김선한·정원률 분류 141건을 의미 검토표에 반영한다. 이전 PR의 141건 `PENDING_CLASSIFICATION`은 이제 분류가 회수됐으므로 재검토할 수 있다.
2. 기존 의미 검토의 FIX 27건·REPLACE 3건과 기존 그림 시각 검토 결과를 대조한다. 미해결 목록 40건은 이 요청들과 김선한의 추가 판단을 사건 ID로 합친 값이며 단순 합산한 값이 아니다.
3. 정원률 원본 검토표는 재사용 후보 5·수정 7·교체 5다. 다른 담당자의 ‘적합’ 제안과 충돌하는 것을 재사용으로 자동 승인하지 않는다.
4. 정원률 PR #50의 수정본 `path_hap_09`, `path_int_10`은 원본 검토 이후 변경됐으므로 수정 파일 기준으로 의미·실제 크롭을 재확인한다. 원본 판정 기록을 덮어쓰지 않는다.
5. 김선한 기존 파일 4건 직접 확인: `adult_068`은 아침 몸살 구도 재사용 후보(크롭 대기), `path_hap_10`은 선택 전 서랍·스케치북·이어폰 구도로 수정, `path_luk_09`는 취출구 캔 세 개를 본문 두 개로 수정, `path_wea_10`은 이미 야간 근무 중인 구도를 주말 낮 제안 장면으로 교체한다.
6. 장면 묶음 재사용의 이유와 승인자를 실제로 남긴 뒤 N/R을 확정한다. 승인된 M을 기존 통합지시서의 q/r 방식으로 5명에게 배분한다. 한 그룹에 제작자는 한 명이다.

## 승인 데이터와 검사

최종 승인 그룹은 `이미지그룹_승인manifest.json` 배열로 제출한다. 각 항목에는 `groupId`, `imageId`, `assetPath`, `sha256`, `approvalStatus=APPROVED`, `semanticReviewer`, `visualReviewer`, `eventIds`, 사건별 `eventSourceHashes`를 넣는다. 수정 대상은 사건별 `resolvedIssueEvidence`도 제공한다.
사건 해시는 `scripts/validate_followup_image_coverage.py`의 `event_hash` 함수를 사용한다. 이름만 적고 실제 검토를 생략하지 않는다.

분류 구조 검사:

```text
python scripts/validate_followup_image_coverage.py
```

최종 이미지 인수 검사:

```text
python scripts/validate_followup_image_coverage.py --acceptance
```

현재는 전자는 통과하고 후자는 미승인 352건으로 실패하는 것이 정상이다. 여기의 미승인은 **승인 데이터 미제출**이며, 기존 이미지가 모두 잘못됐다는 뜻은 아니다. 필수 승인·그림이 없는 상태에서 검사를 끄거나 기준을 낮추지 않는다.
