# 승인된 최종 리팩토링 계획 원문

아래는 구현 승인 직전 대화의 계획 원문이다. 현재 구현 상태는 `20261119-progress.md`에서 별도로 관리한다. 이후 사용자가 실물 검증은 별도 진행하도록 지정했다.

최종 방향은 **기존의 전체 화면 그림 + 본문·선택지 오버레이 구조를 유지하면서, 게임의 안정성과 콘텐츠 완성도를 높이고 로비·장면·버튼에 깊이와 움직임을 더하는 것**입니다. 아래는 구현 순서와 완료 기준까지 포함한 계획이며, **아직 프로젝트 코드는 수정하지 않았습니다.**

기준은 앞서 가져와 검토한 main `e08d25f`입니다. 이 프로젝트는 Android Compose 앱이므로, 백엔드는 로컬 게임 엔진·저장·외부 AI 연동을, 디자인은 앱 화면·그래픽·접근성을 중심으로 다룹니다.

현재 단위 테스트와 핵심 기기 테스트는 통과했지만, lint 오류 1건, 의미 검수 25항목, 이미지 검수 대기 151항목이 남아 있습니다. 시뮬레이션에도 현재 게임과 다른 검증 규칙이 있어, 이를 먼저 바로잡아야 합니다. [기존 검증 기록](C:/HSU/3-2/mobile/main-audit-20261119/docs/demo/20261119_통합_시연검증.md)

우선순위는 **P0: 안정성·출시 필수 조건 / P1: 핵심 리팩토링과 체감 개선 / P2: 그래픽 완성도 확대**로 구분합니다. P2도 이번 최종 계획에 포함합니다.

1. **P0 — 게임 규칙과 테스트 기준 일치**

   앱과 시뮬레이터가 같은 프로필·초기 능력치·자동 사건·세션 생성 경로를 사용하도록 정리합니다. 기존 사망 규칙으로 실패한 207건은 현재 규칙으로 재판정하고, 지력 목표 경로와 미관측 결말은 실제 플레이 도달 가능성을 다시 확인합니다. 이 검증을 마친 뒤 필요한 밸런스 조정을 진행합니다.

   lint 오류를 해결하고 PR에서 단위 테스트·콘텐츠 검증·lint가 실행되도록 구성합니다.

   **완료 기준:** 같은 프로필·시드·선택으로 앱과 시뮬레이터의 결과가 일치하고, 실제 오류와 오래된 검증 규칙을 구분할 수 있어야 합니다.

2. **P0 — 외부 AI 연동과 배포 보안 정리**

   실제 API 키를 설정하면 APK에 포함될 수 있는 현재 빌드 구성을 개선합니다. 얼굴 생성 기능을 배포에 포함한다면 서버에서 키를 보관하고, 인증·요청 제한·시간 초과·취소·오류 응답을 처리하도록 구성합니다. 사진의 업로드 안내, 임시 파일 삭제, 백업 범위도 함께 정리합니다. 모바일 앱의 서비스 키는 서버에 보관하는 것이 공식 권장 방식입니다. [OpenAI 키 보안 안내](https://help.openai.com/en/articles/5112595-best-practices-for-api-key-safety)

   **완료 기준:** 배포 APK에 서비스 비밀키가 없고, 생성 실패·취소·재시도 후에도 프로필과 저장 상태가 정상이어야 합니다.

3. **P1 — 게임 엔진·저장·화면·연출의 책임 분리**

   큰 `ViewModel`, 게임 엔진, 사건 화면에서 진행 규칙, 콘텐츠 조회, 저장, 생성 요청, 화면 표시, 애니메이션을 구분합니다. 필수 JSON 파싱 실패를 빈 목록으로 숨기는 처리는 오류 원인을 구분할 수 있도록 개선합니다.

   기존 저장 버전 처리·손상 감지·기록 중복 방지는 보존하고, 저장 실패와 중단·복원을 강화합니다. **연출의 시작·종료가 선택 결과나 보상을 다시 적용하지 않도록** 경계를 명확하게 만듭니다.

   **완료 기준:** 기존 저장을 이어서 사용할 수 있고, 연타·화면 전환·앱 종료·복원에서도 선택·보상·결말이 한 번만 적용되어야 합니다.

4. **P1 — 콘텐츠·이미지 검수와 리소스 정리**

   의미 검수 25항목을 문구–선택 조건–결과가 맞는지 확인하며 마감합니다. 이미지 대기 151항목은 **수정 필요 131개와 지정 PNG가 없는 20개**로 나누어 처리합니다. 로비·첫 사건·주요 전환점·결말부터 우선합니다.

   승인된 원본은 보존하고, 세로 화면 크롭 기준과 효과용 파생 리소스를 별도로 관리합니다. 현재 약 222MiB의 assets는 참조 관계를 확인한 뒤 미사용 파일, 과도한 해상도, 중복 리소스를 정리합니다.

   **완료 기준:** 출시 대상 콘텐츠의 검수가 완료되고, 주요 인물·소품이 잘리지 않으며 이미지 누락 시에도 화면이 정상 표시되어야 합니다.

5. **P1 — 공통 UI·버튼·게임 진행 UX 정교화**

   글자 크기, 간격, 대비, 버튼 상태, 확인창, 로딩·실패·재시도 표현을 공통 규칙으로 정리합니다. 기존 선택지의 눌림 효과와 잠금 이유 표시는 보존하면서 로비·설정·결과 화면까지 일관되게 확장합니다.

   버튼은 **누름 → 접점의 빛 → 짧은 복귀 → 동작 확정**이 연결되게 하고, 능력치 변화와 선택 결과도 읽기 쉬운 순서로 표시합니다. 타이핑 완성 탭, 연출 건너뛰기, 선택 확정이 서로 충돌하지 않게 합니다. 햅틱·효과음·움직임 강도는 설정을 따릅니다.

   **완료 기준:** 작은 화면·큰 글씨·TalkBack에서도 주요 행동이 가능하고, 효과 때문에 입력이 중복되거나 진행이 지연되지 않아야 합니다.

6. **P1 — 게임을 시작하고 싶게 만드는 로비 완성**

   로비에도 전체 화면 그림을 적용하고, 캐릭터·빛·접촉 그림자로 장면의 중심을 만듭니다. 상태별 역할을 분명하게 나눕니다.

   | 상태 | 보여줄 내용 | 가장 강조할 행동 |
   |---|---|---|
   | 첫 방문 | 게임 분위기를 보여주는 장면과 짧은 초대 문구 | 새 인생 살기 |
   | 진행 중 | 실제 시기·외형·마지막 사건 | 이어하기 |
   | 완주 후 | 실제 대표 장면·얻은 칭호 | 다른 선택으로 새 인생 시작 |

   로비 진입 효과는 짧게 구성하고 시작 버튼은 바로 사용할 수 있게 합니다. 새 인생의 덮어쓰기 확인과 **프로필 → 주사위 → 첫 사건** 흐름은 유지합니다.

   **완료 기준:** 첫 방문자는 무엇을 하는 게임인지 이해하고, 재방문자는 자신의 진행 상황과 다음 행동을 즉시 찾을 수 있어야 합니다.

7. **P1 — 기존 그림에 2.5D 깊이·빛·환경 움직임 적용**

   대표 장면 3개부터 전경·중경·후경, 빛 마스크, 움직일 영역을 준비합니다. 레이어별 시차, 작은 카메라 이동, 햇빛·먼지·비·창밖 불빛을 장면에 맞게 적용합니다. 캐릭터는 호흡과 접촉 그림자부터 시작하고, 눈 깜빡임·표정 프레임으로 확장합니다.

   글자와 선택지의 위치·터치 영역은 안정적으로 유지합니다. 고급 셰이더는 호환성을 나누어 적용합니다. AGSL은 Android 13 이상이므로 하위 지원 기기에는 기본 효과를 제공합니다. [Android AGSL 문서](https://developer.android.com/develop/ui/views/graphics/agsl)

   **완료 기준:** 움직일 때 빈 가장자리나 레이어 분리 흔적이 없고, 효과를 꺼도 같은 정보를 읽고 같은 선택을 할 수 있어야 합니다.

8. **P2 — 실제 3D 주사위와 중요한 순간의 연출**

   실제 3D는 시작 주사위부터 적용합니다. 회전·착지·광원·접촉 그림자를 구현하고, 도트 그림과 어울리는 재질을 맞춥니다.

   **기존 게임 로직이 주사위 결과를 먼저 결정하고, 3D는 그 결과의 눈으로 착지하도록 합니다.** 재굴림 횟수·능력치 계산·도전 코드의 의미를 보존합니다. 이후 칭호 배지, 중요한 전환점, 완주 순간의 짧은 연출로 확대합니다.

   **완료 기준:** 모든 주사위 눈과 실제 계산이 일치하고, 중단·복원·건너뛰기에도 결과가 바뀌지 않아야 합니다. 3D를 사용할 수 없는 환경에서는 기존 표시로 진행할 수 있어야 합니다.

9. **P0·P1 — 성능·접근성·배포 최종 검증**

   성능 측정은 처음부터 병행하고, 마지막 단계에서 전체 흐름을 검증합니다. 시작 시간, 이미지 로딩, 프레임 지연, 메모리, 발열, 패키지 크기를 같은 기기·장면으로 비교합니다. 기존 이미지 캐시와 다운샘플링은 측정 결과에 따라 조정하고, 화면 밖의 애니메이션과 3D 자원은 정지·해제합니다.

   PR 기본 검증과 출시 인수 검증을 구분해 운영하고, 출시에는 콘텐츠·이미지·시뮬레이션·기기 테스트를 필수로 적용합니다. 서명, 버전, 런처 아이콘, 지원 OS와 의존성 호환성도 마무리합니다.

   **완료 기준:** 대표 실기기에서 성능 저하·메모리 누적·입력 오류가 없고, 효과 축소 상태와 기존 저장의 업데이트 후 복원까지 확인되어야 합니다. 성능 수치 목표는 기준 측정 후 확정합니다.

실제 개발은 **1 → 3 → 5 → 6 → 7 → 8**을 중심 순서로 진행하고, **2의 배포 연동과 4의 콘텐츠·이미지 검수는 병행**합니다. 9의 검증은 각 단계에 적용한 뒤 출시 전에 종합합니다.

첫 번째 완성 단위는 **새 로비 → 프로필·주사위 → 첫 선택 → 결과 → 저장·이어하기**입니다. 이 흐름에서 디자인과 동작을 먼저 완성하고 나머지 시기와 사건으로 확장하겠습니다.

시각적 구현 기준은 아래 세 전후 비교로 묶었습니다. 각 항목을 펼쳐 로비·버튼, 전체 화면 그림의 움직임, 실제 3D 주사위를 확인할 수 있습니다. 이는 계획용 예시이며 프로젝트 적용은 아직 하지 않았습니다.
