## 1. 시안에서 확인한 전체 방향

Figma 시안은 텍스트 기반 인생게임을 모바일 세로 화면에서 플레이하는 구조다. 핵심은 사건 이미지를 단순 사각형으로 두지 않고, 필름 프레임처럼 보여주면서 사용자가 한 장면을 넘겨 보는 느낌을 주는 것이다.

현재 앱의 기능 흐름은 유지한다.

```text
새 게임 → 캐릭터/이름 설정 → 사건 화면 → 선택 결과 → 다음 사건 → 돌발 사건 → 결말
```

7주차 UI 전환에서는 기능을 새로 만들기보다, 위 흐름을 Figma 시안의 화면 구조와 시각 언어로 바꾸는 것을 우선한다.

## 2. Figma 화면 구조 요약

### 2.1 사건 선택 화면

사건 선택 화면은 다음 순서로 구성한다.

1. 상단 진행 정보
   - 현재 나이: 예시 `7세`, `16세`
   - 성장 단계: 예시 `유년기`, `청소년기`
   - 능력치 미니 표시
   - 진행 상태 바 또는 작은 진행 인디케이터
   - 보조 문구: 예시 `지난 기록 3개 · 아래로 당겨서 보기`
2. 이미지 영역
   - 필름 테두리 형태
   - 내부에 실제 이미지 또는 이미지 준비 박스 표시
   - 하단에 `IMG_CHILD_SCHOOL_012` 같은 imageId 표시
3. 사건 정보
   - 사건 제목: 예시 `발표회 무대`, `자동문과의 대치`
   - 사건 본문
   - 돌발 사건일 경우 빨간 계열 라벨 표시
4. 선택 영역
   - 상단 라벨: `어떻게 할까`
   - 우측 보조 문구: `결과는 운에 따라 달라짐`
   - A/B/C 선택지를 카드형 버튼으로 표시
   - 각 선택지는 왼쪽에 선택지 문자 배지, 중앙에 문장, 우측에 영향 지표 힌트를 둔다.

### 2.2 선택 결과 화면

결과 화면은 선택 화면과 같은 상단/이미지 구조를 유지하되, 선택지 목록 대신 사용자가 고른 선택과 결과를 보여준다.

구성은 다음과 같다.

1. 상단 진행 정보
2. 필름 이미지 영역
3. 사건 제목
4. 선택 결과
   - 사용자가 고른 선택을 화살표 문장으로 보여줌
   - 예시: `→ 친구의 대사를 대신 말해 줬다`
5. 결과 문장
6. 변화한 지표 칩
   - 예시: `사회성 +6`, `지력 +2`
7. 하단 고정 버튼
   - 예시: `다음 해로 · 8세`

결과 화면은 선택 화면보다 정보가 적으므로, 하단 CTA 버튼이 명확하게 보여야 한다.

### 2.3 돌발 사건 화면

돌발 사건은 일반 사건과 시각적으로 구분한다.

확인된 예시:

- 제목: `자동문과의 대치`
- 라벨: `돌발 사건`
- 이미지 영역: 연한 붉은 배경
- 필름 테두리: 검정 대신 짙은 와인색 계열
- 보조 정보: `이번 생 2번째 · 도감 12 / 30`

돌발 사건 화면 기준:

1. 일반 사건과 같은 화면 구조를 유지한다.
2. 라벨, 이미지 배경, 필름 테두리 색상으로 돌발 사건임을 구분한다.
3. 사용자가 돌발 사건을 특별한 장면으로 인식해야 한다.
4. 지나치게 경고 화면처럼 보이지 않게 하고, 게임의 코믹한 분위기를 유지한다.

### 2.4 기록/히스토리 화면

시안에는 지난 기록을 아래로 당겨서 보는 흐름이 있다. 기록은 별도 화면으로 강하게 분리하기보다, 현재 플레이 화면 안에서 접거나 펼치는 형태가 적합하다.

기록에 들어갈 항목:

- 나이
- 사건 제목
- 선택한 선택지
- 결과 요약
- 변화한 주요 지표

7주차에는 완전한 기록 기능보다, 현재 `HistoryPanel`을 Figma 스타일에 맞게 정리하는 것을 우선한다.

## 3. 디자인 언어

### 3.1 기본 분위기

- 흰색 배경 중심
- 검정 텍스트와 검정 CTA 버튼
- 얇은 구분선과 충분한 여백
- 카드형 선택지
- 필름 프레임을 핵심 시각 요소로 사용

### 3.2 색상 방향

| 용도 | 색상 방향 | 설명 |
| --- | --- | --- |
| 기본 배경 | 흰색 또는 아주 연한 회색 | 텍스트 기반 게임이므로 가독성 우선 |
| 기본 텍스트 | 검정/진회색 | 사건 제목과 본문을 명확히 구분 |
| 보조 텍스트 | 회색 | 진행 정보, imageId, 보조 설명 |
| 기본 버튼 | 검정 배경 + 흰 글자 | 다음 진행 CTA |
| 선택지 카드 | 흰색 배경 + 연한 테두리 | 긴 선택지도 읽기 쉽게 |
| 일반 필름 | 검정 필름 테두리 | 기본 사건 이미지 |
| 돌발 필름 | 짙은 와인/붉은 계열 | 돌발 사건 강조 |
| 돌발 배경 | 연한 분홍/붉은 계열 | 위험하지만 코믹한 분위기 |
| 지표 변화 칩 | 연한 파랑 계열 | `사회성 +6` 같은 변화 표시 |

### 3.3 타이포그래피 방향

- 사건 제목은 본문보다 확실히 크게 둔다.
- 본문은 2~4줄 정도를 자연스럽게 읽을 수 있어야 한다.
- 선택지는 2줄 이상 줄바꿈을 허용한다.
- 선택지 글자가 버튼 밖으로 나가면 실패로 본다.
- imageId는 작고 흐리게 표시한다.

### 3.4 여백과 배치

- 모바일 세로 화면 기준으로 위에서 아래로 자연스럽게 읽히는 구조를 유지한다.
- 상단 정보와 이미지 사이 여백을 확보한다.
- 이미지와 사건 제목 사이 여백을 확보한다.
- 선택지 카드 사이 간격은 일정하게 유지한다.
- 하단 CTA 버튼은 손가락으로 누르기 쉬운 높이와 여백을 둔다.

## 4. 현재 Android 코드와 연결할 구현 대상

7주차에는 다음 파일을 중심으로 Figma 시안을 반영한다.

| Figma 요소 | Android 파일 | 작업 방향 |
| --- | --- | --- |
| 상단 나이/단계/능력치 헤더 | `LifeHeader.kt` | Figma의 나이·단계·능력치 미니 표시 구조로 정리 |
| 필름 이미지 영역 | `FilmStrip.kt`, `EventImageBox.kt` | 일반/돌발 필름 색상 분기, imageId 표시 정리 |
| 사건 카드 | `EventCard.kt`, `GameScreen.kt` | 제목, 본문, 라벨, 선택 영역의 정보 계층 정리 |
| 선택지 카드 | `ChoiceButton.kt` | A/B/C 배지, 긴 문장 줄바꿈, 지표 힌트 표시 |
| 결과 화면 | `GameScreen.kt` 또는 별도 결과 상태 | 선택 결과 문장, 지표 변화 칩, 다음 CTA 표시 |
| 기록 패널 | `HistoryPanel.kt` | `지난 기록 n개 · 아래로 당겨서 보기` 흐름 반영 |
| 색상/폰트/간격 | `Color.kt`, `Theme.kt`, `Type.kt` | 흰 배경, 검정 CTA, 와인색 돌발 사건, 지표 칩 색상 정리 |

## 5. 7주차 적용 우선순위

### 1순위: 실제 플레이 화면 전환

가장 먼저 `GameScreen.kt`를 Figma 구조로 바꾼다.

완료 기준:

- 사건 선택 화면이 Figma처럼 보인다.
- 결과 화면이 Figma처럼 보인다.
- 돌발 사건이 일반 사건과 색으로 구분된다.
- 선택지 3개가 작은 화면에서도 잘리지 않는다.

### 2순위: 컴포넌트 정리

Figma 스타일을 개별 컴포넌트로 분리한다.

대상:

- `LifeHeader`
- `FilmStrip`
- `ChoiceButton`
- `StatBar`
- `HistoryPanel`

완료 기준:

- `GameScreen.kt`가 너무 비대해지지 않는다.
- 컴포넌트별 역할이 분명하다.
- UI 테스트에서 컴포넌트가 안정적으로 표시된다.

### 3순위: 이름 입력/캐릭터 선택 화면 연결

김재겸 6주차 작업에서 이름 입력이 들어갔으므로, 캐릭터 선택 화면도 Figma 스타일과 맞춘다.

완료 기준:

- 이름 입력이 자연스럽게 보인다.
- 캐릭터 선택 카드가 앱의 새 디자인과 어울린다.
- `{name}`, `{nameCall}` 치환이 유지된다.

### 4순위: 결말 화면 정리

결말 화면은 7주차 후반 또는 8주차 초반에 정리해도 된다.

완료 기준:

- 최종 지표가 읽힌다.
- 선택 기록이 너무 길면 요약된다.
- 다시 시작 버튼이 명확하다.

## 6. 팀원별 7주차 작업 연결안

| 담당자 | 연결 작업 |
| --- | --- |
| 김재겸 | Figma 시안 기준으로 `GameScreen`, 이름 입력 화면, 결과 화면 구조 적용 |
| 정원률 | 색상, 여백, 선택지 버튼, 필름 프레임, 돌발 사건 시각 구분 정리 |
| 김우영 | UI가 필요한 `currentEvent`, 선택 결과, 다음 사건, 돌발 사건 상태를 안정적으로 제공 |
| 신기훈 | Figma 화면에 들어갔을 때 너무 긴 사건 문장을 다듬고 이미지가 필요한 사건 우선순위 지정 |
| 김선한 | imageId, QA 기준, Figma 적용 후 테스트 케이스와 데이터 검증 기준 정리 |

## 7. 검증 기준

7주차 UI 전환 후 다음을 확인한다.

### 일반 검증

- 앱 시작 후 캐릭터/이름 설정 화면이 열린다.
- 이름 입력 후 사건 화면에 진입한다.
- 일반 사건 화면이 Figma 구조로 보인다.
- 선택지를 누르면 결과 상태가 보인다.
- 다음 사건으로 이동할 수 있다.
- 결말까지 진행할 수 있다.

### 위험 검증

- 긴 사건 본문이 화면 밖으로 밀리지 않는다.
- 긴 선택지 3개가 버튼 밖으로 나가지 않는다.
- 작은 화면에서 하단 CTA가 잘리지 않는다.
- imageId만 있고 실제 이미지가 없어도 화면이 어색하게 깨지지 않는다.
- 돌발 사건 화면이 일반 사건과 구분된다.

### 애매 검증

- 선택지 우측 지표 힌트가 없을 때도 레이아웃이 무너지지 않는다.
- 결과 지표 변화가 여러 개일 때 칩이 줄바꿈된다.
- 지난 기록이 없을 때도 헤더 문구가 자연스럽다.
- 화면 전환 중 흰 화면 또는 검은 화면이 나오지 않는다.

## 8. 남은 확인 사항

Figma 공개 화면에서 직접 확인한 내용 기준으로 정리했다. Dev Mode 수치, 정확한 색상 hex, 간격 px, 폰트 스타일은 Figma 권한이나 Inspect 접근이 가능할 때 추가 확인해야 한다.

추후 보강할 항목:

- 정확한 색상 hex
- 정확한 radius, padding, spacing
- 선택지 카드 높이
- 필름 프레임 두께
- 헤더 능력치 미니 그래프 구성 방식
- 기록 패널 펼침/접힘 동작
