# 8주 범위 관리표

현재 수업은 4주차이며, 남은 약 8주 동안 기본 플레이 가능 앱을 완성하는 것을 목표로 한다. 최종 확장 목표는 더 크지만, 8주 안에는 통합 가능한 범위를 우선한다.

| 항목 | 4주차 목표 | 8주 안 목표 | 최종 확장 목표 |
| --- | --- | --- | --- |
| 사건 | 80개 이상 | 200개 이상 | 300~500개 이상 |
| 선택지 | 160개 이상 | 400개 이상 | 1,000개 이상 |
| 결말 | 20개 이상 | 30개 이상 | 30개 이상 |
| 돌발 이벤트 | 5개 이상 | 30개 이상 | 50개 이상 |
| 화면 | 5개 초안 | 시작부터 결말까지 연결 | UI polish 및 발표용 안정화 |
| 저장 | 구조 초안 | 이어하기 가능 | 오류 복구와 저장 버전 관리 |
| 테스트 | 역할별 기준 작성 | 핵심 기능 자동/수동 검증 | 반복 플레이 경로 검증 |

## 주차별 목표

| 주차 | 목표 | 완료 기준 |
| --- | --- | --- |
| 4주차 | 프로젝트 뼈대, 백엔드 로직, 데이터 샘플, QA 기준 작성 | 역할별 파일 Notion 제출, 팀장 검증 |
| 5주차 | Android 화면과 GameEngine 연결 | 선택 버튼 클릭 시 지표 변화 표시 |
| 6주차 | 사건·결말 데이터 확장 | 사건 120개 이상, 결말 25개 이상 |
| 7주차 | 저장·이어하기 구현 | 앱 재실행 후 진행 상태 복원 |
| 8주차 | 시작부터 결말까지 통합 | 최소 3개 결말 경로 확인 |
| 9주차 | 콘텐츠 확장과 오류 수정 | 사건 200개 이상, 돌발 이벤트 30개 이상 |
| 10주차 | 발표·시연 준비 | 3분 시연 경로 3개 준비 |
| 11주차 | 최종 정리 | 빌드, README, 발표자료, 시연 검증 완료 |

## 범위 조정 원칙

- 앱이 시작부터 결말까지 동작하는 것을 콘텐츠 수량보다 우선한다.
- 1,000개 선택지는 최종 확장 목표이며, 8주 안에는 데이터 구조와 작성 방식이 확장 가능함을 증명한다.
- C 선택지 AI 기능은 기본 게임이 완성된 뒤 선택 확장으로 다룬다.
