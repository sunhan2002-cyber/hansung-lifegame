# 변경 전후 비교 기준

이 문서는 팀원이 Notion에 제출한 결과물을 팀장이 검사할 때 사용하는 비교표다. 변경 전은 현재 기획/문서 상태, 변경 후는 제출물이 반영된 상태를 의미한다.

| 구분 | 변경 전 문제 | 변경 후 기준 | 확인 방법 |
| --- | --- | --- | --- |
| 결말 데이터 | 결말 조건과 우선순위가 문서에만 있음 | `endings.sample.json`에 20개 이상 작성 | JSON 파싱, 개수 확인 |
| 이미지 데이터 | 사건별 이미지 연결 기준이 없음 | `image_ids.sample.json`에 80개 이상 작성 | ID 중복 확인 |
| 데이터 구조 | 사건·선택지·결말 필드가 흩어져 있음 | `docs/data_schema.md`에 필수 항목 정리 | 문서 항목 확인 |
| Repository | assets JSON 로딩 위치가 없음 | `ContentRepository.kt`에 `loadEvents`, `loadEndings` 존재 | 파일·메서드 확인 |
| 저장 구조 | 이어하기 저장 기준이 없음 | `ProgressStore.kt`에 저장/불러오기/초기화 메서드 존재 | 파일·메서드 확인 |
| 테스트 기준 | 일반적인 말로만 검증함 | 일반 10개, 위험 10개, 애매 10개 테스트 작성 | `test_cases.md` 확인 |
| Push 절차 | 제출 전 push 가능성이 있음 | Notion 제출 → 팀장 검사 → 검증 통과 후 push | Notion 카드 상태 확인 |
| 통합 테스트 | 팀원별 파일이 따로 있음 | Android 프로젝트 병합 후 `./gradlew test` 실행 | 터미널 결과 확인 |

## 제출물 검사 순서

1. Notion 카드에 파일 또는 ZIP이 올라왔는지 확인한다.
2. 파일명이 숙제 기준과 일치하는지 확인한다.
3. JSON은 파싱 가능한지 확인한다.
4. ID 중복, 필수 필드 누락, 개수 기준을 확인한다.
5. Kotlin 파일은 요구 메서드가 있는지 확인한다.
6. Android 프로젝트가 준비되면 `./gradlew test`를 실행한다.
7. 통과한 뒤에만 GitHub push를 허용한다.
8. push 후 commit 링크가 Notion 카드에 남아야 완료 처리한다.
