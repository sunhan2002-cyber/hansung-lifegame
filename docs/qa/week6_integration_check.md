# 6주차 통합 검증표

## 1. 통합 목표

6주차 통합 목표는 5주차 통합본을 실제 PR 기반 개발 흐름으로 전환하고, 이름 치환, 사건 진행, 콘텐츠 데이터, UI 가독성, QA 기준을 동시에 검증하는 것이다.

## 2. 통합 전 상태

| 항목 | 현재 상태 |
| --- | --- |
| 사건 수 | 150개 |
| 결말 수 | 31개 |
| 이미지 ID 수 | 232개 |
| 캐릭터 수 | 3개 |
| 데이터 검증 스크립트 | `scripts/validate_content.py` 추가 |
| 6주차 QA 문서 | PR 체크리스트, 통합 검증표, 테스트 케이스 작성 |

## 3. PR 병합 권장 순서

| 순서 | 담당자 | 이유 |
| --- | --- | --- |
| 1 | 김우영 백엔드 | 사건 진행과 결말 판정이 안정되어야 다른 작업 검증 가능 |
| 2 | 신기훈 시나리오 | 사건 수와 imageId 매칭을 먼저 확인해야 함 |
| 3 | 김선한 DB·QA | 결말, 이미지 ID, 데이터 검증 기준을 최신화 |
| 4 | 정원률 UI/UX | 실제 화면 구성과 작은 화면 가독성 확인 |
| 5 | 김재겸 프론트엔드 | 이름 입력, 화면 흐름, 최종 앱 사용성 확인 |

## 4. 통합 검증 절차

| 단계 | 검증 내용 | 통과 기준 |
| --- | --- | --- |
| 1 | 최신 main pull | 로컬 main이 origin/main과 일치 |
| 2 | 콘텐츠 검증 | `python scripts/validate_content.py` PASS |
| 3 | 단위 테스트 | `./gradlew test` PASS |
| 4 | 빌드 | `./gradlew assembleDebug` PASS |
| 5 | 앱 실행 | Android Studio 또는 에뮬레이터에서 앱 실행 가능 |
| 6 | 이름 치환 | `{name}`, `{nameCall}`이 화면에 그대로 보이지 않음 |
| 7 | 사건 진행 | 최소 10개 사건 진행 중 흰 화면/검은 화면 없음 |
| 8 | 돌발 이벤트 | 너무 초반에 고정으로 등장하지 않음 |
| 9 | 단계 전환 | 성장 단계가 정상 이동 |
| 10 | 결말 도달 | 성인기 이후 조건에 맞는 결말 표시 |

## 5. 역할별 통합 확인

### 프론트엔드

- 이름 입력 화면이 보이는지 확인한다.
- 사건 본문과 결과 화면에서 이름 치환이 적용되는지 확인한다.
- 선택 결과에서 다음 사건으로 이동하는지 확인한다.
- 결말 화면에서 다시 시작이 가능한지 확인한다.

### 백엔드

- 사건 후보가 없을 때 앱이 죽지 않는지 확인한다.
- 돌발 이벤트 확률과 최대 횟수가 적용되는지 확인한다.
- 결말 우선순위가 테스트와 일치하는지 확인한다.

### UI/UX

- 작은 화면에서 버튼과 지표가 겹치지 않는지 확인한다.
- 긴 선택지가 줄바꿈되어 보이는지 확인한다.
- 돌발 이벤트 화면이 일반 사건과 구분되는지 확인한다.

### 시나리오

- 사건 수가 200개 이상인지 확인한다.
- 새 사건에 선택지가 2개 이상 있는지 확인한다.
- 새 사건의 imageId가 이미지 목록에 있는지 확인한다.

### DB·QA

- 결말이 30개 이상인지 확인한다.
- 기본 결말이 존재하는지 확인한다.
- 데이터 스키마 문서가 실제 JSON과 맞는지 확인한다.
- 테스트 케이스가 일반/위험/애매 사례를 모두 포함하는지 확인한다.

## 6. 통합 후 완료 기준

6주차 통합은 다음 조건을 모두 만족해야 완료 처리한다.

- 모든 팀원 PR이 Notion 카드에 등록되어 있다.
- 팀장 검증 통과 PR만 main에 merge되어 있다.
- `python scripts/validate_content.py` PASS
- `./gradlew test` PASS
- `./gradlew assembleDebug` PASS
- Android Studio에서 새 게임부터 최소 10개 사건까지 진행 가능
- 통합 후 main 기준 README 또는 Notion에 결과가 기록되어 있다.
