# 7주차~9주차 v4 개발 완료 QA 계획

목표는 3주 안에 v4 핵심 게임 루프를 실제 앱에서 플레이 가능한 수준으로 만드는 것이다. 10주차 이후는 이미지 확장, 밸런싱, 발표 안정화에 사용한다.

## 1. 7주차 통과 조건

7주차는 구조 전환 주차다. 완성 화면보다 v4 흐름을 코드와 데이터가 받아들일 수 있는 상태를 만든다.

### 필수 산출물

- `periods.sample.json`
- `focuses.sample.json`
- `events.sample.json`의 `kind`, `outcomes`
- v4 GameEngine/Session 뼈대
- 홈/장 표지/자동 진행/결정 화면 초안
- 이미지 스타일 가이드와 샘플 프롬프트

### 통과 기준

- [ ] 콘텐츠 검증 PASS
- [ ] 앱 테스트 PASS
- [ ] Debug 빌드 PASS
- [ ] 한 회차가 장 표지 → 자동 진행 → 결정/돌발까지 이동 가능
- [ ] 이미지가 없어도 placeholder로 실행 가능

## 2. 8주차 통과 조건

8주차는 연결 주차다. 백엔드, 프론트, 콘텐츠, 이미지 ID가 실제로 이어져야 한다.

### 필수 산출물

- `PeriodGameSession`과 프론트 ViewModel 연결
- 시기별 초점 선택 화면 실제 적용
- 대표 사건 5개 이상 v4 outcomes 기반 연결
- 도트 샘플 이미지 최소 20장 연결
- 주마등/기록 썸네일 흐름 초안

### 통과 기준

- [ ] 새 인생 시작 후 초점 선택 가능
- [ ] 자동 진행 중 능력치 변화 확인 가능
- [ ] 결정/돌발에서 선택 후 결과가 확률적으로 결정됨
- [ ] hidden outcome이 UI에 보이지 않음
- [ ] 최소 1개 시기를 끝까지 진행 가능

## 3. 9주차 통과 조건

9주차는 개발 완료 주차다. 이후에는 확장과 안정화만 남기는 것을 목표로 한다.

### 필수 산출물

- 시작부터 결말까지 한 회차 완주
- 저장/이어하기 복구
- 주마등 또는 미래 모습 화면 초안
- 결말 우선순위 적용
- 대표 도트 이미지 세트 연결
- 발표용 시연 흐름 고정

### 통과 기준

- [ ] 앱 실행 후 강제 종료 없이 결말까지 도달
- [ ] 저장 후 재실행해도 진행 상태 복원
- [ ] 1회차 시연 시간이 과도하게 길지 않음
- [ ] 테스트/빌드 PASS
- [ ] 팀장이 Android Studio에서 직접 시연 가능

## 4. merge 전 확인 명령

Windows 기준:

```powershell
python scripts/validate_content.py
.\gradlew.bat test
.\gradlew.bat assembleDebug
```

macOS/Linux 기준:

```bash
python3 scripts/validate_content.py
./gradlew test
./gradlew assembleDebug
```

## 5. 실패 시 처리 기준

- 콘텐츠 검증 실패: DB·QA가 원인 파일과 JSON 항목을 지정해 되돌려 보낸다.
- 테스트 실패: 담당자가 실패 테스트명을 PR에 적고 수정한다.
- 빌드 실패: merge 금지.
- UI 깨짐: 화면 캡처와 기기 크기를 함께 첨부한다.
- 이미지 규격 실패: 이미지 파일명, 크기, 스타일 기준을 다시 맞춘다.

## 6. 10주차 이후 안정화 항목

- 사건 수 확장
- 이미지 수 확장
- 결말 문장 다듬기
- 게임 밸런스 조정
- 발표 대본과 시연 경로 고정
- 심사 질문 대비 문서 정리
