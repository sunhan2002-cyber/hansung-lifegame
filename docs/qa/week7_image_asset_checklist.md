# 7주차 이미지 산출물 검증 체크리스트

v4 개편 이후 이미지는 게임의 핵심 연출 요소다. 이미지는 단순 삽화가 아니라 사용자의 현재 성장 상태, 선택 상황, 주마등 기록을 보여주는 데이터 자산으로 관리한다.

## 1. 공통 파일 규격

- [ ] PNG 파일인가
- [ ] 300×225 px인가
- [ ] 4:3 비율인가
- [ ] 파일명이 `imageId + .png`와 일치하는가
- [ ] `image_ids.sample.json`에 등록되어 있는가
- [ ] `fallbackText`가 있어 이미지 누락 시 앱이 대체 문구를 보여줄 수 있는가

## 2. 스타일 기준

- [ ] 도트풍/픽셀아트 느낌이 명확한가
- [ ] 피그마 예시처럼 레트로 게임 화면에 어울리는가
- [ ] 실제 사진처럼 보이지 않는가
- [ ] 과도한 3D, 실사, 웹툰풍, 수채화풍으로 벗어나지 않았는가
- [ ] 텍스트, 워터마크, 로고가 이미지 안에 들어가지 않았는가

## 3. 이미지 역할별 기준

| usage | 기준 |
| --- | --- |
| scene | 자동 진행 화면용 3인칭 장면. 캐릭터와 배경이 함께 보여야 함 |
| pov | 결정/돌발 화면용 1인칭 장면. 사용자가 그 상황에 들어간 느낌이어야 함 |
| moment | 주마등 썸네일. 작게 보여도 어떤 사건인지 구분 가능해야 함 |
| face_sheet | 얼굴 생성/변화 후보. 추후 서버 생성 기능과 연결 가능해야 함 |
| body_part | 성장 단계별 몸 형태 후보. 시기 변화 표현에 사용 가능해야 함 |

## 4. 내용 검증

- [ ] 사건 제목과 이미지 상황이 맞는가
- [ ] 시기와 이미지 속 인물 나이가 어긋나지 않는가
- [ ] 1인칭/3인칭 구분이 명확한가
- [ ] 위험하거나 잔인한 장면은 과하게 직접적으로 표현하지 않았는가
- [ ] 발표 시 화면에 띄워도 민망하거나 저작권 문제가 생기지 않는가

## 5. 자동 검증 기준

`scripts/validate_content.py`는 다음을 자동으로 확인한다.

- imageId 중복 없음
- fileName이 `imageId.png` 형식인지
- usage 값이 허용 목록인지
- width/height 값이 있으면 300/225인지
- 실제 PNG 파일이 존재하면 헤더 기준 크기가 300×225인지

## 6. 수동 검증 기준

자동 검증으로 잡기 어려운 항목은 팀장이 직접 본다.

- 도트풍이 맞는지
- 텍스트/워터마크가 없는지
- 피그마 예시와 화면 톤이 맞는지
- 사건 내용과 이미지가 어울리는지
- 팀원이 만든 이미지가 같은 스타일로 통일되는지
