## 2. 시기별 초점 20개

쓰는 규칙:

- 해마다 오르는 값 합 +3, 내려가는 값 -1 (한 시기 5년이면 +15 / -5). 팀장 초안과 같은 크기
- 같은 시기 안에서 내려가는 능력치가 겹치지 않게 했다 (중년기 취미·동네 모임만 둘 다 경제력: 장비값, 경조사비)
- 설명은 "결과 가능성이 달라진다"는 식으로 쓰고, 능력치로 무언가를 막는 표현은 쓰지 않았다
- 자동 진행 기록 문장에는 `{name}`을 넣지 않았다 (자동 진행 기록 치환 경로가 아직 정해지지 않음)
- 영아기 5개는 팀장 초안을 그대로 두었다

공통 규칙:

- 선택지 문구에는 능력치나 숫자를 쓰지 않는다. 능력치는 결과 가능성(`chanceWeights`)만 바꾼다
- 숨은 결과(`hidden: true`)는 대표 결과가 될 수 없고, 사망 결과는 반드시 숨은 결과로 둔다
- 사망 결과는 몸살 1개뿐이며 청년기·중년기에만 나온다 (영아·유년 사망 0건)
- 기존 앱 호환을 위해 선택지의 `statDelta`/`resultText`/`addFlags`는 대표 결과와 같게 두었다
- 사건마다 결정 화면용 1인칭 이미지(`imageId`, usage `pov`)와 주마등용 이미지(`momentImageId`, usage `moment`)를 붙였다

결과 표의 "능력치 낮음/보통/높음"은 관련 능력치가 20 / 50 / 80일 때 결과가 나오는 비율(%)이다. PR #20 GameEngine의 계산식(`chance + (능력치-50)×가중치÷10`)으로 구했다. **검토용 숫자이며 화면에는 내보내지 않는다.** 화면에는 "보통일 때 표현"과 같은 말만 쓴다.

## 4. 기존 사건 v4 정리

기존 사건 204개는 eventId와 문장을 하나도 바꾸지 않았다 (7주차부터 저장 데이터가 eventId를 쓰므로 번호를 바꾸지 않음). v4 엔진이 쓰는 `kind`, `periods`, `yearInPeriod`만 붙였다.

### 4.1 큰 돌발 (BIG_INCIDENT)

6주차 돌발 이벤트(`type: SPECIAL`) 19개를 모두 `BIG_INCIDENT`로 올렸다. 일반 돌발보다 드물게 나오고, 엔진에서 화면 일그러짐(DISTORT) 연출을 받는다. 이번 주 구조조정 사건까지 합해 큰 돌발은 20개다.

### 4.2 성인기 사건의 청년기/중년기 나누기

v4는 성인기를 청년기(YOUNG_ADULT)와 중년기(MIDDLE)로 나눈다. `periods`가 없으면 PR #20 파서는 성인기 사건을 두 시기 모두에 넣는다. 그러면 '쉰 번째 생일'이 청년기에 나오거나 신입 회식이 중년기에 나올 수 있다. 그래서 내용에 맞춰 직접 나눴다.

## 5. 입영 통지서와 성별 (팀장 확인 필요)

- 지금 캐릭터 데이터에는 성별이 없다. 3주 계획(`three_week_development_plan_v4.md`)에는 "성별/이름/캐릭터 설정"이 있다.
- 그래서 입영 통지서(adult_071)는 성별을 직접 보지 않고 **시작 플래그 `military_service_required`**가 있을 때만 나오게 했다. 이 플래그가 없는 플레이어에게는 나오지 않는다.
- 제안: 캐릭터 설정에서 병역 대상을 고르면 엔진/프론트가 시작 플래그로 `military_service_required`를 넣는다. 어떤 선택을 병역 대상으로 볼지는 팀장이 정해 주면 맞춘다.
- 어느 선택지를 골라도 `military_done`이 붙어서 다시 나오지 않는다. 현역·행정반·취사병(숨은 결과)·산업기능요원·사회복무요원으로 결과가 갈린다.
- 전쟁, 총기, 군 사고는 다루지 않았다.
