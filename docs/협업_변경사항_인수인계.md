## 1. 게임 진행 구조

기존에는 이벤트와 선택지를 단순히 반복하는 구조였지만, 현재는 생애 시기 기반의 인생 시뮬레이션 흐름으로 확장했다.

```text
홈
  ↓
플레이어 설정
  ↓
생애 시기 시작
  ↓
시기별 초점 선택
  ↓

  ↓
```

## 2. 스탯 시스템 개편

현재 스탯은 다음 7개다.

```text
건강
운동능력
지력
사회성
경제력
행복
운
```

기존에 있던 특수 스탯 `생명력(life)`은 제거하고 `건강(health)`으로 통합했다.

### 건강 스탯의 역할

건강은 다음 기능을 모두 담당한다.

- 상단 생존 게이지 표시
- 선택지 결과에 따른 건강 변화
- 생애 시기별 자연 감소
- 건강 0에 따른 사망 판정
- 건강이 낮을 때 발생하는 돌발 사망
- 건강 관련 사건의 확률 가중치
- 선택지의 건강 회복 및 감소 효과

기본 스탯 범위는 0부터 100이다.

영아기와 유년기에는 건강이 완전히 0으로 내려가지 않도록 최소값을 1로 유지한다. 청소년기 이후에는 건강 0을 허용하고, 건강이 0이 되면 인생이 종료된다.

### 시기별 건강 자연 감소

현재 기본 감소량은 다음과 같다.

```text
영아기: 0
유년기: 0
청소년기: 0
청년기: -1
중년기: -3
노년기: -5
```

### 기존 콘텐츠 호환

기존 JSON 콘텐츠에는 `lifeDelta`가 남아 있을 수 있다. 이 필드는 호환을 위해 모델에 남겨 두었지만, 실제 게임 적용 시 건강 변화로 합산한다.

```text
실제 건강 변화 = outcome.statDelta.health + outcome.lifeDelta
```

새 콘텐츠에서는 `lifeDelta`를 새로 사용하지 말고 `statDelta` 안에 `건강` 값을 기록해야 한다.

관련 파일:

```text
app/src/main/java/com/example/lifegame/domain/model/GameModels.kt
app/src/main/java/com/example/lifegame/domain/engine/GameEngine.kt
```

## 3. 사건 종류

사건은 다음 세 종류로 구분한다.

### MILESTONE

특정 연도나 시기에 반드시 또는 우선적으로 등장하는 주요 사건이다.

예시:

- 고등학교 원서
- 졸업식
- 시기 전환 사건

### INCIDENT

일반적인 인생 사건이다.

예시:

- 첫 중간고사
- 스터디 카페
- 친구 관계
- 가족 사건
- 아르바이트
- 건강 관련 상황

### BIG_INCIDENT

낮은 확률로 발생하는 큰 돌발사건이다. 과장되거나 우연성이 강한 상황을 만들고, 선택에 따라 생존·부상·사망 위기로 갈라질 수 있다.

예시:

- 피구공의 궤적
- 멈춘 엘리베이터
- 특수 사고 상황
- 과장된 위기 상황

관련 콘텐츠:

```text
app/src/main/assets/events.sample.json
```

## 4. 사건 조건과 분기

사건과 선택지는 현재 상태에 따라 열리거나 잠길 수 있다.

### 스탯 조건

사용 가능한 조건 스탯:

```text
건강
운동능력
지력
사회성
경제력
행복
운
```

예시:

```json
{
  "requiredStats": {
    "지력": 52
  }
}
```

위 선택지는 지력 52 이상일 때 활성화된다.

### 플래그 조건

사건 결과는 플래그를 추가할 수 있다.

```json
{
  "addFlags": [
    "passed_exam",
    "joined_club"
  ]
}
```

다른 사건에서 플래그를 요구할 수 있다.

```json
{
  "requiredFlags": [
    "passed_exam"
  ]
}
```

특정 플래그가 있을 때 사건을 막는 것도 가능하다.

```json
{
  "blockedFlags": [
    "injured"
  ]
}
```

### 사건 중복 방지

완료한 사건은 다음 형식의 플래그로 기록한다.

```text
v4:event:<eventId>
```

같은 사건은 완료 후 다시 선택 후보에 포함되지 않는다.

## 5. 스탯 기반 사건 선택

사건 선택은 완전한 무작위가 아니다.

먼저 다음 조건으로 후보를 걸러낸다.

```text
현재 생애 시기와 일치하는가?
사건의 스탯 조건을 만족하는가?
필수 플래그를 갖고 있는가?
차단 플래그가 없는가?
이미 완료한 사건이 아닌가?
```

그 다음 사건의 기본 가중치와 결과의 `chanceWeights`를 사용해 후보를 선택한다.

### 지력 예시

지력이 94라면 다음 효과가 발생한다.

- 지력 조건이 있는 사건이 활성화될 가능성이 높아진다.
- 지력 조건이 있는 선택지가 잠금 해제된다.
- 지력에 유리한 결과의 확률이 증가한다.
- 학업, 시험, 토론, 해커톤, 진로 관련 결과가 상대적으로 유리해진다.

청소년기 학업 관련 사건 예시:

```text
첫 중간고사
고등학교 원서
청소년 해커톤
교내 토론대회
문과냐 이과냐
스터디 카페
수능 D-100
수능 날 아침
기말고사 1교시
```

중요한 현재 동작:

```text
지력이 높다
→ 지력 조건 사건이 해금되고 결과 확률이 유리해진다.
```

다음처럼 학업 사건만 강제로 고정되는 것은 아니다.

```text
지력이 높다
→ 학업 사건만 무조건 등장한다.
```

현재는 같은 생애 시기의 다른 사건도 후보에 남아 있으며, 조건과 가중치에 따라 선택된다.

관련 구현:

```text
app/src/main/java/com/example/lifegame/domain/engine/GameEngine.kt
app/src/main/java/com/example/lifegame/data/V4ContentParser.kt
```

```text
동아리
```

## 7. 자동 진행과 인생 기록

각 시기의 연도는 자동으로 진행된다.

한 해가 진행될 때의 순서는 다음과 같다.

1. 선택한 초점의 스탯 효과를 적용한다.
2. 생애 시기별 건강 자연 감소를 적용한다.
3. 인생 기록 문장을 만든다.
4. 건강 상태에 따른 돌발 사망 여부를 판정한다.
5. 사건 발생 여부를 판정한다.
6. 사건이 없으면 다음 연도로 이동한다.
7. 현재 시기가 끝나면 다음 생애 시기로 이동한다.

인생 기록은 다음 정보를 가진다.

```text
생애 시기
시기 내 연도
기록 문장
선택적 이미지
```

관련 모델:

```text
LifeMoment
PeriodRunState
TurnStep
TurnPhase
```

## 8. 사망 처리와 실제 종료 시기

사망은 다음 상황에서 발생할 수 있다.

- 선택지 결과가 `death = true`인 경우
- 선택지 적용 후 건강이 0 이하가 된 경우
- 건강이 낮은 상태에서 연간 돌발 사망이 발생한 경우
- 노년기 전체 진행을 마치고 자연사하는 경우

### 과거 문제

기존에는 사망 순간의 시기를 별도 저장하지 않았다. 그래서 청년기에 사망해도 이후 화면 계산이나 저장 상태 때문에 다음과 같이 잘못 표시될 수 있었다.

```text
실제: 청년기 사망
표시: 노년기에서 인생을 마쳤다.
```

### 현재 수정

`PeriodRunState`에 다음 필드를 추가했다.

```kotlin
val endingPeriod: LifePeriod? = null
```

사망이 발생한 순간의 `state.period`를 `endingPeriod`에 저장한다. 종료 화면은 현재 진행 시기가 아니라 이 값을 사용한다.

기존 저장 데이터처럼 `endingPeriod`가 없는 경우에는 마지막 `LifeMoment`의 시기를 fallback으로 사용한다.

관련 파일:

```text

app/src/main/java/com/example/lifegame/domain/engine/GameEngine.kt
app/src/main/java/com/example/lifegame/data/V4ProgressStore.kt
app/src/main/java/com/example/lifegame/ui/PeriodPlayUi.kt
app/src/main/java/com/example/lifegame/ui/screens/RunEndScreen.kt
```

## 9. UI 개편

UI는 첨부된 인생게임 참고 이미지의 구성과 흐름에 맞춰 전면 수정했다.

### 상단 건강 패널

상단에는 다음 정보를 표시한다.

```text
건강
현재 건강 수치 / 100
건강 게이지
생애 시기 진행 상태
```

시기 진행은 점과 선 형태로 표시한다.

```text
●──○──○──○──○──○
```

현재 시기는 강조 색상으로 표시한다. 기존의 `생명력` 명칭은 제거하고 `건강`으로 통일했다.

관련 파일:

```text
app/src/main/java/com/example/lifegame/ui/components/PeriodChrome.kt
```

### 사건 본문

사건 화면은 다음 순서로 구성한다.

```text
사건 종류 또는 전환점 효과
사건 제목
사건 설명
장면 보기 버튼
선택지 목록
```

변경 사항:

- 사건 제목 중앙 정렬
- 사건 설명 중앙 정렬
- 제목 크기 확대
- 사건 종류 표시를 큰 시각 효과로 변경
- `돌발사건`, `인생의 전환점` 표시 개선
- 배경에 묻히던 글자 색상 개선
- 사건 설명 가독성 개선

### 배경 블러

선택지 화면에서는 배경만 블러 처리하고 사건 텍스트와 선택지는 선명하게 표시한다.

목표는 다음과 같다.

```text
배경: 분위기 전달
사건 설명: 읽기 쉬움
선택지: 선명하고 클릭 가능
```

### 장면 보기 흐름

`장면 보기`를 누르면 다음 상태로 전환한다.

```text
배경 블러 제거
상단 건강 패널 숨김
사건 제목과 설명 숨김
선택지 숨김
장면만 표시
```

장면만 표시된 상태에서 화면을 다시 터치하면 기존 UI가 복귀한다.

관련 파일:

```text
app/src/main/java/com/example/lifegame/ui/screens/DecisionScreen.kt
```

### 선택지 카드

선택지는 참고 이미지와 같은 카드형 UI로 변경했다.

```text
┌────────────────────────────┐
│ A  선택지 제목              │
│    조건 / 가능성            │
```

변경 사항:

- 선택지 전체 카드 영역 확대
- 선택지 텍스트가 잘리지 않도록 수정
- 조건과 효과를 분리해 표시
- 카드 배경과 텍스트 대비 강화
- A/B/C 표시를 카드 왼쪽 상단 모서리에 배치
- 카드와 A/B/C 표시의 겹침 제거
- 선택지 카드별 클릭 영역 확대
- 잠긴 선택지의 조건과 잠금 이유 표시
- 선택지 배경과 텍스트가 따로 노는 문제 수정

관련 파일:


## 10. 결과 화면

선택지를 누른 직후에는 선택 결과 화면이 표시된다.

표시 정보:

```text
선택한 선택지
결과 설명
변경된 스탯
사망 여부
계속하기 버튼
```

개선 사항:

- 결과 카드의 배경 대비 강화
- 사건 제목과 결과 텍스트 색상 개선
- 전환점 텍스트가 배경에 묻히지 않도록 수정
- 건강 변화 문구를 `건강 +N 회복`, `건강 N 감소`로 통일
- 생명력 관련 문구 제거
- 사망 결과일 때 실제 종료 시기로 연결

관련 모델:

```text
OutcomeUi
```

## 19. 이후 작업에서 반드시 유지해야 할 규칙

### 생명력과 건강

새로운 `life` 또는 `생명력` 스탯을 다시 추가하지 않는다.

```text
건강이 생존 게이지와 사망 판정을 모두 담당한다.
```

기존 `lifeDelta`는 호환용으로만 처리한다.

### 사건 등장

지력이 높다고 학업 사건만 강제로 표시하지 않는다. 현재 시기의 후보 사건을 조건으로 필터링한 뒤 가중 랜덤으로 선택한다.

### 사망 시기

사망 순간의 `state.period`를 반드시 `endingPeriod`에 저장한다. 종료 화면에서 현재 진행 시기를 임의로 사용하지 않는다.

### 선택지 UI

배경을 블러 처리하더라도 선택지 텍스트는 선명해야 한다. A/B/C 배지는 선택지 카드의 왼쪽 상단 모서리에 배치하고, 배지와 텍스트가 겹치지 않도록 한다.

### 장면 보기

장면 보기 진입 시 상단 UI, 사건 텍스트, 선택지를 숨기고 배경 블러를 제거한다. 장면 화면을 다시 터치하면 원래 UI를 복귀시킨다.

### 콘텐츠 작성

새 사건에서는 다음과 같은 형식을 사용한다.

```json
{
  "statDelta": {
    "건강": -5,
    "지력": 3
  }
}
```

새 콘텐츠에 별도 생명력 수치를 추가하지 않는다.
